## 3. 見立て——一日に 16 本、同じ型で書かれた精読報告

16 本はすべて `2026-10-24` の日付を持ち、同じ型で書かれている。型は次の七点である。

1. **第0部に検死を置く**（12/16 本が「第0部」を持つ）。資料を選ぶ前に、既存の断片を自前の語彙表で数える。
2. **群分けして資料カードを並べる**。42〜47 件を四〜六群に分け、各カードに一節・解釈・考え・感じたことを書く。
3. **横断報告を三層に分ける**（どう解釈したか／その解釈をどう考えたか／結果としてどう感じたと記述できるか）。この三層は `PROJECT_CHARTER.md` の要求と対応している。
4. **反論を並べて決めない**（14/16 本に「反論」の語がある）。決めないことを成果として書く。
5. **計数の範囲を明示する**。範囲は 2〜3 種類に分かれ、混ぜることを禁じている。
6. **「感じた」の地位を冒頭で限定する**。`CONTENT_POLICY.md` の反省的・文芸的応答モードであることを毎回書き、身体感覚の報告ではないと断る。
7. **縫い目・自己批判を置く**（「縫い目」2/16、「自己批判」3/16、「限界」「弱点」を含めるとさらに増える）。自分の手順違反を自分で書く。

この型そのものが U11 の主題である。16 本は「人間とは何か」を別々の軸（労働、予測、時間、数、訂正、待機、知覚、声、遊び、眠り、契り、誓い、訂正の宛先、死、獣、匂い）から読んでいるが、報告の骨格はほぼ同一で、軸だけが入れ替わる。したがって U11 の分類は「何を読んだか」より「同じ型のなかで、どこが計器になり、どこが宛先になり、どこが配管になったか」で分かれた。

とくに目立つのは、**この日の後半で軸が感覚と身体へ降りていく**ことである。労働（030）→ 予測（031）→ 時間（031・035）→ 数（033）→ 訂正（034）→ 知覚（036）→ 声（036）→ 遊び（038）→ 眠り（039）→ 契り（040）→ 誓い（041）→ 修復（041）→ 死（044）→ 獣（046）→ 匂い（046）と並べると、抽象語（予測・時間・数）から身体語（声・眠り・死・獣・匂い）へ移っている。同じ型を保ったまま、扱う対象だけが身体へ近づく。この移行は番号の順序と一致しない（§4-2）が、一日のなかで起きた移行としては読める。

## 5. 判定の規準（この 16 本に当てた規則）

U09・U10 と同じ規則を、U11 の性格に合わせて一段だけ具体化した。

1. **主象限は「資料の主題」ではなく「報告が自分に向けた計器の向き」で決める。** 16 本はすべて人間の資料を読むので、主題で切ると全部 `A_human` になる。そこで、報告の見出しと第0部がどこを測っているかを見た。人間の語彙を測って書庫の偏りを出す報告は `AB_crossed`、自分の書き方だけを測る報告は `B_ai_self_db`、宛先・声・返送先が軸の報告は `C_interface`、番号・来歴・シャードの配管が主題の報告は `D_infrastructure`、それ以外で人間の側の主題を正面から読む報告は `A_human` とした。
2. **`return_status` は報告が自分で書いた「次の作業」と「書かなかった理由」で決める。** 問い・断片・関係へ降りたと報告自身が書いていれば `returned_to_core`、断片 0 編を明示して空席を問いへ回していれば `productive_detour`、書誌の未照合が多いか ID の来歴が読めなければ `source_uncollated`、範囲や規約として残ったなら `infrastructure_rule`、比喩が接続されないまま次へ渡されたなら `metaphor_unconnected`。
3. **`read_depth` は読んだ行為で決め、判定の重みで調整しない。** 全文で読んだのは 1 本だけである。抜粋で読んだ 15 本についても、冒頭・断面・末尾の四点は読んでいるが、それは全文ではないので `excerpt_and_metadata_read` とした。U10 で 16 本を全文にできたのは、対象に 8,700 文字以下の短いノートが 16 本あったからで、U11 には一本もない。
4. **数値は報告の自己申告として引用し、台帳と突き合わせられたものだけ「一致」「不一致」と書く。** §4 の数値は、16 本の本文から機械的に抽出した ID と、`state/` の 2,434 素材・59 モチーフ・226 セッションとの照合による。報告が書く `questions=91` のような検証値は、台帳（問い 390）と一致しないが、これは報告時点のスナップショットである可能性があるので「不一致」ではなく「時点が違う」と書いた。
5. **一つの対象に一行。** 16 本は似ているが、統合しない。`session-036` の二本は 37 の ID を共有していても、読んでいる軸（知覚／声）が違うので別行にした。`session-041` の二本、`session-046` の二本も同じ理由で別行である。

## 7. このノートの限界

- **15 本は全文を読んでいない。** 一本あたり 4,600〜4,900 文字（9〜20%）を読んだだけである。読んだのは冒頭 1,700 字、三分の一と三分の二の断面、末尾 950 字で、中間の資料カード群はほとんど読めていない。したがって `human_view_stance` の記述は、報告の見出し・第0部・群の構成・結びから再構成した要約であり、個々の資料の読みの質を評価したものではない。
- **報告の数値を検算していない。** §4 のうち、ID の衝突・範囲・件数・字数は本文と台帳から機械的に取ったが、`手 103 回／23 編` のような語彙の実測値は、報告の計器を再実行しないと確かめられない。`tools/*_audit*.py` は凍結されているので、このターンでは再実行していない。
- **象限の判定は一次資料ではなく、報告の自己記述に依存している。** とくに `source_uncollated` の 3 本は、本文が名指しする ID が台帳で別の資料を指すという事実で決めた。報告の読みそのものが弱いという判定ではない。
- **`2026-10-24` の一日を、後の視点でまとめている。** 16 本は並行して書かれ、番号は何度も振り直された。本ノートは現在のファイル名で並べたが、当時の順序とは違う（§4-2・4-3）。
- **断片・問い・関係の追加はしていない。** U11 は分類ユニットであり、Reduce ターン（U12 以降）で台帳へ書き戻す前提である。このノートは材料の整理であり、台帳の更新ではない。

## 9. 引き継ぎ（Reduce ターンと U12 へ）

1. **ID の一意性が壊れている。** `SESSION-036`／`041`／`046` が各二本、`MAT-LIT` は 266 種中 35 種が複数本に現れ、そのうち 37 件（`MAT-LIT-388`〜`415` と `MAT-EVD-20261024-90`〜`98`）は本文の題名が総入れ替えになっている。Reduce では「ID は引用の鍵にならない」を前提に、題名と番号を必ず併記してほしい。
