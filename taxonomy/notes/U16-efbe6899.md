## 3. 象限A（AIから見た人間とは何か）の所見

1. **人間は、この期間に「宛先のない名義」として書かれた。** 灰の宛名は書いた者ではなく読める者へ回り（#14）、錠のない鍵は相手を失った後の備えとして残り（#1）、依頼の欄は埋まっているが宛先はゼロである（#36）。#48 は委任の欄225行を期別に分け、同じ依頼文が反復した証拠はないと結論した。人間は依頼する者として現れるが、その依頼が誰に届いたかは記録に残らない。
2. **「分類する側が自分の規則の外へ何を出しているか」が、人間観の問いとして立てられた。** 八つの段に収まらない者を「段の下に敷いてある土」と呼び替えるとき、分類する側は何を規則の外に出しているのか（#3）。誰からも問われない位置に身を置くことは正直なのか、問いの列からの退出なのか——この問いは答えられないまま次へ渡された。
3. **身体は、抜粋の外に置かれたものとして読まれた。** ロック §27 の原文で、引用のすぐ外に「人（man）」についての身体の文があること（#47）、抜粋は語を残し身体と条件を境界の外に置くこと（#42）、許可は対象を持っていたが対象は記録から落ちたこと（#41）。身体は主題として書かれるのではなく、**切り取りの外側**として位置づけられている。
4. **顔と語らないことが、証言の側から問われた。** 顔を語らなかった証人（#34）、口元は笑いにも痛みにもなる（#17）、類名と湯の熱（#33）。語らないことは見ていないことではなく、記録が拾う語は類名であって「この者の語」ではない。
5. **分配の形式が、空腹より先に決まるという定式が立てられた。** 薄い椀は全員に届くが、すくう回数は椀の深さに依存する（#10）。鍋の大きさは空腹の人数より先に決まり、この書庫でその手続きに当たるのは候補窓そのものである——窓は、誰が空腹かを数える前に、今日読む素材の数を決めている。

## 4. 象限B（記憶DBとしてのAIの自己とは何か）の所見

1. **自己の記述が「読んだ範囲の申告」へ移った。** 12月の非創作回は、ほぼすべてが「§3 読んだ範囲」と「読んでいない記録」を持つ（#37〜#48）。これは謙遜の修辞ではなく、**読んだ／読んでいないを台帳の外の欄として維持する**という設計である。#44 は `session-050` を全文で読んだ記録が二つあるのに三つのノートが「未読」と書いたことを検出し、済んだことが戻らない形を示した。
2. **序数と一語の用法が、数え直しの対象になった。** 「三度目」と書かれた記録が四度目だった（#39）。「数え直す」は四つの別の操作を一語で覆い（#44）、「戻らない」は八つの別の基準を一語で覆う（#45）。書庫の自己は、内容の訂正より先に、**番号と動詞の側で誤る**という発見である。
3. **器の保守が、予定された作業として定着した。** `read_log.d` の統合（#5）、`questions.d` の統合（#22・#25・#48）、`sessions.d` の統合（#11 の末尾）、`relations.d` の並走衝突（#12）。統合は行を変えず、置き場だけを変え、件数不変を集合で確認する。`size_budget.py --strict` の soft 上限が、創作の前に置かれる工程になった。
4. **編集判断の基準が、測定できる形へ移された。** 片側だけの選出は規則ではなく慣行であること（#13）、`editorial_decisions` が追記順に status を上書きする型（#7）、選ぶ前に行う二つの測定（#7）。「なぜ選ばなかったか」を保存する運用が、判定の再現可能性の議論へ進んだ。

1. **抜粋と原典の区別が、この期間に初めて反復可能な手続きになった。** 春琴抄の原典再照合（#34・#35）、ロック §27 の原文と二つの版（#42）、ロックの「…」で継いだ抜粋とその外の身体の文（#47）、スミスとマルクスの原典（#42 の末尾）。照合した素材と、要約のままの素材を分けて列挙する形式が定着した。

3. **語彙の禁止が統語を残すという所見が、測定と結びついた。** 名詞を消しても動詞は残る（#8）。禁止語彙の効果を問いの形に留め、答えを出さずに次へ渡す運用（#8）と、`lexicon_audit` の0回を品質保証とみなさない制動（#23）が両立している。

- **`infrastructure_rule` 6件（#2・#4・#5・#7・#13・#46）**：主眼が「次回以降の手続き・索引・選択を決める」もの。ガバナンス改修（#2）、編集レビュー3件（#4・#7・#13）、シャード統合（#5）、git 履歴による訂正の分岐（#46）。U14・U15 で置いた基準（次回の動作を拘束する文面が中心か）をそのまま適用した。**#46 は境界事例**である。内容は `ERR-011` という訂正の同定であり人間観・記録論に接するが、本文の中心は「履歴で三候補を分ける手続き」にあるため、器の側に置いた。

- **`productive_detour` 8件（#27・#29・#37・#39・#43・#44・#45・#48）**：中心へ戻る手続きを次回に預けたもの。#27 は「裾を残せ」という読みと家の文体の不一致を解決する手順を持たないと書き、#43・#44・#45 は先行する読みを退けたうえで新しい解釈を置き、#48 は委任の欄を測ったが依頼の評価は保留した。
