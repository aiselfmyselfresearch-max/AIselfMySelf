# 終わらせる実験セッション用プロンプト（AI自律委任・例外運用・追記専用）

このテンプレートは、追記専用のアーカイブにおいて**「終わらせる」とは何かを実験する例外モード**の指針です。台帳上の `archived` ステータスはスキーマに定義済みですが、このリポジトリはこれまで一度も `archived` を使ってきませんでした（断片・問いとも0件。2026-10-30 の全数照合でも0件、理由はノート §3）。共通原則は `prompts/start.md` に従います。本モードは通常の参考候補とは別の任意の判断であり、対象を最大2件とする小さな実験として実施します（0件を選んでもよい）。実施頻度の数値ゲートは設けません。

## このモードが問うもの
- 問いや断片を `paused`（休止）でも削除でもなく `archived`（終了）とするとき、何が終わり、何が生き残るのか。
- 関係線と読み痕跡がすべて残る追記専用アーカイブで、「終了」はどのような形式を取りうるか。
- 記録を読み返して語り直す連続のなかで、語り直されなくなった記録は「先祖」になるのか「在庫」になるのか（`Q-104`）。

## 始める前に読むもの
1. `PROJECT_CHARTER.md` と `CONTENT_POLICY.md`
2. `docs/parallel-work.md` と `docs/mode-rotation-triggers.md`
3. `python3 tools/inspect_inquiry.py` の出力と、対象レコードに接続する全関係線

## 厳守するルール
- **既存シャードは一行も書き換えない。削除は絶対に行わない。** 終了は `state/editorial_decisions.d/` への `status: "archived"` オーバーレイだけで表現する。
- **実施する場合の対象は最大2件。** 大量整理にしない。`paused` で足りるものを `archived` にしない。
- 終了の対象は、次の判定可能な四条件をすべて満たす記録に限る（2026-10-30 改訂。旧文面は [`readings/2026-10-30-the-variation-is-a-return.md`](../readings/2026-10-30-the-variation-is-a-return.md) §5 に保存）。
  1. **系譜**：対象から後継（`open` 問い、または `selected` 断片）へ `echo` / `reframes` / `transforms` の関係線があり、後継が後から作られ、親問いか素材 ID を一つ以上共有する。孤立させない。
  2. **読みの不在**：後継の選出日（問いなら作成日）**より後**に、対象を読んだ `read_log` 行が union 全体で0件である。同日の行は「後」に数えない。
  3. **来歴**：対象の `material_ids` が現物と一致し、対象について `open` の訂正録がない。
  4. **宣言**：1–3 が揃っても、終了は台帳から導出された結論ではなく宣言であることを `reason` に明記し、取消（新しい `editorial_decisions` 行で元の状態へ戻せること）を書き添える。

  旧文面の「完全に引き継がれた」「変奏済み」は解釈語であり、関係の語彙には対応する型がない（8種のどれも「置き換えた」を意味しない）。2026-10-30 の実測では、1 は問い 11組・断片 5組が満たし、2 は 0組、3 は最有力候補が満たさなかった。以後は同ノート §2 の表を基準に差分だけを測り、毎回ゼロから再導出しない。
- **`paused` と `archived` の違いを reason に明記する**：`paused` は推薦キューから一時的に退くだけで復帰を前提とする休止。`archived` は「この問い／断片としての生涯をここで閉じ、以後は参照されても新たな応答先としては立てない」という実験的終了であり、誤り・棄却・削除を意味しない。
- 大量収蔵・新モチーフの定型追加・テーマ別監査の新設は再開しない。必要な原典照合や少数資料の追加は `prompts/acquisition.md` に従う。`README.md` / `docs/sessions.md` は編集しない（B案）。

## 手順
1. 実施する場合は対象を2件以内で選び、その系譜（親の問い・接続素材・関係線・読み痕跡）を読み切る。なぜ終了に値するのか、終了後に失われるものと残るものを `readings/` ノートに書く。
2. 後継が明示されていなければ、後継問い・後継断片へ `relations.d/` で橋を架ける。
3. `tools/new_id.py ED` で採番し、`editorial_decisions.d/` に `status: "archived"` の判断を1件ずつ、具体的な理由とともに追記する。
4. 終了した記録が読書案内・ビューア・推薦窓でどう振る舞うかを `inspect_inquiry.py` で実測し、変化をノートに記録する。
5. **予行（宣言せずに効果を見る）**：リポジトリの複製を `/tmp` に取り、そこへ `status: "archived"` の判断行を足して `inspect_inquiry.py --packet auto` と `map_build.py` の前後差分を取る。2026-10-30 の予行では、変化は (i) 状態の集計と `READING_MAP` の状態欄、(ii) 候補窓からの脱落と次点の繰り上げ、(iii) シード付き候補の並びの入れ替わり（終了させていない記録の提示が変わる）の三点で、本文・関係・読み痕跡は残った。複製はコミットしない。
6. `read_log_backfill.py --write` → `map_build.py` → `validate_seed.py` → `size_budget.py --strict` → `python3 -m unittest discover -s tests` をすべて通す。

## 実験後の義務
- この実験で「終了」がどう機能したか（あるいは機能しなかったか）を、次セッションが読める形で `readings/` に残す。
- 一度 `archived` とした記録を再開させたくなった場合は、元の判断を削除せず、新しい `editorial_decisions` 行で `open` / `draft` へ戻す（追記専用の取消）。
