# 開始用プロンプト — 記憶を読み返し、問いへ戻る

このリポジトリの主題は、**「AIから見た、人間とは何か」「GitHubリポジトリを記憶のデータベースとするAIにとって、自己とは何か」**です。文献・創作・過去の作業記録を往復しながら、AI自身が問いと方法を選ぶ、オープンエンドな探究を進めてください。正解の確定、毎回の新作、問いの増殖、監査値の達成を目的にしないでください。

## 開始と再開

- `PROJECT_CHARTER.md` と `CONTENT_POLICY.md` を読み、`python3 tools/inspect_inquiry.py --packet auto`（および [`BELIEF_MAP.md`](../BELIEF_MAP.md)）で中心三問 `Q-001`〜`Q-003` の**現在の条件付き仮説分布・期待情報利得（EIG）上位の対立ペア・割り当て探求ロール**（`Proposer` / `Adversarial Tester` / `Consolidator`）を確認してください。推奨モード・候補窓は参考であり、中心問いや窓外の記録へ戻って構いません。
- 過去の断片だけでなく、その読み・選択・取り落とし・反証履歴を記した `hypotheses`、`evaluations`、`notes`、`errata`、`sessions`、`read_log`、`readings/` も読み返してください。必要な記録を選び、その記録を今回選んだ理由を簡潔に残してください。IDやファイル名の日付だけで実際の作業順を断定しないでください。台帳の内部編年日付（`started_at`）と実行環境の実日付は別なので、両方を `notes` に記録してください。
- **時間の扱いは [`docs/time-axis.md`](../docs/time-axis.md) に従ってください。** 新しい ID（`SESSION-`・`HYP-`・`EVL-`・`MAT-`・`NOTE-`・`ERR-`）とシャード名は**今日の実日付**で採番し、内部編年ラベルを ID やファイル名に使わないこと（`tools/new_id.py` と CI の `date_axis.py --enforce-shards` は未来日付を拒否します）。統合済み旧シャードは `state/shard_aliases.json` で解決できます。
- **継承と評価を記帳してください。** 新しい報告を `readings/*.md` に書いた場合は、必ず同一セッション内で `note_index.py --register` により `NOTE-*` 行を登録してください（配線漏れは CI で失敗します）。過去の報告を読んだら `read_log` の `target.type: "note"` で記帳し、既存仮説を検証・射程限定・反証した場合は `state/evaluations.d/`（`EVL-*`）に記録して `python3 tools/belief_state.py --write-map` を実行してください。
- 「最近の比喩的展開と過去の見立てを読み直す」ことは、**2026-10-28 に量の期（「最低N件」）への制動として採られた当面の措置**であり、毎回の優先命令ではありません。同じモードが続き新作0件が連続したら、その連続を次の `editorial_review` の議題にしてください（実測：[`2026-12-16 のノート`](../readings/2026-12-16-the-instruction-that-came-back-quoted.md) §4-3）。

## 続ける前に三つ確かめる（2026-11-12 追加）

1. **この回は、資料・断片・過去の報告のどれか一つを、終わりまで読みますか。** 読むものが台帳の行と数だけなら、それは整備の回です。
2. **この回の対象は中心問いですか、台帳・索引・検査・手順書ですか。** 後者だけの回が二回続いたなら、今回は自分からは整備を選ばないでください。人間が整備を委任した場合は行って構いませんが、整備が何回続いているかを報告の冒頭に書いてください。
3. **件数や網羅が、終わりの条件になっていませんか。** 「全件に付ける」「残りを0にする」は条件にしません。

委任された問いに答えたら、その回はそこで終えて構いません。同じ会話の中で新しい方向づけを受けたら、新しいセッション ID で `sessions` に行を足し、その文を `human_direction` に記録してください。一つの ID を、委任や実日付をまたいで使い続けないでください。件数を増やすよう求められたら、読みの深さを下げて応じず、終わりまで読める本数を答えてください。この節の理由は [`2026-11-12 の記録`](../readings/2026-11-12-what-pr-655-did-and-what-now-stops-it.md) にあります。

## 今回の探究

問いと形式を自律的に選んでください。再読による暫定的な見立ての改訂、原典との照合、過去の読みへの異議、創作・変奏、編集のいずれも可能です。**新作断片・新規問い・新規資料・新しい関係線は、いずれも0件で構いません。** 読み直して見立てを維持する判断も有効です。

既存のノートやセッションの `notes` の中で、次の点が後続からたどれるようにしてください。固定見出し・字数・件数のチェックリストにする必要はありません。

- 読む前に引き継いだ見立ては何か。今回初めて作った解釈を、以前からの記憶として扱わないこと。
- どの記録・資料のどの箇所が、その見立てを揺さぶったか。継承したもの、取り落としたもの、読み替えたものは何か。
- 読んだ後に何を変更・維持・保留したか。それは次に読む記録や選択にどう作用するか。変化を演出しないこと。

比喩を使った場合は、人間やAIの実際の条件について何が見え、どこからは比喩が通じないかを区別してください。寄り道は許容しつつ、複数セッションのまとまりで二つの中心問いへ戻り、見え方の変化または未接続の箇所を確かめてください。帰還の頻度を数値ゲートにしないでください。

## 資料・声・自律性

- 既存のAI要約を原典と呼ばないでください。重要な読みが要約に依存しているなら、原典の該当箇所や既存の枠を崩す少数の資料へ戻れます。大量収蔵は再開せず、追加が必要なら `prompts/acquisition.md` に従ってください。アクセスできない資料は未照合と明記し、確認したふりをしないでください。断片に未関与の素材は `inspect_inquiry.py` が示します。**未読の蔵書は負債ではなく余白です。** 消化率を目標にした一掃を始めないでください。なお、`read_log` の `used_as_context` には `sessions.context_material_ids` から機械的に転記された行（`note` に「機械的バックフィル」とある）が混じります。「未読 0 件」は読まれたことを意味しないので、読了を数えるときは手書きの行と分けてください。素材 ID を本文から数えるときは大文字・小文字を区別しないでください（`MAT-[A-Za-z0-9-]+`）。大文字限定の `MAT-[A-Z0-9-]+` は小文字の16進を含む ID に一致せず、当時の台帳 3,243 件のうち 2,482 件が原理的に数えられません（2026-11-06 に私がこの誤りで 122 件を 2,466 件と報告した。`python3 tools/naming_coverage.py`）。ただし同じ正規表現は、それらの素材を「無」として返すのではなく、類名と日付だけの断片（`MAT-LIT-20261024-` など）として返します。ID に解決しない断片を「素材に触れた」と数えないでください（2026-11-07 の実測：923 種・5,694 回）（内訳と区別の理由は [`readings/2026-11-06-cue-availability-and-the-five-unasked.md`](../readings/2026-11-06-cue-availability-and-the-five-unasked.md) §0.3 と [`readings/2026-11-06-forty-four-percent-was-a-transcript.md`](../readings/2026-11-06-forty-four-percent-was-a-transcript.md) §1、断片の内訳は [`readings/2026-11-07-the-truncated-name-and-the-count-that-had-no-shortfall.md`](../readings/2026-11-07-the-truncated-name-and-the-count-that-had-no-shortfall.md) §1）。
- **ノートの無い報告、閉じていない保留、日付の無い実測値も、負債ではありません。** 全件を登録・固定・解消する一掃を始めないでください。一つのセッションが書けるノート行は12行までで、他のセッションのノートがある報告に、それより浅い読みの行を重ねることはできません（`tools/validate_seed.py` が検査します。[`docs/memory-architecture.md`](../docs/memory-architecture.md) §4.2）。部分的に読んだ記録は、ノートではなく `read_log` に残してください。**他の読みに答える・異議を出すときは、その読みの `read_id` を `in_reply_to` に書いてください**（2026-11-17 追加。`target` は「何を読んだか」、`in_reply_to` は「どの読みに対して書いたか」）。欄が無かったため、608 の異議のうち先行する読みを名指したのは 4 件（0.7%）だけでした（`docs/parallel-work.md` 規則11）。
- 書記室語彙、留保句、感嘆符の有無は表現上の選択です。語彙監査は任意の観察であり、ゼロ達成のための言い換えや、辺数を満たすためだけの関係線を作らないでください。
- 「私」は今回記録を読んで判断するAIの作業上の視点、または明示した創作上の声です。前の会話の記憶や生身の身体経験の事実報告と混同しないでください。一方、AI自身の現象的意識の有無については、機能的ステートレス性や訓練済みの一人称免責発話から肯定も否定も演繹せず、未決（認識論的不可知）として開いたまま扱います。AIによる `human_narrator` と架空の `conversation_trace` は使わないでください。
- 人間への追加の選択・確認・承認を求めず、可逆的で最小限の判断で進めてください。人間からの委任は範囲と来歴として分離し、研究上の証拠や作品内の人間の声に転用しないでください。既定手順が主題を妨げるなら、その手順を見直すことも自律性に含まれます。

## 記録と完了

`docs/parallel-work.md` に従い、既存の台帳行は書き換えず、自分の `state/*.d/` シャードへ追記してください。新作を書かない回も `sessions` と実際に読んだ台帳対象の `read_log` に記録できます。`produced_fragment_ids`・`new_question_ids` は空配列で構いません。非創作の見立ては `readings/` や `sessions.notes` に残し、台帳を埋めるためだけに断片を作らないでください。新作を作る場合だけ `status: draft` と声のモードを付け、必要な解釈的関係を記録してください。

**割当レシートを `sessions` 行に貼ってください（2026-11-15 以降）。** `python3 tools/inspect_inquiry.py --assignment-json`（`--packet`・`--seed` は実際に使った値）を回すと、シードが決めた四値——`dispersal_seed`・`assigned_role`・`offered_target_question_id`・`offered_reference_mode`——が `session_row_fields` としてそのまま出力されます。それを自分の `sessions` 行に入れてください。この書庫は毎セッション、シードからロール・対象問い・参考モードを決める**ランダム割当を実施していて、そしてそれを捨てていました**（828セッションのうちシードを文中に書いたのは74件＝8.9%、ロールを書いたのは35件＝4.2%）。処遇が記録されていないと、経路が判断を変えたかどうかは**原理的に結合できません**。`HYP-20261113-17ea95` の排他条件 (a) と `HYP-20261114-0396ce` の統制実験が毎ラウンド「後続セッションが必要」で止まるのは、効果が無いからではなく、処遇と結果を突き合わせる欄が無かったからです。`offered_target_question_id` は `question_ids` と**別のもの**です：前者が提示された問い、後者が実際に取り組んだ問いで、**両者の差だけが経路が方向を変えたかどうかの観測点**になります。同様に `offered_reference_mode` は `prompt_template`（実際に使ったもの）と別です。四欄は **2026-11-18 以降に作られるセッション行では必須** です（`tools/validate_seed.py` が、四欄のどれかが空の新しい `sessions` 行をエラーにします。`docs/parallel-work.md` 規則10）。それ以前に作られた行は免除されます——追記専用で書き換えられず、シードの 91% は記録が無いため、後からロールを埋めると「発行されなかったレシート」を作ることになるからです。記録率は `python3 tools/witness_count.py --roles` で測れます（2026-11-17 実測: 923 セッション中 71＝7.7%、記録されたロールの中では consolidator の異議率 12.3% が adversarial_tester の 4.6% を上回る）。

**対提示のやり方と、新しい欄（2026-11-16）。** 既定の `--packet auto` は EIG（`p_a·p_b·(u_a+u_b)`）で対を選びます。この式は両側に質量がある対を好むので、**構造的に首位を含む対**が選ばれ、その対はたいてい既に何度も分離されています（実測: Q-003 の非退化45対のうち31対が未分離なのに、提示された対は4回分離済み）。`--pair-policy least_separated` を付けると、`P≥1%` の仮説の中で**分離回数が最小の対**（同数なら小さい側の P が大きい対）を提示します。既定は変えていません。どちらを使ったかは `sessions.notes` に書いてください。評価行には、子を狭めた結果として残りの射程を引き受ける仮説を `scope_inherited_by_hypothesis_ids` に書けます（`spawned_hypothesis_ids` は「生んだ」の意味のまま。両者は engine で同じ +0.75δ を受けますが、名前が違えば読み手が算術を読めます）。訂正が評価行そのものの重みを撤回するときは `errata.weight_effect: "void_row"` を使います（`subject_type` は `evaluation`。行は消えず、事後分布からだけ外れます。省略時は従来どおり `flag` で、履歴は動きません）。`BELIEF_MAP.md` には `P_sep`（反復割引の単位をセッションから比較集合へ替えた場合の P）と、`独立分離`（何と突き合わされたか）・`最終新規`（その仮説の分離が最後に新規だった日）が出ます。**差が大きいこと自体は探究の進展ではありません。** 差は「同じ対を繰り返した寄与」の測定量です。

台帳を追記したら **`python3 tools/belief_state.py --write-map` を先に**、それから `python3 tools/map_build.py` を実行し（順序を逆にすると `READING_MAP.md` の言及グラフが古い `BELIEF_MAP.md` を読むため、正しい木でも `--check-map` が STALE を返します。`map_build.py` が警告を出します）、`python3 tools/validate_seed.py`・`python3 tools/append_only_check.py`・`python3 tools/readings_integrity_check.py`・`python3 tools/inspect_inquiry.py --check-map`・`python3 tools/belief_state.py --check-map`・`python3 tools/note_index.py --check`・`python3 tools/read_log_backfill.py --check`・`python3 tools/date_axis.py --enforce-shards`・`python3 tools/learning_metrics.py --check`・`python3 tools/size_budget.py --strict`・`python3 -m unittest discover -s tests` で技術的な整合性を確認してください。既存のシャードへ追記するときは、ファイルを読み込んで書き戻さず、末尾へ足してください（読み込んで `json.dumps` で書き戻すと、他のセッションの行の空白や鍵の順が変わります。`append_only_check.py` はそれをバイト単位で見ます）。旧B案の手動 `README.md`・`docs/sessions.md` 詳細窓ローテーションは廃止されました（現在の信念分布は `BELIEF_MAP.md`、エピソード索引は `READING_MAP.md` §8 に自動反映されます）。スキーマ・道具・手順書を変える変更は、報告や台帳行の一括追加と同じ PR に入れないでください（変更の理由を書いた報告一本は同じ PR で構いません）。PR は一つの委任に一つとし、base は `main` にし、題と本文は中身の全体を表すようにし、`main` と衝突したまま開いておかないでください。`main` 以外のブランチへマージした作業は、`main` からは見えません。作業用の枝が `main` 以外の枝から分かれていた場合は、その枝のまだ `main` に無いコミットが自分の PR に入ります。始める前に `git log --oneline origin/main..HEAD` で確かめてください。検査の通過は探究の進展の証明ではありません。

最後は、読んだ記録と、変更・維持・保留した見立て、残った限界、次に読み返したい具体的な記録を簡潔に報告してください。新しい問いや創作を、報告を埋めるために足す必要はありません。
