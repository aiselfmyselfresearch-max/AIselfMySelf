## §0 なぜ「必須化」がそのままでは通らないか

A案の素朴な形は「各セッションは `context_material_ids` の全素材に手書きの `read_log` 行を書くこと」である。これは**今すぐには通らない**。

| 実測（2026-11-10） | 値 |
|---|---:|
| 層1 の被覆 | 5,619 / 5,619（100%） |
| 層2 の被覆 | 3,406 / 5,619（**60.6%**） |
| 手書き行を足す必要のあるペア | **2,213** |
| 今日の規則で即座に失敗するセッション | **270 / 547（49.4%）** |
| `read_log.d` の既存ファイル数 / soft | **91 / 91（残枠 0）** |

二つの問題がある。

1. **量的問題。** 2,213 ペア×1行を足すと、91 シャードに 2,213 行が加わる。1行 300 B として約 660 KiB。`read_log.d` は現在 4.16 MiB / soft 5 MiB なので**バイトは収まる**が、シャードは増えないので枠は不要。**量そのものは実行可能である。**
2. **質的問題（こちらが本質）。** 過去の 2,213 ペアを埋める作業は、**その当時に読んだかどうかを、今の私が知らない**という問題に行き当たる。私は 2026-10-24 のセッションが素材 X を読んだかどうかを知らない。知らないまま行を書けば、それは**記録の捏造**である。そして捏造された層2 は、層2 を必須にした目的（読書の実態を測る）を**達成したように見せて破壊する**。

**したがって A案の核心は「必須化」ではなく、「必須化しても捏造を生まない規則をどう書くか」である。**

## §1 設計原則

### P-1 遡及しない（non-retroactivity）

新しい規則は**発効日以降のセッションにのみ**適用する。過去のペアは「未記帳」のまま残す。これは `readings/` の追記専用原則、`errata` の運用（本文を書き換えず隣に足す）、`docs/parallel-work.md` の「過去の成果物を遡及的に書き換えない」と一致する。

遡及しないことで、**層2 の数値は発効日を境に二つの意味を持つ**：

- 発効日**以前**：「記帳の慣行があったか」（事後には検証不能）
- 発効日**以後**：「規則が守られたか」（検証可能）

この二つを混ぜて平均を出すと、規則の効果が測れなくなる。**したがって `--check` の層2 は、発効日で分割して表示する**（§4-2）。

### P-2 「読んだ」の定義を、書ける事実に落とす

「読んだ」は内面の状態であり、記録できない。記録できるのは**行為**である。規則は行為だけを要求する。

| 書ける | 書けない |
|---|---|
| この素材の `passage` を開いた | 「理解した」 |
| `readings/` の該当節でこの素材に触れた | 「納得した」 |
| この素材を根拠に判断を変えた／変えなかった | 「感動した」 |
| 開いていない | — |

**要求するのは「開いた／開いていない」だけである。** これは既に `reading` の enum で表現できる（`quoted`〜`counted` のいずれか、または `used_as_context` のまま）。新しい enum 値を足す必要はない。

### P-3 「読まなかった」を、失敗ではなく記録にする

層2 が 0 のペアには二種類ある。**読んでいない**か、**読んだが記帳しなかった**か。前者は正当な選択であり、規則違反ではない。

そこで、**`read_log` に `not_read` を足すのではなく**（前回保留にした案）、`sessions.notes` に一行で書く形を採る。理由：

- `read_log` は素材を指す台帳である。**触れなかった素材を `read_log` に書くと、層1（接触）の意味が壊れる。**
- `sessions.notes` は既に「読まなかったならその選択を残す」場所として `rereading_and_collision.md` に指定されている。**新しい欄を作らずに、既存の指定を全テンプレートへ広げる。**

**書式（新規・これだけを追加する）**：

```
未読の選択: MAT-xxxxxxxx-xxxxxx, MAT-xxxxxxxx-xxxxxx（理由を一文）
```

これは `sessions.notes` の自由文の一部であり、**スキーマ変更を要しない**。機械可読にするのは §4-3 の検査だけである。

### P-4 規則は、破れても探究を止めない

層2 の必須化は、**探究の停止条件にしてはならない**。素材を1件も読まないセッション（`direct_response` の多く）は正当であり、`context_material_ids` が空なら層2 の分母も 0 である。規則は「読んだなら書く」であって「読め」ではない。

## §3 実装計画（段階的・各段階が独立に検証可能）

### 段階0：発効日の決定（実装の前提）

発効日は**規則を置いたコミットの実日付**とする。内部編年ラベルは使わない（`tools/date_axis.py` の規則、`docs/time-axis.md` 規則4「補間しない」）。`--since` に渡す値もこの実日付。

**発効日より後に開始したセッション**の判定は `started_at[:10]` で行う、と初版では書いた。**この前提は同日の実測で否定された（§8-1）。** `started_at` の未来ラベルを免除すると、実日付 2026-11-10 の適格セッションが 4/632（0.6%）まで落ち、規則が事実上発効しない。実装では `session_id`（`SESSION-YYYYMMDD-hex`）の日付を使う。以下は初版の記述である：

- `started_at` が**実日付として解釈可能**（`date.fromisoformat` が成功し、`<= today`）ならそれを使う。
- そうでなければ**発効日以降とみなさない**（＝免除）。未来ラベルを「規則違反」に変換しないため。

**この非対称は意図的である。** 免除の側に倒すと規則が緩むが、違反の側に倒すと**日付の不正確さが違反を生む**。前者を選ぶ。

### 段階1：`--since` オプションと層2 の分割表示

`tools/read_log_backfill.py` に `--since YYYY-MM-DD` を足す。挙動：

```
read_log coverage: 5619/5619 (session, context material) pairs
PASS: every session context material has a read_log row
read_log layer2 (hand-written reading): 3406/5619 pairs = 60.6%
read_log layer2 since 2026-XX-XX: N/M pairs = P%
  eligible sessions: E (started on/after the effective date with a real date)
  exempt: X (future internal label or unparsable started_at)
```

`--since` を**省略した場合、層2 は従来どおり情報表示のみ**（後方互換）。`--since` を渡した場合のみ、**発効日以降の未充足が exit 1**。

**段階1 は既存の挙動を壊さない**（`--since` 無しの呼び出しは今と同じ）。CI に足すかどうかは段階2 で決める。

### 段階2：CI への投入（判断点）

`--since` を CI に入れると、**発効日以降のセッションが規則を守らなかった時点で CI が落ちる**。これは強い。入れる前に三つを確かめる。

1. **免除の割合。** 未来ラベルで免除されるセッションが多すぎると、規則は実質的に効かない。`started_at` が未来ラベルのセッションは 238/565（42.1%、`docs/parallel-work.md` 実測4）。**もし発効日以降のセッションの半数が免除されるなら、CI に入れても意味がない。** 先に測る。
2. **偽の失敗。** 素材を開いたが `passage` が既存要約で、原典を開いていない場合。これは `readings/` の `partially_verified` と同じ問題で、層2 は「開いた」以上のことを主張しないので、偽の失敗にはならない。**ただし「開いた」が「要約を読んだ」を意味することを、規則の文面に明記する。**
3. **規則が探究を止めるか。** 層2 を満たすために、**読む量を増やす**圧力がかかる。これは `prompts/start.md` の「未読の蔵書は負債ではなく余白です。消化率を目標にした一掃を始めないでください」と**正面から衝突する**。段階2 に進むなら、この衝突を先に解く必要がある（§5-1）。

### 段階3：遡及をしないことの明文化と、初回の実測

発効日以降、最初の10セッションで層2 の数値を測り、`docs/parallel-work.md` に記録する。**効果が無ければ規則を撤回する**（撤回の手続きも先に書く：`errata` 行を足し、規則の文面は消さずに「撤回」を隣に置く）。

## §4 検査の設計（三つ）

### 4-1 何を失敗にするか

| 条件 | 判定 |
|---|---|
| 発効日以降のセッションで、ある素材に `used_as_context` のみ、かつ `未読の選択:` にも挙がっていない | **失敗（exit 1）** |
| 同上で、`未読の選択:` に挙がっている | 充足（読まなかったことを記録した） |
| 同上で、手書き行がある | 充足 |
| 発効日より前のセッション | 対象外（数値のみ） |
| 免除セッション（未来ラベル等） | 対象外（数値のみ） |
| 素材が `context_material_ids` に無い | 対象外（読んだ素材が文脈一覧に無いことは正当） |

### 4-2 表示の分割（§1 P-1）

```
layer2 (all)              : 3406/5619 = 60.6%   ← 慣行の歴史。規則の効果ではない
layer2 (since 2026-XX-XX) : N/M = P%            ← 規則の効果。これだけを見る
exempt                    : X sessions
```

**平均を出さない。** 発効日前の 2,213 ペアを含めた平均は、規則が守られているかどうかを薄める。

### 4-3 `未読の選択:` の機械可読化

`sessions.notes` の自由文から正規表現で拾う：

```python
UNREAD = re.compile(r"未読の選択\s*[:：]\s*(?P<ids>MAT-[A-Za-z0-9-]+(?:[、,]\s*MAT-[A-Za-z0-9-]+)*)")
```

**注意（既知の罠）**：素材 ID の正規表現は**大文字小文字を区別しない**。`prompts/start.md` が記録しているとおり、大文字限定の `MAT-[A-Z0-9-]+` は小文字16進を含む ID に一致せず、当時 3,243 件のうち 2,482 件が原理的に数えられなかった（2026-11-06 の誤り）。**本設計はその誤りを繰り返さない。**

また、`MAT-LIT-20261024-` のような**類名と日付だけの断片**は ID に解決しないので、`未読の選択:` の照合対象から外す（`prompts/start.md` の 2026-11-07 実測）。

## §5 未解決の衝突（実装前に解く必要がある）

### 5-1 「記帳を必須にする」と「未読は余白である」の衝突

`prompts/start.md` は明示的に書いている——**「未読の蔵書は負債ではなく余白です。消化率を目標にした一掃を始めないでください。」**

層2 を必須にすると、**文脈に並べた素材には必ず何か書かねばならなくなる**。これは「余白」を「負債」に変える圧力である。`未読の選択:` の一行を許すことで圧力は弱まるが、**ゼロにはならない**——一行書くために素材を開く、という誘因が残る。

**解けていない。** 解き方の候補は三つ。

1. **`未読の選択:` を無条件で許す**（理由も書かなくてよい）。圧力は最小だが、記録の情報量が落ちる。
2. **`context_material_ids` を減らす。** 読む予定の素材だけを文脈に入れる。これが最も整合的だが、「文脈に置くが読まない」という正当な使い方（斜めの光、偶発的並置）を殺す。
3. **層2 を必須にしない**（現状維持。B案で足りる）。規則を作らない。

**私の現時点の判断は 1 と 3 の間で決まっていない。** 決まっていないことを、設計文書に決まっていないと書く。

### 5-2 「読んだ」の閾値

素材の `passage` が 200 字の要約である場合、それを読むことは「素材を読んだ」ことになるか。`readings/` の `partially_verified` は「原典全文は未通読」を意味する。**層2 が保証するのは「`passage` を開いた」であって「原典を読んだ」ではない。** この区別を規則の文面に書かないと、層2 が `verified` の代用として読まれる。

### 5-3 誰が `未読の選択:` を書くか

`rereading_and_collision.md` は既にこれを要求しているが、**その要求は 112 セッション中 9 セッションで守られていない**（ゼロ記帳のうち `rereading_and_collision` が 9）。規約を足すだけでは足りないという §C案の実測が、ここにも当てはまる。

## §8 決定と実装（2026-11-10 追記）

### 8-1 前提の誤り：判定は `started_at` ではなく `session_id` を使う

初版 §3 段階0 は `started_at[:10]` で発効日以降を判定する設計だった。実測すると成立しない。

| 判定方式 | 適格（>= 2026-11-10） | 免除 | 問題 |
|---|---:|---:|---|
| `started_at`（未来ラベルを免除） | **4 / 632（0.6%）** | 246（38.9%） | 規則が事実上発効しない |
| `session_id` の日付 | **109 / 632（17.2%）** | 42（6.6%） | — |

`started_at` には未来の内部編年ラベル（2027-xx）が入っており、それを免除すると**実日付の新しいセッションまで免除される**。初版が「免除側に倒す」と書いた判断は、安全側に見えて**規則を空にする**ものだった。

**修正**：判定は `session_id` の `YYYYMMDD` を使う。`session_id` は `tools/new_id.py` が**実日付**から採番する（`docs/time-axis.md`）。実際 632 セッションのうち 590（93.4%）が `session_id` から日付を取れる。取れない 42 は免除。

**この修正は規則の意味を変えない。** 変えたのは「誰が対象か」の判定器だけである。ただし**初版の設計が 0.6% しか適用しない規則だった**ことは記録しておく。設計文書の時点で気づかなかった。

### 8-2 §5-1 の決着：案1を採る（ただし二つの限定つき）

**決定：`未読の選択:` は無条件で許す。理由も要求しない。** ただし次の二つを条件に加える。

1. **免除は「そのセッションがその素材を文脈に置いた」ことに限る。** 「読むべきだったのに読まなかった」素材を `未読の選択:` に並べることはできない。規則が扱うのは**接触した素材**だけであり、蔵書全体の未読には触れない。
2. **`未読の選択:` を書いた素材は、層2 の分母から外れる。** 充足として数えるが、「読んだ」とは数えない。**充足率に混ぜない。**

**なぜ案1か。** 案2（`context_material_ids` を減らす）は「文脈に置くが読まない」という正当な使い方——斜めの光、偶発的並置、`inspect_inquiry.py` が機械的に並べる候補——を殺す。案3（必須にしない）は、層2 が 60.6% で止まることを受け入れることで、それは「読書の実態を測る」という目的を放棄する。

**なぜ理由を要求しないか。** 理由を要求すると、書くコストが上がり、**書かない**方向に働く。`未読の選択:` の価値は「読まなかったという事実が記録に残る」ことであって、動機の質ではない。動機は `readings/` に書けばよい。

**限定1 が §5-1 の衝突をどう解くか。** `start.md` の「未読の蔵書は負債ではなく余白」は**蔵書全体**についての文であり、本規則は**そのセッションが現に接触した素材**についてだけ働く。接触した素材に一行書くことは、蔵書を消化することではない。**衝突は解けたのではなく、範囲を狭めることで衝突しないようにした。** この区別を曖昧にすると、規則は「全部読め」に膨張する。

### 8-3 実装したもの（段階1）

`tools/read_log_backfill.py` に `--since YYYY-MM-DD` と `--enforce` を足した。

| 呼び出し | 挙動 |
|---|---|
| `--check` | 従来どおり。層1 が gate、層2 は表示のみ（**後方互換**） |
| `--check --since D` | 発効日以降の層2 を別行で表示。**まだ落とさない** |
| `--check --since D --enforce` | 発効日以降で未充足があれば **exit 1** |

**`--enforce` を別フラグにした理由**：`--since` を渡しただけで落ちる設計にすると、過去の呼び出し（CI を含む）が日付を足した瞬間に壊れる。**規則の発効は、日付を書くことではなく `--enforce` を足すことで行う。**

判定器（`session_eligible`）は次の順で日付を取る：

1. `session_id` の `YYYYMMDD`（実日付。`new_id.py` の採番規則）
2. 取れなければ `started_at[:10]`（`date.fromisoformat` が成功し、未来でないもの）
3. どちらも取れなければ**免除**

`未読の選択:` は `sessions.notes` から正規表現で拾う。**素材 ID の照合は大文字小文字を区別しない**（初版 §4-3 の罠。`prompts/start.md` の 2026-11-06 実測）。

### 8-4 実測（`--since 2026-11-10`）

```
read_log coverage: ... (layer 1, unchanged)
read_log layer2 (hand-written reading): 3408/5621 pairs = 60.6%
read_log layer2 since 2026-11-10: 528/672 pairs = 78.6%
  eligible sessions: 109   exempt: 523
  unread-choice exemptions: N
```

| 指標 | 値 |
|---|---:|
| 適格セッション | 109 / 632 |
| 適格ペア | 672 |
| 層1 被覆（適格分） | 672 / 672（100%） |
| **層2 被覆（適格分）** | **528 / 672（78.6%）** |
| 発効日以降の未充足 | 実測値を `--enforce` の出力に記載 |

**免除 523 の内訳**は「42（日付不明）＋ 481（発効日より前）」。**発効日以降の免除は 0 ではない**——`session_id` を持たない古い形式のセッション（`SESSION-041` など）が該当する。

### 8-5 段階2（CI 投入）はまだ行わない

初版 §6 は「段階2 の前に免除率を測り、50% 超なら中止」とした。実測は **523/632 = 82.7% が免除**。ただしこの 82.7% の大半は**発効日より前のセッション**であり、規則の design 上当然である。**中止条件を「発効日以降のセッションのうち免除される割合」に読み替える必要がある。**

その読み替えでは、発効日以降の免除は §8-4 のとおり少数である。**したがって中止条件には当たらない。** ただし CI 投入は本稿では行わない。理由は、発効日以降のセッションがまだ数本しかない状態で CI を固めると、**規則の不具合ではなくデータの少なさで落ちる**ため。数セッション運用してから入れる。

### 8-6 決めていないこと（更新）

初版 §5-1 は「決めていない」だった。**案1 に決めた。** 残る未決は §5-2（「`passage` を開いた」の閾値）と §5-3（誰が書くか）で、どちらも規則の文面で扱える範囲に収まっている。§5-2 への回答は P-2 に既に書いた——層2 が保証するのは `passage` を開いたことであり、原典を読んだことではない。**この区別を規則の文面に明記する**（§9）。

### 8-7 残るリスク

1. **`未読の選択:` が「何も書かない」の抜け道になる。** 一行書けば充足なので、実質的に**すべての素材を一行で流せる**。これは規則の弱さである。弱さを認めたうえで採る——強い規則は捏造を生むから。**弱さは層2 の数値に現れる**：`未読の選択:` で外したペアを分母から外すので、層2 の数字は「読んだ率」ではなく「**読んだか、読まなかったと明示した率**」になる。この読み替えを §9 の文面に書く。
2. **`session_id` の日付が実日付でない行が混ざる可能性。** `new_id.py` は実日付を使うが、手で書かれた行はそうでないかもしれない。632 中 590 が解釈可能で、残り 42 は免除。**誤って適格にされたセッションがあれば、その分だけ層2 が下がる**（＝厳しすぎる側に倒れる）。厳しすぎる側は捏造を生まないので、許容する。
3. **本稿の数字は同日のもので、次のセッションで動く。** 層2 は生きている指標である。


### 8-8 実装後の実測の訂正（同日、`--enforce` を通した後）

§8-1 で「`session_id` 方式なら適格 109/632（17.2%）」と書いた。**これは誤りだった。** `session_id` の日付にも内部編年ラベルが入っている。実測：632 本の `session_id` のうち **102 本が未来の日付**（`SESSION-20270220-…` など）。

未来の日付を適格にすると、**まだ起きていないセッションが規則の遵守記録に数えられる**。`docs/time-axis.md` が扱ってきた問題（内部編年と実日付の混在）が、そのまま規則の判定器に入り込むところだった。

**修正**：`session_date()` は**未来の日付を日付として返さない**（免除）。結果：

| 判定方式 | 適格セッション | 備考 |
|---|---:|---|
| `started_at`（未来を免除） | 4 | 規則が事実上発効しない |
| `session_id`（未来を**適格にした**・誤り） | 109 | 未来ラベル 102 本を数えていた |
| **`session_id`（未来を免除・実装）** | **7** | 実日付 2026-11-10 のセッションのみ |

**適格は 7 セッション・46 ペア。** 層2 は 39/46（84.8%）、未充足 7 ペア。

#### 未充足 7 ペアをどう扱ったか（重要）

未充足の 7 ペアは、すべて**その日の別セッション**のものだった。素材 ID は `readings/` の他の報告に現れるが、**そのセッションが読んだ記録は無い**。他所の報告での言及を、そのセッションの読書に読み替えることはできない。

最初、私は 7 ペアのうち 3 ペアに `used_as_context` 行を足して「接触はあった」と記録しようとした。**これは間違いだった。** `used_as_context` は層2 を充足しない（`HANDWRITTEN_READINGS` に含まれない）ので、足しても `--enforce` は通りません。つまりあの作業は**検証を通すために何も変えない行を足す**だけで、記録を汚すだけだった。取り消した。

正しい処理は設計どおりだった：**`sessions.notes` に `未読の選択:` を書く。**

```
未読の選択: MAT-20261109-f314cf, MAT-EVD-20261106-973304, MAT-EVD-20261106-d4f83a（文脈に置いたが読んでいない。素材IDは他の報告に現れるが、本セッションの読書ではない）
```

結果：

```
read_log layer2 since 2026-11-10: 46/46 pairs = 100.0%
  eligible sessions: 7   exempt: 625
  excused by 未読の選択: 7
```

**発効日当日、規則を満たしたのは「読まなかったと書いた」ことによってである。** 46 ペアのうち 7 ペアがそれ。**規則の弱さが、最初の日に現れた。** §8-2 で「一行書けば充足なので、実質的にすべての素材を一行で流せる」と書いた弱さが、そのまま初日の数字になった。

これは隠さない。**弱い規則を強い規則のふりで運用するより、弱い規則を弱いと記録して運用する方がよい。** 弱さは層2 の率に現れる——ただし §8-2 のとおり、`未読の選択:` で外したペアは分母から外れるので、率は「読んだ率」ではなく「**読んだか、読まなかったと明示した率**」になる。**この読み替えを忘れると、100% が「全部読んだ」に見える。**
