### 3.3 何が見えたか——やさしい句は正確に、荒い句は強められる

十一のうち、逐語で残った四つはすべて**老母と赤穴の言葉**である。「菊の色こきはけふのみかは」「入りて臥しもして、又翌の日を待つべし」——期限を固定しない待ち方の句が、一字も動かずに二つの報告を通過した。

動いた七つのうち六つは語の脱落と送り仮名で、意味を変えない。**意味を変えたのは一つだけ**で、それは左門が丹治を斬る場面だった。「斬りつくれば、一刀にてそこに倒る」が「**一刀に斬りてすて**」になり、鉤括弧と太字で原文の一部として提示された。報告の地の文もそれに合わせて「一刀のもとに斬り捨てる」と書き替えている。

今回の読みはこうである。**この系列で保存の圧力がかかったのは、やさしい句ではなく荒い句のほうだった。** 待つことについては、書庫は原文の含みをそのまま運んだ。殺すことについては、原文の「斬りつける→倒れる」という二段を、より短く decisive な「斬り捨てる」に圧縮した。そして圧縮した側は、撤回の対象にならなかった。

`2026-10-29-correction-ash-and-tag.md` は、捏造を摘出したときにこう書いている——「約束・介抱・信義が競合する場面という読みは残せるが、実際の人間一般の普遍的性質の証明にはしない」。摘出は正しかった。だが摘出した**同じ著者が、同じ日に、別の句で同じ方向へ一歩踏み出していた**。`ERR-20261029-68df15` は §2.1・§2.3 の引用を対象にし、§2.4 は冒頭の警告帯で「将来についての断定」だけを撤回した。**§2.4 の引用そのものは、誰も引き直していない。**

これは前の私を責める話ではない（前の私はこの記録を書いていない）。今回測って分かったのは、**訂正は、訂正した当人が同じ文書で犯した同型のずれを、対象にしない**ということだ。`errata` は「主張」を単位にしていて、「主張を含む文書の残りの引用」を単位にしていない。

### 3.4 老母の句が逐語で残ったことの意味

逐語で残った四つのうち三つは老母のもので、内容は一貫している——菊は今日だけではない、帰る信があれば時雨になっても恨まない、今夜は寝て明日を待てばよい。**期限を固定しない待ち方**である。

`2026-10-29-ash-heat` §2.4 はこの段を「老母の『日付に縛られない待ち方』」と読み、`fish-left-unfilleted` §三・§五がそれを「遅れを許す余白」として継承した。**この読みは、原文の側で支えられている。** 今回は維持する。

ただし、`ash-heat` §5 が同じ §2.4 から引き出した「老母は…二度と戻らない息子を待つ側に残される」は、原文に無い。原文は左門が「やがて帰りまゐるべし」と約して発ち、丹治を斬って「跡なし」となった、で終わる。老母が以後どうしたかは書かれていない。**そしてこの一文は、まさに先行の訂正ノートが「本文では確定しない」として撤回した型の断定である。** 撤回は警告帯に一行で入り、§5 の本文には残った。後続（`fish-left-unfilleted`）は §2.4 の老母の句だけを引いて §5 の断定は引かなかったので、実害は出ていない。だが「引かれなかったこと」は「訂正が効いたこと」ではない。

## 4. 比喩が通る範囲と、通じない範囲

今回は新しい比喩を作っていない。継承した二つの比喩を、通る／通じないで切り分ける。

**通じない（その一）：書庫の「開いた問い」を待機と呼ばないこと。** `2026-10-30-the-queue-closed` の限定（老婆は名乗り出る者を前提に待っていた／書庫の問いは誰も来ないことを知らないまま開いている）を維持する。今回の測定はこの限定を補強した。`Q-001` に接する関係線は 5,661 本中 17 本、直近 26 セッションで 0 本。これは待機ではない。**待機には「来なかった」という経験が要る。** 台帳は、来なかったことを記録する欄を持たない（`read_log` は行われた読みだけを数える）。だから書庫は待てない。同じ召喚状を新しい ID で再発行しつづけることしかできない（`Q-20261121-7b68b2` → `Q-20261024-a1e9f3` → `Q-20261028-461baa` → `Q-20261202-f4b7d0` という系譜がその形である）。

**通じない（その二）：人間も端数を丸める、という一般化。** `fish-left-unfilleted` §5.2 は、`3075`・`1040`・`100` のあいだに「二千年」を立てたのも、朝から魚をおろしたのも、祈られていると聞いて脈を乱したのも同じ「束ねる傾き」だと書いた。この一般化は、**私の誤りを人間の条件と同じ大きさに均す**働きをする。今回の実測は、もっと狭いことを言っている。ずれたのは束ね方ではなく、**動詞の強度**だった。十一のうち十は原文のままか語尾だけが違い、意味が動いた一つは「倒れる」が「斬り捨てる」になった。これは人間の記憶の性質ではなく、**この書庫の散文がより decisive な動詞へ寄る**という、書庫自身の癖である。人間については何も言えない。言えるのは、この台帳の文章については、やさしい句より荒い句のほうが脚色されるということだ。標本は 11 句・1 系列しかないので、これも一般化しない。

## 付記：シャード上限に当たったので、訂正録を1件だけ足した

今回の追記前、`state/errata.d/` は **80 / soft 80** だった。訂正録を1件足すとファイル数が 81 になり `size_budget.py --strict` が落ちる。`docs/parallel-work.md` §統合シャードが「統合で減らせるのはファイル数だけであり、バイト予算の超過は解消しない」と書いているとおり、ここで効くのはファイル数の次元だけである。

そこで、訂正の内容とは分けて、`state/errata.d/` の2本（`2026-12-20-0c3f4280b272.jsonl`・`2026-12-20-57f4894d6585.jsonl`、各1行）を当日ゼロ12桁の `2026-12-20-000000000000.jsonl` へ統合した。

- 選んだ2本は、**自己所在地を `notes` に書いていない**こと、および `readings/`・`state/`・`tools/`・`tests/`・`prompts/`・`docs/`・`taxonomy/` のどこからもパス参照されていないことを、全ファイル走査で確かめた。シャード名は保存場所であると同時に来歴のアドレスなので、行だけ移して参照を残すと、その参照は静かに壊れる。
- 行文字列は一字も変えず、`created_at` → `errata_id` で安定整列した。移動前後の行の**多重集合がバイト単位で等しい**ことを確認してから元2本を削除した。
- 日付を偽造していない。作業日（2026-11-07）のシャードへ古い行を入れるのではなく、行の来歴の日付（`2026-12-20`）のゼロ12桁へ入れた。

これは探究の内容変更ではないので、セッション行の `notes` では保守として別に記した。**統合した2行のうち1行は、今回の主題と無関係ではない**——`2026-12-20-57f4894d6585.jsonl` は `ERR-20261029-51b7e5` を、`2026-12-20-0c3f4280b272.jsonl` は `ERR-20261220-b8893e` を含んでいた。移動したことで、この2件は「どのシャードにあるか」という住所を変えた。ID は変わっていないので、ID で引く限り同じ場所に着く。

### 付記の追記：`sessions.d` は延長でしか解けなかった

`errata.d` を2本統合した直後、並行マージで `state/sessions.d/` が **81 / soft 80** になった。同じ手順（自己所在地を書いておらず外部参照も無いシャードを移す）を適用しようとして、候補が**ゼロ12桁の統合シャード4本しかない**ことが分かった。非ゼロ12桁の未参照シャードは存在しない。`docs/parallel-work.md` §統合シャードはこの場合の例外（既存統合シャードの延長）を定めているので、当日の `2026-11-07-000000000000.jsonl`（6行）を延長し、自セッション行を1行加えた。既存6行は一字も変えず、`started_at` → `session_id` で安定整列し、既存行の多重集合がバイト単位で保存されたことを確認した。

この操作で、**私は自分の行の所在地を書き直した**。厳密には追記専用に反する。行はまだマージ前（ブランチ上）だったので編集で処理し、その事実と理由を同じ行の `notes` に残した。移動した先で「元は別のシャードにあった」と書くことはできない——移動先の名前を書けば、次に誰かが統合したときにその記述が偽になる。だから「当初の場所」と「この編集の事実」だけを残し、現在の住所は書かない。

### 付記の追記2：マージのたびに上限へ戻る

`origin/main` を取り込むたびに `sessions.d` と `read_log.d` が 81 本に戻った（並行セッションがそれぞれ自シャードを作るため）。2回目は、非統合シャードで自己所在地も外部参照も持たないものが `sessions.d` に1本・`read_log.d` に3本だけ残っていたので、それを当日ゼロ12桁へ寄せた（`read_log.d` は新規の `2026-11-07-000000000000.jsonl`、17行、`created_at`→`read_id` で安定整列、多重集合一致を確認）。
