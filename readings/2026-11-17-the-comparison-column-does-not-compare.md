## §1 engine が比較相手から読む三つの量

`tools/belief_state.py` の `compute_belief_state` から、`compared_against_hypothesis_ids` が現れる箇所を全部挙げる（**引用**、行番号は測定時点）。

**(1) 反復割引の鍵**（:630-633）

```python
compared_key = ",".join(
    sorted(c for c in (evl.get("compared_against_hypothesis_ids") or []) if isinstance(c, str))
)
if pair_level_repeat:
    repeat_key = (target_id, verdict, compared_key or sid or source_key)
else:
    repeat_key = (target_id, verdict, sid or source_key)
```

既定の `pair_level_repeat=False` では `compared_key` は**使われない**。`--write-map` の第二基底（`P_sep`）だけがこれを使う。つまり既定の算術では、比較相手は反復割引に一切関与しない。

**(2) 割引の有無**（:641-643）

```python
comp_factor = 1.0 if compared else 0.65
delta = base_w * indep_discount * comp_factor
```

**比較相手の集合が空か、空でないか。** それだけである。中身は読まない。

**(3) 固定の減点**（:683-689）

```python
if verdict == "supports":
    log_odds[target_id] += delta
    if compared:
        share = (0.20 * delta) / len(compared)
        for cid in compared:
            log_odds[cid] -= share
```

名指された相手それぞれに `0.20 × delta ÷ 相手の数` を引く。**誰を名指しても、引かれる量は同じである。** 相手が3件なら3等分、1件なら全額。

この三箇所のどれも、相手の**同一性**を読まない。読むのは「空かどうか」と「何件か」だけである。

`narrows_scope`（:691-697）と `refutes_unconditioned`（:699-705）は `compared` を減点に使わない。相手は割引を外すためだけに効く。

**解釈。** これは実装の偶然ではない。設計として、この欄は**「この判定を、どこから引くか」を書く欄**であって、「この判定が、どの命題との対立の結果か」を書く欄ではない。名前が `compared_against` であるために、書く者も読む者も対照だと信じてきた。

信じるだけでは足りないので、engine に訊いた。

## §2 相手を入れ替えても、分布は一ビットも動かない

`tools/pair_identity_probe.py` を書いた（この回の新しい計器。読み取り専用、台帳には一行も書かない）。対象・判定・証拠型・重みをすべて固定し、`compared_against_hypothesis_ids` だけを入れ替える。

`Q-003` 首位 `HYP-20261113-a35ee5`（P=14.43%）に、`narrows_scope`（`reproducible_script`、δ=1.35）の行を一本だけ架空に足す。相手を二通りに入れ替える。

| 相手 | 選び方 | 相手の P（前→後） | 対象の P（後） |
| :--- | :--- | ---: | ---: |
| `HYP-20261116-91572a` | 順位で隣 | 9.19% → 9.96% | 3.31% |
| `HYP-20261112-5273a5` | 同問い・最下位 | 0.00% → 0.00% | 3.31% |

**測定**（`python3 tools/pair_identity_probe.py`）：二通りで posterior ベクトルの差は

```
max |posterior difference| between partners: 0.000e+00   <- identity not read
```

**37仮説の事後確率が、小数第12位まで一致する。** 相手が誰であれ、対象の確率も、他の36の確率も、同じである。

**そして、ここで一度立ち止まる必要がある。** 当初私はこれを「差が出るのは名指された相手自身の確率だけ」と書いた。**それは誤りだった。** 回帰テスト（`tests/test_pair_identity_probe.py`）を書く過程で、合成台帳の上で `narrows_scope` の行の相手を入れ替えると、**名指された相手の log-odds すら動かない**ことが分かった。理由は §1 の (3) にある——`share` の減点は `supports` の分岐の中にしかない（:683-689）。`narrows_scope` の行は相手を**減点しない**。相手は割引のスイッチとしてだけ読まれ、それ以外の何も受けない。

**修正後の文。** `narrows_scope` の行にとって、比較相手は**完全に無内容**である。空でなければ 0.65 の割引が外れる、それだけ。`supports` の行だけが相手から `0.20 × δ ÷ 件数` を引き、その場合にかぎり softmax の分母が動くので、**名指していない第三者の確率も動く**（合成台帳で 6.5 ポイント動いた）。

つまり、同じ欄が判定によって**別の意味**を持つ。`supports` では「減点を置く宛先」、`narrows_scope` では「割引のスイッチ」。どちらも相手の同一性を読まないが、読み方の悪さが二段階に分かれている。

**解釈。** 「AをBと比較した結果、Aが狭められた」と読める行は、engine にとって「Aから δ×1.15 を引いた（Bは何も受けない）」という一操作でしかない。「AをBと比較した結果、Aが支持された」は「Aに δ を足し、Bから δ×0.20 を引いた」の二操作である。BがAと両立するか、BがAの否定か、BがAの特殊例か、BがAの先祖か——どれも読まれない。

**これは §1 の読み上げではなく、測定である。** 入れ替えて動かないことを確かめた以上、「読んでいない」は推測ではなく観測になった。そして、当初の私の書き方の方が engine を正確に写していなかったという事実も、測定の一部としてここに残す。

## §3 「比較」の全体量は、割引のスイッチ一つ分しかない

では、相手を名指すことには何の意味もないのか。意味は一つだけある。

**測定**（同ツール、ARM none）：同じ `narrows_scope` の行から `compared_against_hypothesis_ids` を空配列にすると、対象の確率は 3.31% から **5.65%** へ動く。差は **+2.34 ポイント**。**この差が、相手を名指すことの全効果である。**

理由は §1 の (2) である。相手が空だと `comp_factor` が 0.65 に落ち、δ が 35% 減る。相手を一人でも名指すと 1.0 になり、減らない。

**解釈。** この台帳における「比較」の情報量は、**35% の割引を回避したかどうか**、それだけである。誰と比べたかは問われない。「比較した」と書けば、比較しなかった場合より対象が有利になる。書かなければ損をする。

この非対称は、`HYP-20261117-b17a54`（支持の減点方向説）が子と親のあいだで測ったものと同型である。あの説は「子を支持する行は、比較相手に親を名指すことで割引を免れる」と言った。私はそれが**子と親に限らない**ことを見つけた。どの行でも、相手を名指せば 1.35 倍で効き、名指さなければ 0.8775 倍で効く。系譜は関係ない。

**「比較相手」欄は、系譜の欄ではなく、重みの欄である。**

| 仮説 | 問い | 前 | 後 |

| `a35ee5`（対象） | Q-003 | 14.43% | **39.42%** |
| `874658`（名指された相手） | Q-002 | 78.83% | 73.97% |
| `977052`（**名指されていない**） | Q-002 | 11.56% | **14.21%** |

**解釈。** `Q-003` の内部で書かれた一行が、`Q-002` の分布を動かした。しかも**誰も名指していない `977052` の確率を上げた**——相手から引いた分が、同じ問いの softmax の中で再配分されたからである。

**測定**：194 の対それぞれについて、A を対象・B を比較相手とする `supports` 行と、B を対象・A を比較相手とする `supports` 行の両方が存在する対を数える。

- **28 対**が、両方向に支持されている。
- **57 対**が、両方向に狭められている。

例（**測定**）：

| 対 | A→B の supports | B→A の supports |

**解釈。** 命題として読むなら、これは矛盾である。「証拠は A が B より正しいことを支持する」と「証拠は B が A より正しいことを支持する」が同時に台帳にある。28 対で。

engine はこれを矛盾として検出しない。**検出する必要がないからである。** 各行は「対象に足す／比較相手から引く」という独立な操作であり、二つの行が逆向きでも、それぞれが別の仮説に足し、別の仮説から引くだけで、算術は破綻しない。

**しかし、この台帳を読む次のセッションは、`BELIEF_MAP.md` の「最優先検証対」を、対立する二つの仮説として受け取る。** その対の 55% は、すでに二度以上「分離」されており、その一部は両方向に支持されている。**分離とは、ここでは何も分けていない。**

これが `HYP-20261115-d4e873`（対立不在の対立対説）とどう違うか。あの説は「**選出式**が対立を検査しない」と言った。私はその一段手前を測った。**選出式に渡される前に、行そのものが対立を記録していない。** 式を直しても、入力が対立でなければ、対立は出てこない。

`d4e873` は現在 `narrowed` で、`Q-20261116-3872ec` の 100% を占めている（**測定**）。その問いには他の仮説がなく、したがって比較もできない。**「対立が記録されていない」という仮説が、対立のない問いに一人で置かれている。**

## §7 訂正の受け皿は作られ、使われなかった

`ERR-20261114-779c68` は、訂正の到達経路を測った行である（**引用**、`check.params.consequence`）：

> 文書が挙げる3種のうち断片は伝播経路に存在せず（仮説側に対応フィールドが無い）、文書が挙げない評価が経路になっている。しかもその評価経路は supports だけに通る。**訂正は、自分が上げた仮説には届き、自分が下げた仮説には届かない。**

この閉路を塞ぐために、`weight_effect: "void_row"` が 2026-11-16 に導入された（**引用**、`schema/errata.schema.json`）：

> 'void_row' withdraws the weight of the evaluation row named by subject_id … This exists so that correcting one's own over-claim punishes the row, not the hypothesis the row supported.

私は数えた。

**測定**：

| 項目 | 値 |
| :--- | ---: |
| 生きている訂正で、宛先が既存の評価行を指すもの | **18** |
| そのうち `weight_effect: void_row` を持つもの | **0** |
| 2026-11-16 以降（`void_row` 導入後）に書かれたもの | **9** |
| `errata_flags` に現れる（＝次の読み手に見える）もの | **11 / 18** |
| 現れないもの | **7** |

`void_row` を名指さなかった 9 行は、導入の翌日以降に書かれている。`ERR-20261117-3f1354` と `ERR-20261117-b1330f` は**今日**書かれた。どちらも `status: open`、`verdict: contradicted`、宛先は評価行、`weight_effect` は無い。
