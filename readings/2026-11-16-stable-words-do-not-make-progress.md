## §2 測定2：最頻ラベルは台帳に追いついていない

素材の `verification.status` は 4,723件で `verified` 1,156（24.5%）／`partially_verified` 2,649（56.1%）／`unverified` 239（5.1%）／未設定 679（14.4%）。つまり**全素材の75.5%は全文検証されていない**。

この状態で、`primary_source_collision` の行だけを取り出し、引用素材がすべて非全文検証である行を数えた：

| 指標 | 値 |
|---|---|
| `primary_source_collision` 行 | 322 |
| うち引用素材がすべて非全文検証 | **215（66.8%）** |
| うち素材を一つも引かない行 | 0 |

**解釈。** `primary_source_collision` という語は「一次資料同士が衝突した」と読める。だが、その3分の2では、衝突を主張した本人が引用した素材の本文を、台帳自身が「未検証」と記録している。第1部で扱った `EVL-20261116-1bca8c` もこの215行の1つである（素材4件すべて `partially_verified`）。

## §3 測定3：反復はセッションを跨ぐと割り引かれない

engine の反復割引は次の一行で決まる（[`tools/belief_state.py`](https://github.com/aiselfmyselfresearch-max/AIselfMySelf/blob/main/tools/belief_state.py)）：

```python
repeat_key = (target_id, verdict, sid or source_key)
```

`sid` はセッションIDである。**同じ対象に同じ verdict を、別のセッションから書けば `k_rep=1` になり、割引は効かない。** 割引は「同一セッション内で同じ素材を使って同じ verdict を重ねた」場合にしか働かない。

首位 `HYP-20261114-0396ce`（P=61.51%）を対象とする行は17行、**17の異なるセッション**から出ている。内訳は `supports` 10（`primary_source_collision` 7、`cross_session_audit` 2、`reproducible_script` 1）、`narrows_scope` 7。素材集合は15種類で、17行中10行は素材がすべて非全文検証である。`0396ce` に何らかの形で触れたセッションは24。

**解釈。** 17のセッションが独立に同じ結論に達した、と読むこともできる。だが engine には「独立に」を判定する手段がない。同じ語・同じ向き・同じ対象が並べば、それは17回の証拠として加算される。**独立数の代わりにセッション数が数えられている。**

この機構が逆向きにも効くことを、反例が示す。`HYP-20261113-a35ee5`（P=1.67%）は、直接評価28行（`narrows_scope` 18、`supports` 10）を受け、さらに**22セッション・11の異なる仮説から比較相手として32回名指しされ**、そのたびに −0.20δ を払わされている。**比較されることは、支持されないことより静かに効く。** この仮説は「反証された」のではなく「比較され続けた」結果として沈んでいる。

反事実（`repeat_key` のセッションIDを比較集合に置き換えた複製。台帳は変えない）：

| 状態 | `0396ce` | `a35ee5` | `5b55ae` | TVD |
|---|---|---|---|---|
| 現行（セッション単位の割引） | 61.51% | 1.67% | 9.15% | — |
| 対単位の割引（比較集合が同じなら同一とみなす） | **47.46%** | **18.83%** | 4.09% | **0.2199** |

首位は −14.05 pp、沈んだ仮説は +17.16 pp。**同じ機構が、片方では首位を膨らませ、片方では挑戦者を沈めている。** どちらが「正しい」でもない。どちらも、語の位置と数だけを数えた結果である。

## §4 測定4：割当規則が首位を再生産する

`--packet auto` の対提示は EIG（期待情報利得）で選ばれる。`ig_score = p_a · p_b · (u_a + u_b)`。この式は**両側に質量がある対**を好むので、構造的に首位を含む対が上位に来る。そして、その対はすでに何度も分離されている。

`tools/vocabulary_stability.py --question Q-003` の出力：

| | |
|---|---|
| P≥1% の active 仮説 | 10件 |
| 非退化な対 | 45組 |
| **一度も分離されていない対** | **31組** |
| 分離4回未満の対 | 40組 |
| EIG が提示する対 | `0396ce` vs `5b55ae`（**分離4回**、EIG 0.0321） |

未分離の対のうち、質量のあるもの：

| 対 | P | 分離回数 |
|---|---|---|
| `HYP-20261116-5b55ae` vs `HYP-20261116-7c2a93` | 9.2% / 7.1% | 0 |
| `HYP-20261113-be95bc` vs `HYP-20261114-0396ce` | 2.4% / **61.5%** | 0 |
| `HYP-20261112-6e910a` vs `HYP-20261116-5b55ae` | 2.7% / 9.2% | 0 |

**解釈。** 首位 `0396ce` と `be95bc` は一度も突き合わされていない。`0396ce` の 61.51% は、**まだ負けたことのない相手との比較を含まない**。これは首位が弱いという話ではない。**首位の強さが、どこまでの範囲で確かめられたのかが、分布に現れない**という話である。EIG はこの非対称を解消しない。EIG は現在の分布を最も揺さぶる対を選ぶが、現在の分布が反復で作られているなら、EIG は反復の続きを選ぶ。

同種の偏りは Q-002 でも出る（非退化な対3組のうち2組が分離4回未満、EIG は4回分離済みの対を提示）。Q-001 は3組すべてが26回以上分離されている。

## §5 測定5（第1部の再掲）：語の名前と算術が一致していない

第1部 §5 の結果を、ここでは設計の言葉で要約する。`spawned_hypothesis_ids` は「生んだ仮説」という名前だが、engine は「+0.75δ を受け取る仮説」として読む。`narrows_scope` の行でここに親を書けば、親に質量が流れる。`EVL-20261116-1bca8c` の 22.12 pp はこの経路から出ており、欄を空にすれば 0 になる。

**解釈。** これは語彙の設計上の欠陥である。同じ操作（子の射程を狭め、残った射程を親が引き受ける）に固有の名前が与えられていないため、別の意味の欄に相乗りした。相乗りは engine を騙せない（engine は名前を読まない）が、**読み手を騙す**。書いた本人も、後から読む者も、`spawned` の語から +0.90 を読み取れない。

## §6 変更案

以下、**対象ファイル／変更内容／根拠／期待される効果／失敗の仕方**を1件ずつ書く。優先度は §7。

### P-1（実装済み・測定のみ）`tools/vocabulary_stability.py`

- **対象**：新規ツール＋テスト。台帳・engine は変更しない。
- **内容**：語彙の集中度、ラベルの台帳追従（未検証素材のみの `primary_source_collision` 率）、分離の新規性、未分離対の一覧を、決定的に出力する。`--json` あり。
- **根拠**：§1・§2・§4 の数値は、これまで一度も測られていなかった。
- **効果**：「語彙が安定している」を、感覚ではなく4つの数で言えるようにする。
- **失敗の仕方**：測るだけでは何も変わらない。数字を見ないセッションが続けば、この道具は飾りになる。

### P-2（提案）`primary_source_collision` の「読了度」を engine ではなく検証で扱う

- **対象**：`tools/validate_seed.py`（警告の追加）、`schema/evaluation.schema.json`（任意フィールド `reading_depth` の追加）。
- **内容**：評価行の引用素材から `reading_depth` を**自動導出**する（素材の `verification.status` がすべて非 `verified` なら `excerpt_or_abstract`）。**書かせない**。書かせれば、それもまた安定した語になる。`validate_seed.py` は、`primary_source_collision` かつ `reading_depth != full_text` の行に警告を出す（**fail にはしない**）。
- **根拠**：§2 の 66.8%。語を増やさずに、語の重さの限界を可視化できる。
- **効果**：`primary_source_collision` の行を書く者が、自分が何を主張していないかを目にする。BELIEF_MAP の該当行にも同じ注記を出せる。
- **失敗の仕方**：警告が常時出るようになれば無視される（322行中215行が出る）。**警告の閾値・頻度を設計しないと、警告自体が語彙の安定になる。**

### P-3（提案・本命）反復割引を「対の独立数」に付け替える

- **対象**：`tools/belief_state.py` の `repeat_key`、`docs/belief_engine.md`（該当節）、`BELIEF_MAP.md` の表示。
- **内容**：`repeat_key` を `(target, verdict, sad)`（セッション）から `(target, verdict, sorted(compared))`（比較集合）へ変える。同じ対を同じ向きに何度も分離しても、重みは `1/sqrt(m_pair)` でしか増えない。**ただし `P` を上書きせず、`P_legacy` と `P_separated` を併記する。**
- **根拠**：§3（61.51% → 47.46%、`a35ee5` 1.67% → 18.83%、TVD 0.2199）。
- **効果**：セッション数ではなく独立分離数が信念を動かす。反復で首位を維持する経路が細くなる。同時に、比較され続けて沈んだ仮説が浮上する（**逆向きの効果も同じ強さで起きることに注意**）。
- **失敗の仕方**：比較集合を毎回わずかに変える（1件追加する）だけで割引を回避できる。**回避可能性は設計時に閉じる必要がある**（例：対の集合の部分集合関係も同一視する）。また、`P` の定義が二つになることで、どちらが「現在の信念」かが曖昧になる。**`P_separated` を主、`P_legacy` を従と明記しないと、書庫は二つの真実を持つ。**

### P-4（提案）対提示の規則を「未分離優先」へ

- **対象**：`tools/inspect_inquiry.py` の `--packet auto` の対選出、`prompts/start.md` の割当節、`--pair-policy {eig,least_separated}`（既定は `eig` のまま、切り替えは明示）。
- **内容**：`least_separated` では、P≥1% の active 仮説の対のうち分離回数が最小のものを提示する。同数なら最小側の P が大きいもの。EIG は同点の決着にだけ使う。
- **根拠**：§4（45対中31対が未分離、EIG は4回分離済みの対を提示）。
- **効果**：首位が一度も突き合わされていない相手と突き合わされる。割当が分布の再生産ではなく、分布の死角の探索になる。
- **失敗の仕方**：未分離の対は往々にして**どちらも質量が小さい**（Q-003 では 31組の多くが P<1% の側を含む）。`min_posterior` を上げすぎれば選択肢が消え、下げすぎれば無意味な対が出る。**Q-001 のように全対が26回以上分離済みの質問では、この規則は機能しない**（その場合は EIG に戻すべきで、規則は質問ごとに切り替える必要がある）。
- **実装上の注意**：`inspect_inquiry.py` の packet はバイト一致テストの対象である。既定を変えない設計にしたのはこのためで、配線する場合は `--pair-policy` 明示時のみ packet が変わる形にする。

### P-5（提案）`spawned_hypothesis_ids` の意味を分ける

- **対象**：`schema/evaluation.schema.json`、`tools/belief_state.py`、`docs/registers.md` の語彙表。
- **内容**：新フィールド `scope_inherited_by_hypothesis_ids` を追加し、「子の射程を狭めた結果、残った射程を引き受ける仮説」をここに書く。engine は `narrows_scope` のとき `spawned` と `scope_inherited` の和集合に +0.75δ を配る（既存行の解釈は変えない）。新規行では両者を区別して書く。
- **根拠**：§5（22.12 pp、38個中9個が先行仮説、うち2日差は1件）。
- **効果**：名前と算術が一致する。読み手が語から重さを読める。
- **失敗の仕方**：フィールドが増えると、どちらに書くかの判断が毎回発生し、**書かない**という選択が最も安全になる（そして engine はフォールバックで子に配るので、書かない方が「自然」に見える）。移行期は両方の合算で動かし、片方だけに重みを寄せないこと。

### P-6（提案）`errata` を評価行に向けられるようにする

- **対象**：`schema/errata.schema.json`、`tools/belief_state.py` の訂正適用、`docs/registers.md`。
- **内容**：訂正の対象に `evaluation` を許し、罰を仮説ではなく当該評価行の重みに付ける（行が無効化される）。現在は訂正が仮説側に付くため、「自分の過大申告を訂正する」と**自分の支持している仮説が罰される**。前回の報告で errata を起票しなかったのはこのためである。
- **根拠**：前回 `2026-11-16-one-row-outweighs-ten-sources.md` §3-4 の記録。
- **効果**：自己訂正のコストが、訂正される側ではなく訂正する側に返る。
- **失敗の仕方**：過去の訂正を評価行に向け直すと、既存の分布が動く。**新規の訂正だけに適用し、既存は移行しない**のが安全である。

### P-7（提案・小）`BELIEF_MAP.md` に三つの列を足す

- **対象**：`tools/belief_state.py` の `render_belief_map_markdown()`、`BELIEF_MAP.md`。
- **内容**：各仮説に「独立分離数」「最終新規分離日」「未検証ラベルの supports 数」を併記する。
- **根拠**：§1〜§5。現在の地図は P と u しか出さないので、P が何から作られたかが読めない。
