## §1 規則を「明日」からにした理由

この書庫の古い行は、ID に内部編年ラベルを持つ。`Q-20270221-…` のような問いの実日付は 2026-11 であり、
`created_at` すらラベルの行がある。したがって「ID が 2026-11-16 以降なら規則を適用」と素朴に書くと、
**過去の行が一斉に規則違反になる**（実装の初回でそうなり、質問数十件が `register is missing` を出した）。

修正は `_is_new_row()` で **cutoff ≤ ID の日付 ≤ 今日** を条件にしたことである。上限（今日）が、
未来のラベルを持つ履歴行を除く。新規シャードの前倒し日付は `tools/date_axis.py --enforce-shards` が既に拒否するので、
この上限は「新しい行を取りこぼす」方向には働かない。規則は採番日で適用され、**既存行は書き換えない**。

## §2 飽和規則は何を禁じないか

実装した文面は「新しい根仮説を足してEIGを回復させないでください」である。これは禁止ではなく、
**既定の行き先から外す**という意味にした。理由は三つある。

1. **事後確率を動かさない。** `saturation_snapshot()` は読むだけで、`compute_belief_state()` の数値を変えない
   （テストで確認している）。飽和は「信じるのをやめた」ではなく「選別器が選べなくなった」である。
2. **仮説の追加を禁じない。** 反証条件を持つ仮説は、飽和していても知識になりうる。禁じるのは
   「EIG を戻すために根を足す」という動機だけである。
3. **代わりの行き先を具体的に出す。** (a) 未解決 `errata`（2026-11-15 のパケット表示で **47件**）、
   (b) claim→評価の配線を伴う再読、(c) 新規資料（`prompts/acquisition.md` の情報利得ゲート）。

2026-11-15 の実測では `Q-001` 0.0067・`Q-002` 0.0000 が飽和、`Q-003` 0.2259 が非飽和である。
パケットには飽和した問いだけが並び、対象が `Q-003` のときは「対象は非飽和で選別はまだ効いている」と出る。

## §5 限界

- **規則は明日から**なので、今日の時点で規則を実際に踏む行は無い。テストは日付を固定して検査している（`tests/test_wiring_rules.py`）。
- **分類語の正規表現**（分類・類型・判定・基準・カテゴリ・仕分け・区分け・クラスタ）は粗い。分類の産出を過大にも過小にも数えうる。
- **`register` は自己申告**である。宣言と実際の使われ方がずれる余地は残る。ずれを見つける道具はまだ無い。
- **0.02 という閾値は私が選んだ**。`Q-003` の 0.2259 を飽和にしないための値であり、根拠は「現時点で二問がこれ未満」という事実だけである。変えるときは日付と理由を `docs/registers.md` に残す。
- **`state/notes.d/` は soft 上限（131ファイル）に到達している。** この回の note 行は、同日の自分の既存 notes シャードへ末尾追記し、新規シャードの作成は取り下げた（同一コレクション内の移動は `docs/parallel-work.md` が認めている）。次の note 行の前に §3 の統合手順が要る。これは台帳の負債ではなく容量の事実であり、ここで一斉整理は始めない。
- **`prompts/start.md` は変えていない**。したがって新しいレジスタ規則は、パケット（`inspect_inquiry`）と `docs/registers.md` と CI からしか届かない。開始プロンプトにも書くべきなら、それは別の委任として、旧文面と理由を残して行う。
