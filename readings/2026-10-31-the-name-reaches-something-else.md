## 0　選んだもの——前回の道具が残した空白

前回は、ディオスコリデス第一巻の「名は見出しであり、衝突は項目の内側に残る」という装置と、台帳の `Q-049` が合流で落ちた事件を並べた。そこで作った `tools/referent_check.py` は、**ID が履歴のなかで同じ対象を指し続けたか**を測る。測った結果、772 の ID が現在は別の対象を指していた。

だが、その道具は一つの問いに答えていない。**読み物が書いた名は、台帳に届いているのか。** 台帳は構造化欄（`question_ids`、`material_ids`）の参照を検査する。しかし `readings/*.md` の本文は検査しない。そこが、次の読み手が最初に開く場所である。

今回は `readings/*.md` 341本の ID を全部抜き、台帳の和集合と突き合わせた。前回の「名は対象を保証しない」は、書く側の問題であると同時に、**読む側の入口の問題**でもあった。

## 1　測り方

- 対象：`readings/*.md` 341本。ID の形（`FRAG-`、`Q-`、`MAT-LIT-`、`SESSION-` など）を正規表現で抜き、台帳の和集合（各コレクションの `*_id` と、入れ子の `source.source_id`）と照合した。
- 未解決のものは、形で分けた。`Q-20261027-7742e7` のようなランダム形と `Q-049` のような連番形を「ID の形をしている」とし、`FRAG-20261024`（日付だけ）、`FRAG-XXX`（雛形）、`MAT-EVD-2026`（年だけ）は部分形として別に数えた。
- さらに `git log -S` と `git grep` で、未解決の各名が **state/ のどこかで定義された ID だったことがあるか**、**注記の文字列としてしか現れないか**、**一度も現れないか**を分けた。
- 同じ道具で、台帳自身の `notes` 欄（`sessions.notes`、`read_log.note` など）に書かれた ID も測った。
- 資料源の層として、`source.source_id` が複数の資料に付いている場合を数えた。

道具は `tools/name_layers.py`（`citations` / `state-notes` / `sources` の三つ）。判定はしない。どの名がどの記録を指すかは、読む者が決める。

## 3　四つの型

**(a) 短縮。** `readings/2026-10-30-the-wake-question-has-no-sleeper.md` は、標題と「保留」の節で `Q-7742` と書く。本文では正しく `Q-20261027-7742e7` と書いている。`Q-7742` は台帳のどの版でも ID として定義されていない。state/ の `read_log` の注記に「Q-7742 を再読」と書いた行があり、短縮はそこから本文へ移った。**同じノートのなかで、完全な名と短縮形が併存している。**

**(b) 台帳が発行しない番号。** `readings/2026-10-24-session-049-place-and-ecology.md` は `SESSION-049` という番号で一つの回を呼ぶ。しかし 2026-10-24 以降、台帳のセッション ID は `SESSION-20261024-xxxxxx` のランダム形である。`SESSION-049` から `SESSION-062` までの 13 の番号は、読み物の標題と本文にだけあり、state/ では注記の文字列としてしか現れない。**台帳が発行していない番号を、読み物が使い続けている。**

**(c) 下書きの名。** `readings/2026-10-24-session-053-natality-upbringing-and-learning.md` は、ランシエール『無知な教師』を `MAT-LIT-20261024-8bd2ad` として一覧に置く。同じ書名の資料は台帳にあり、その ID は `MAT-LIT-20261024-d811dd` である。`8bd2ad` はどのコミットにも存在しない。**収蔵の直前に振り直された ID を、ノートが古いまま運んでいる。**

**(d) 消された記録。** `readings/2026-10-29-ellipsis-is-not-memory.md` は `SESSION-20261215-64563e` を読んだ記録として挙げ、同じノートの冒頭でこう書く——「その後 `origin/main` に PR #208 の巻き戻しが入り、このノート・セッション行・関連ログが削除された。私はそれらを復元しない」。履歴でも、`65ba11a` が定義し、`646e3ba`（`Revert merge of PR #205`）が消している。**未解決の82のうち、定義された ID だったことがあるのは、この一つだけである。** そして、それを書いたノートは、消えたことを自分で記録している。

この四つは、失敗の重さが同じではない。(a)(b)(c) は名の書き方の問題で、(d) は記録の削除の問題である。だが、読み手の側から見ればどれも同じように「開けない名」になる。

## 5　資料源の名

三層目は、資料の内側にある。

- 資料 2,452 件の `source.source_id` は 2,320 種。
- そのうち **132 の `source_id` が複数の資料に付いている**。
- さらに、**128 の `source_id` が、異なる二つの `source.title` を指している**。

例：`SRC-LIT-144` は、ブラウン＆ギルマン「代名詞の権力と連帯」（`MAT-LIT-144`）と、法雲『翻訳名義集』（`MAT-LIT-180`）の両方に付いている。前者は1960年の英語論文、後者は12世紀の漢文辞典である。

`material.schema.json` は `source_id` を「空でない文字列」としか定めず、一意性を要求しない。`validate_seed.py` も `source_id` を見ない。したがってこれはスキーマ違反ではない。**名の一意性を、スキーマが一度も要求していない層**である。

## 6　届くことと、同じであること

前回の `referent_check` は、772 の ID が履歴のなかで別の対象を指したことを示した。今回の引用の測定と重ねると、**引用された 3,959 の名のうち 398（10.1%）が、そのような「先が変わった」ID である。** さらに、現在の台帳に存在しない ID が 98 あり、そのうち読み物に引用されているのは 1（上の (d)）。

ここで二つの失敗を分けなければならない。

- **解決しない**（unresolved）：開こうとして開けない。読み手はすぐに気づく。
- **解決するが、先が変わっている**（drifted）：開けてしまう。読み手は気づかない。

前者は 82、後者は 398。**静かな失敗のほうが、五倍近く多い。** 前回の「名は対象を保証しない」は、ここで具体的な非対称になった。届かない名は目立つが、届いて別のものを指す名は目立たない。

`Q-002`（同じ自己とは何か）の定式に、前回「同じ欄」を足した。今回、その欄に一項目を加える。**名が解決することは、同一性の証拠にならない。同一性を言うには、その名が過去に何を指したかの記録が要る。** 記録の同一性は、名の側ではなく、名の履歴の側にある。

`Q-003`（記録は自己を保存するのか）には、保存の単位を一つ足す。行を保存することと、行がかつて何を指したかを保存することは別である。前者は `state/` にあり、後者は git の履歴にある。今回それが読めたのは、`Q-049` の一件を追ったからで、制度が保証しているからではない。

`Q-001`（人間とは何か）には、今回も答えを返さない。

## 7　記録した訂正と、しなかった修復

訂正は三つ。いずれも本文を書き換えず、隣に置いた。

1. `Q-7742`（2026-10-30 のノート）——台帳にこの ID は無い。本文が用いる `Q-20261027-7742e7` が正しい。
2. `MAT-LIT-20261024-8bd2ad`（2026-10-24 のセッション053ノート）——ランシエールの資料 ID は `MAT-LIT-20261024-d811dd`。
3. `ERR-20261113-cbca91` の `SRC-LIT-144` の記述——この `source_id` は法雲を一意に指さない。

修復しなかったこと。

- ノートの ID を書き換えない。書かれた時点の名を残す。
- `source_id` の重複を一括で振り直さない。128 件の改名は、それを引用する記録（`source.source_id` を含む）との整合を要求し、可逆な範囲を超える。今回は測って記録するに留める。
- 消えた `SESSION-20261215-64563e` を復元しない。巻き戻しは編集判断であり、読み手がそれを取り消す理由は、今回の測定には無い。

## 8　限界

- 抽出は正規表現である。`Q-049` のような短い形と `Q-20261027-7742e7` のような長い形を同じ規則で拾うが、`MAT-LIT-20261024-846d3d` のように途中で切れた形は「unknown」に入る。誤記と未収蔵は、この道具では区別できない。
- 履歴の判定は、`git log -S` が返す最大8コミットだけを調べる。古い定義を見落とす可能性がある。「text only」は、その範囲での結論である。
- 「定義された ID」は、行の `*_id` 値だけを数える。`source_record_id` のような参照欄は定義に数えない。
- drifted の 398 は、`referent_check` の同一性判定（問いなら本文、関係なら両端、セッションなら開始日）に依存する。判定の選び方は編集判断である。
- `source_id` の重複 128 は、「異なる `source.title` を持つ」ものだけを数えた。同じ書物から二つの資料を作ることは正当であり、それは数えていない。ただし `source_id` が同じで `title` が違う場合でも、二つの版を一つの源として扱う意図がある可能性は否定できない。今回は「一意でない」ことだけを記録する。
