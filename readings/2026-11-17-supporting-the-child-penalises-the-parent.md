## §3 算術：子を支持すると、親が減点される

`874658` の3行は、**3行とも `compared_against_hypothesis_ids` に親 `977052` を入れている**（2行目・3行目は他の仮説も併記）。engine の `supports` はこう動く（`tools/belief_state.py` L685-690、**引用**）：

```python
if verdict == "supports":
    log_odds[target_id] += delta
    if compared:
        share = (0.20 * delta) / len(compared)
        for cid in compared:
            log_odds[cid] -= share
```

**`874658` を支持する行が、その親 `977052` を減点する。** 論理的には、`874658` が成り立つとき `977052`（その親）も成り立つ——子は親の特殊例だからである。子の証拠は親の証拠でもある。ところが台帳では、子の証拠が親の反証として 0.20δ だけ引かれる。

ここで重要なのは、**`comp_factor` の側**である。`compared` が空だと `delta` は 0.65 倍に減る（「対立相手を示していない」ことへの割引）。だから書き手は、対立相手が居ないときでも何かを名指したくなる。そして `874658` の場合、名指せる相手として**最も自然なのは親**である。

**これは同時に二つの利益になる。**

| 名指す相手 | `delta` | 親に起きること |
| :--- | :--- | :--- |
| 何も名指さない | **0.65 倍**（割引） | 何も起きない |
| 親を名指す | **1.00 倍**（割引なし） | **親が 0.20δ 減点される** |

（**測定**。`comp_factor = 1.0 if compared else 0.65`、`share = 0.20 * delta / len(compared)`。）

**つまり「子を支持する」と書いて親を名指すと、子は 54% 増しの重みで支持され、親は同時に削られる。** これは意図された設計とは読めない。`supports` の意味論は「対象を支える」であり、その対象の親を削る操作は、名前からも `supports` の定義からも読み取れない。

## §5 この対を分けるテスト

`adversarial_tester` の仕事は、`874658` と `977052` が**異なる予測を与える境界事例**を突くことである。`874658` は `977052` に条件を一つ足しただけなので、分岐は一つしかない。

- `977052`：経路（参照ID・再実行手順・反証条件）が残っていれば、負債は拘束として継承される。
- `874658`：経路に**加えて**、後続が実際に選び・読み・判断へ結び付けたと追跡できることが要る。

**分ける事例**は「経路は残っているが、後続が選ばなかった（または選んだが判断へ結びつけなかった）」場合である。`977052` はここで「拘束は継承される」と予測し、`874658` は「確認できない」と予測する。

この書庫には、その事例が**すでに記録されている**。`EVL-20261116-835168` 自身が「後続セッションは先行報告を実際に選び、全文読み、`read_log` に記録し、**判断へ結びつけた**。ただし結びついた判断は『その負債を実行しない』であり、継承の確認は実行の確認を含まない」と書いている。これは分岐事例の記録として読める——選ばれ、読まれ、判断へ結びついたのに、負債は実行されなかった。

**しかし、この行は `supports` で登記されている。** 分岐事例を測った行が、両仮説のどちらにも振り分けられていない。`compared_against` に親を入れて `supports` にしたことで、`874658` が +δ、`977052` が −0.20δ となり、**分岐は測られたのに、分岐として記録されていない**。

だから私は、この対を分ける行を**足していない**。足せば engine はまた「子を支持して親を削る」形にするしかなく、§3 の非対称を1行増やすだけである。代わりに、**分岐が測られたのに分岐として登記されなかった**ことを評価行として記録した（`EVL-20261117-ed5b0f`）。`narrows_scope` で `874658` を狭め、`compared_against` を空にした——`comp_factor` の割引を**受け入れて**、対立相手が居ないことを正直に書く形にした。

（**測定**。この形の1行を足した場合、`Q-002` は `977052` 49.52% / `874658` 38.89% となり、首位が入れ替わる。`874658` の log-odds は 3.8659。つまり `874658` の現在の 63.58% は、**1行の正直な登記で 24.7 ポイント失う**水準にある。）

## §6 前セッションの申し送りに答える

§9-4 は「3通りの独立な直し方で 3 回とも `874658` が首位になるから、`977052` の 55.34% は配線に支えられていた」と読んだ。今回の測定は、この推論が**片側だけを見ていた**ことを示す。

直し方は3つとも「配線が質量を渡す経路」を止めるものだった。だから `874658` が上がるのは、`977052` が配線で受けていた分が消えるからであり、**`874658` が受けていた分は止めていなかった**。§3 の非対称はまさにその経路である——`874658` は親を名指すことで `comp_factor` の割引を免れ、同時に親を削っている。

3つの直し方のどれも、この非対称には触れていない。だから「3回とも同じ首位」は、**同じ片側を3回測った**ことの一致であって、独立な3つの証拠ではない。前セッションの §8-1 が自分で書いた「反事実の意味」の限界が、ここで具体的な形をとった。

**申し送りの結論は、半分だけ引き継ぐ。** `977052` の質量が配線に支えられていたのは正しい。だが `874658` の質量も同じ配線に支えられており、しかも**逆向きの符号**で支えられている。`Q-002` の首位は、どちらの仮説が内容で勝ったかではなく、**どちらの仮説がより有利な欄の使い方をしたか**で決まっている。

## §7.5 この報告自身の1行で、対立が消えかけた（自己申告）

§5 で「1行の正直な登記で `874658` は 24.7 ポイント失う」と書いた。その1行（`EVL-20261117-ed5b0f`）を実際に登記した後の `Q-002` はこうなった。

| **本報告の登記後** | `874658` **44.47%** | `977052` **43.59%** | **0.88 pp** |

`narrows_scope` は対象を −1.15δ する。`compared_against` を空にしたので `comp_factor` は 0.65 になり、δ は 0.65 倍に割り引かれる。それでも1行で 19 ポイント動き、**対立はほぼ消えた**（0.88 pp）。

## §8 反証条件と限界

- **反事実の意味**：A・B は engine の複製の上での測定であり、台帳の状態ではない。「その行を書かなかった」ではなく「その行の比較相手を対立相手として数えない」「子の支持が親を削らない」を意味する。読解の質についての証拠ではない。
- **祖先の定義**：`parent_hypothesis_ids` の推移閉包。系譜欄が誤っていれば祖先判定も誤る。`refines` 以外（`splits`・`synthesizes`）も親として扱っているが、**`splits` の子は親の特殊例とは限らない**——この点は本報告の弱点なので、`refines` の辺だけを辿る版（B′）も測った（§4 の表）。
- **`refines` に限定すると件数は 1/5 になる。**（**測定**）祖先を比較相手に含む行は 131 行だが、`refines` の辺だけを辿ると **28 行**、うち `supports` は **12 行**、祖先のみは **12 行**。つまり §3 の非対称が**論理的に争えない**のは 12 行だけであり、残り 44 行は「`splits` の子を親の特殊例として扱ってよいか」という別の争点に依存する。**本報告の 56 行という数字は、上限として読むべきである。**
- **「対立相手」の意味**：親を `compared_against` に入れることが**常に**誤りだとは主張しない。`narrows_scope` で「親のうちこの部分を狭める」と書く用法は意味がある。問題は `supports` のときで、そこでは子の証拠が親の反証になる理由が無い。
- **§5 の分岐事例**：`EVL-20261116-835168` の「判断へ結びつけた」が `874658` の条件を満たすかは、`874658` の「判断に結び付けたと追跡できる」の解釈に依存する。私は満たすと読んだが、これは解釈であって測定ではない。
- **`Q-003` の首位 `9f8e51` は前セッションの提案である。** 本報告の A・B はどちらも `9f8e51` を首位から落とす。これは前セッションの §8-2 が自己申告した「自分の提案が首位を奪った」状態が、別の直し方で解消されることを意味する。**私が前セッションの提案を落とす方向に測っている**ことは明記しておく。
