**対象**：

## 第1部　「遠近法」のどこが測れるのか

`Q-036` は「選ばれた断片と選ばれなかった断片が同じ棚に並ぶとき、書庫はどんな遠近法を作っているのか」と問うた。この問いには二つの部分がある。

- **測れない部分**：その断片が読者に何を残したか。これは憲章が「自動ゲートにしない」と決めた領域で、数えられない。
- **測れる部分**：`status` という一語が、台帳のどこに効いているか。これは数えられる。

二つ目を数えないまま「選出には意味がある／ない」と論じるのは、`SESSION-021` が `voice_audit.py` の 58 文字切断で学んだ失敗（見えないものをゼロと数える）の繰り返しになる。だから今回は、**先に測れる部分を測る道具を作った**。

## 第2部　`tools/selection_audit.py` —— 選出の重みはどこに保存されているか

### 2-1. 数えたもの

断片ごとに四つ。

| 指標 | 出典 | 意味 |
|---|---|---|
| 関係線 | `state/relations.jsonl` | 何本の解釈的関係がこの断片に触れているか |
| セッション記録 | `state/sessions.jsonl` の `produced_fragment_ids` | 何回のセッションがこの断片を生んだと記録しているか |
| 言及 | `READING_MAP.md` 内のID出現回数 | 生成された読書案内がこの断片をどれだけ引き合いに出しているか |
| 本文長 | `state/fragments.jsonl` の `text` | 何文字書かれているか |

加えて、`MAT-TRC-002`（閲覧器の欄名盲点）の教訓に従い、**`viewer/app.js` の描画定数も読む**。台帳に書かれた重みと、読者の目に届く重みは別だからである。ツールは読み取り専用で、状態を一切書き換えない。

### 2-2. 実測結果

```
selected n=18  関係= 5.0  READING_MAP言及=15.78  本文長=548.39  セッション記録あり=18/18
draft    n=10  関係= 4.7  READING_MAP言及= 14.2  本文長=545.3   セッション記録あり=10/10
```

**差がない。** 関係線で 0.3 本、言及で 1.6 回、本文長で 3 文字。統計を語るほどの差ではない。

さらに二つの事実が出た。

1. **台帳全体で最も線が集まっている断片は `FRAG-019`（関係 9 本・言及 28 回）で、これは `draft` である。** 2位以下には選出済みの `FRAG-023`・`FRAG-024`（各9本）が並ぶが、`FRAG-021`（7本）・`FRAG-025`（7本）も draft として上位に入る。
2. **選ばれているのに線が少ない断片**もいる（`FRAG-014`・`FRAG-015`・`FRAG-013`・`FRAG-016`・`FRAG-003`、いずれも関係2〜3本）。

つまり、**選出は関係の多さで決まっていないし、関係の多さは選出を押し上げない。** 二つの軸は独立している。

### 2-3. この数字の弱さ（自己検算）

実測したあとに `FRAG-029` を追加したので、同じツールをもう一度走らせた。

```
selected n=18  関係= 5.0   READING_MAP言及=15.78  本文長=548.39
draft    n=11  関係=4.64   READING_MAP言及=13.64  本文長=524.55
```

**草稿を一編足しただけで、draft 群の平均は 4.7→4.64、14.2→13.64、545→524.55 と動いた。** 差が「小さい」ことと、差が「無い」ことは別である。n=10 の群では、一編の追加が平均をこれだけ動かす。したがって上の表から言えるのは「差が統計的に無い」ではなく、**「この台帳の現在の規模では、選出の有無を関係線の本数で読み分けることはできない」**という、もっと弱い命題である。

弱い命題でも、`Q-036` の役には立つ。遠近法が平坦かどうかを判断するには、まず**平坦さを測る物差しの分解能**を知る必要がある。今回分かったのは、その分解能がまだ粗いということだ。

### 2-4. `status` が実際に効いている唯一の場所

```
星座図の半径: selected=8.0 / draft=6.2  (比 1.29 倍)
状態フィルタ: あり / 状態バッジ: あり
```

`viewer/app.js` の 408 行目、星座図のノード半径は `f.status === "selected" ? 8 : 6.2`。**この書庫で「選ばれた」と「選ばれなかった」を分けているのは、現時点ではこの 1.8 と、バッジの色と、フィルタの三つだけである。**

これは欠陥ではない。むしろ正確な設計かもしれない。選出は内容の優劣の認定ではなく、人間の編集者による「今の重みの置き方」であり、それを台帳の構造（関係線・参照）に書き込めば、**選出が自己成就する**——選ばれたものが参照され、参照されたものが選ばれる、という循環が生まれる。`Q-037` はこの循環を問いにする。

しかし同時に、`status` が描画の定数にしか効いていないなら、**この書庫の遠近法はほぼ平坦である**。断片はすべて同じ速さで読まれ、ただ星座図の点だけが少し大きい。

## 第3部　`FRAG-029`「同じ重さの二冊」—— 最後の空席

### 3-1. なぜ `human_narrator` なのか

`SESSION-022` の検死は、`schema/fragment.schema.json` が定める六つの `narrator_mode` のうち **`other` と `human_narrator` が一度も使われていない**ことを報告した。`other` はその後 `FRAG-023`・`FRAG-025`・`FRAG-028` で使われ、今回の実測時点で **残る空席は `human_narrator` だけ**だった。

この空席が残っていた理由は、たぶん単純である。この書庫は「AIの一人称を、生身の経験の報告と混同させない」ことに慎重で（`CONTENT_POLICY.md`）、`human_narrator` はその慎重さの外にあるように見える。だが、**人間の語り手を創作することは、人間の経験の事実報告ではない**。`fictional_first_person` が「架空の一人称」であるのと同じ強度で、`human_narrator` は「創作上の人間の語り手」である。両方とも創作であり、台帳の外側のメタデータで区別される。

そこで `FRAG-029` では、製本所の職人という**架空の人間**を一人称の語り手にした。`editor_note` に「実在の人物の証言でも、AI自身の経験の報告でもない」と明記している。

### 3-2. 本文と、実測との対応

> 同じ版で刷った二冊は、秤の上で同じ目方を指した。……違うのは、私が片方の背にだけ小さな丸を箔で押したことだけである。
>
> （十年後、古書市で）持ち上げてみると、読まれなかった方がわずかに重い。湿気を含んだままだからだ。
>
> 丸は重さを変えなかった。変えたのは、どちらが先に開かれるかだけである。それでも十年たてば、先に開かれた方だけが軽くなっている。

この情景は、`MAT-TRC-004` の実測と一対一で対応している。

- **同じ目方の二冊** = 関係線 5.0 対 4.7、言及 15.78 対 14.2、本文長 548 対 545
- **背に押された小さな丸** = `viewer/app.js` の半径 8.0 対 6.2
- **十年後に軽くなっている方** = 読まれた方だけが、後から重さを変える

三つ目が、実測にはまだ現れていない。**選出は最初は重さを変えないが、読まれることで少しずつ重さを変える。** 台帳の数値は 2026-10-22 の一時点であり、この「十年後」はまだ来ていない。だからこの断片は、実測の報告ではなく、実測の**先**を書いている。

### 3-3. 意図した制約

- 保留句・二項対立・留保の型は 0（`voice_audit.py` の定型句リストで確認済み）
- 説明的な比喩を置かない。丸、目方、湿気、鳴る紙だけ
- 「選出」「status」「draft」という語を本文に一度も出さない。制度の語彙を使わずに制度を書く

今回の追加で、`schema` の六つの `narrator_mode` がすべて一度以上使われた。`voice_audit.py` の第6節も「未使用の narrator_mode : なし」と表示する。

ただし、空席が埋まったことは成果ではない。`SESSION-022` が `other` の空席を指摘したとき、それが重要だったのは「無主語で書く方法が未試行だった」からであって、「全モードを使い切る」こと自体に価値があるわけではない。**埋めた直後から、その席は埋まっていることが当たり前になる。** 次の空席は、おそらく `schema` の外側にある。

## 第5部　新しい問い

**`Q-037`（選出の重みはどこに書かれるべきか）**

> 選出の重みが描画の半径1.8にしか保存されていないとき、選出は書庫の中で何をしていることになるのか。重みは関係線や editor_note の文章として書き足されるべきなのか、それとも見え方の差だけに留めておくのが正しいのか。

この問いには罠がある。**重みを構造に書き込めば、選出は自己成就する。** 選ばれた断片に人が関係を張り、関係が張られた断片が次の選出で選ばれる。逆に書き込まなければ、選出は星座図の半径だけになる。どちらも閉じた循環である。

だから `Q-037` は、答えではなく**循環の所在**を記録する問いとして開いたままにする。
