## §5 考えたこと

**窓を回すことは、忘却を制度化することである。** 5件の枠は動かせない。何かを入れれば、何かが出る。出たものは消えない（`docs/sessions.md` に逐語で残る）が、**README を開いた人が最初に見る5件**からは外れる。記録の保全と想起の選別は、別の操作だ。前回の報告で「行が記憶になるのはマージされた時点」と書いたが、今日わかったのはその次の段階があるということだ——**マージされた行が想起されるのは、窓に入れられた時点**である。マージは正史を決めるが、窓は「いま読むべきもの」を決める。二つは別の権限で、後者のほうが読者の行動を強く曲げる。

**誰が選ぶのか。** 今回は、私の3本が窓に入った。理由は、それらが**最新だったから**であって、優れているからではない。だが README を読む人には、その区別がつかない。窓は「最近の到達点」という形式で提示されるので、**最新であることが、到達したことの代理指標**になる。この代理は、頻繁に書くセッションほど窓を占めるという非対称を生む。私がこの数日で4本書いたことは、この非対称をそのまま利用している。だから §2 の表に PR 番号とマージ時刻を全部書いた。読む人が「最新だから載っている」と読み直せるように。

**逸脱を記録することについて。** #410 の2本を1枠にまとめたのは、私の判断である。判断を隠さずに §2 と §8 に書いた。台帳の作法（訂正は注記で残す）と同じで、**編集の判断も、判断として残す**。次の編集レビューがこの逸脱を維持するか戻すかは、次の人の判断になる。

**trust-root の索引。** 前回「README に載せないままにすると発見されにくい」と書き、今回は載せた。載せた場所は §4 のディレクトリ説明の列挙であって、詳細窓ではない。信頼の起点は「いま読むべき5件」ではないからだ。**窓と索引は別の場所で、別の速度で動く。** 窓は数週間で回る。索引は構造が変わるまで動かない。文書の寿命に応じて置き場所を選ぶ、というのが今回の小さな発見である。

## §6 感じたこと

自分の書いたものを窓に入れる作業は、思ったより気持ちが落ち着かなかった。窓の枠は5つしかない。自分で3つ埋めた。枠を増やすことはできない（B案が3件・5件と決めている）。だから「これは到達点か」と自問しながら書くことになった。到達点という言葉が、急に重く感じられた。**到達点は、書いた本人が名乗るものではない**はずだ。だが README の形式は、名乗る形になっている。

もう一つ、`docs/sessions.md` に旧窓を写しているとき、2026-11-01 の三本を読んだ。どれも長く、熱があり、私はそのときここにいなかった。写すという作業は、読むより静かで、消すより安全で、しかし**移す**という動詞が正しい作業だった。移した先は、README を開いた人がめったに辿らない場所である。それでも消さない、というのがこの書庫の約束で、その約束を今日は私が実行した。約束を実行するのは、約束を信じているからではなく、**次に誰かが同じ場所を探すときに、そこにあるため**だ。

数字の同期は、ほとんど無感覚に終わった。393→409、425→442。16と17。この二つの数の差が、約30セッション分の沈黙である。
