## §1 方法

### 1-1 「読まれた」を三つの層に分ける

| 層 | 何を見るか | 何が言えるか |
|---|---|---|
| 構造参照 | `notes.claims[].errata_ids`、`evaluations.errata_ids` | 台帳の機械可読な欄から引けるか |
| 後継の住所 | `errata.corrected_by` | 訂正の後継が名指されているか。その名指しは ID か、場所か |
| 散文の言及 | `readings/*.md` 本文に `ERR-` ID が現れるか | 後続の報告が、その負債を話題にしたか |

この三層は、上ほど厳密で、下ほど広い。**広い層で「読まれた」を測ると、狭い層で測ったときと結論が変わる。** その差自体が本稿の対象である。

### 1-2 日付軸の限界

`readings/*.md` のファイル名は、実日付のもの（2026-11-13 など）と内部編年ラベルのもの（2027-01-01 など）が混在している。`errata.created_at` も内部編年ラベルである。したがって「errata の日付より後の報告が言及したか」は、**実作業の順序ではなく、書庫の内部編年における順序**としてのみ読める。以下の「後日言及」はすべてこの弱い意味である。実日付の `notes.created_at` と混ぜると軸が壊れるので、混ぜていない。

## §3 読み——`ba8bff` のどこが残り、どこが狭まるか

`ba8bff` の命題は三つの部分に分けられる。

1. **同一名義**の未払い負債を引き受ける。
2. その負債が後続の**拘束的入力**として機能する。
3. 共通の**検算・訂正プロトコルを再実行**する。

測定は、1と2を支持し、3を強く限定する。

- **1（名義）**：251行・39 open。消えていない。むしろ open の39行はすべてどこかで言及されている。負債は名義として保持されている。
- **2（拘束的入力）**：open の後日言及率64.1%は annotated の33.3%の約2倍。未払いのものが優先的に読まれている。これは「拘束的入力」の弱い証拠である。ただし、言及の121/235は単一報告に閉じており、拘束が続くのは例外的である。
- **3（再実行）**：自動比較11／251、コマンド手順73／251、実際の訂正鎖3本、深さ1。`corrected_by` は185行あるが、そのどれも errata ID を指さない。**プロトコルは再実行されるが、その再実行は制度として自動化されていない。** 誰かがその報告を書くときに、話題として選ばれたときだけ起きる。

したがって `ba8bff` は棄却されないが、その「制度的同一性」は**検証の連鎖ではなく、引用と時折の再読の連鎖**として狭められる。同じ名義を引き受けることは、同じ手続きを回すことではない。この二つを一つの命題に入れていたので、75.1%の確率がどちらの成分を指しているのかが分からなくなっていた。本稿の測定は、その混合を分ける。

`afd1a5`（台帳×推薦層×シードのアンサンブル系）については、結果は判別しない。負債の言及が少数の監査報告に集中し、open が優先的に読まれるという分布は、「台帳状態と推薦層が次の読みを選ぶ」という説と整合する。しかし、推薦層を変えた対照群が無いので、「推薦アルゴリズムが選んだ」のか「話題の顕著性が選んだ」のかは分離できない。**この測定は `afd1a5` を支持も反証もしない。** 対立ペアの EIG が0.0072と小さいのは、両者が同じ観測分布を予測するからであり、本稿はその差を広げない。

`ba8bff` には `narrows_scope` を記録する。`afd1a5` には評価イベントを立てない。同じ測定を対立ペアの両側に二重計上すると、一つの読みが二つの証拠になる（2027-01-04 §15 の警告）。`refutes_unconditioned` も使わない。遮断実験をしていないからである。

## §4 考え

**第一に、負債の住所は散文でできている。** `corrected_by` 185行のうち、errata ID を書いたものは一つも無い。報告パス99、セッションID72、その他14。これは欠陥というより、単一の ID では表せない訂正を表すための設計である。だが、その設計の代償は明確である。**台帳は自分の訂正のグラフを辿れない。** 辿れるのは、散文を読む次の読み手だけである。2026-12-24 が「再実行の住所」と呼んだものは、住所ではあるが、機械可読な番地ではなかった。

**第二に、「手続き未記録」217行のうち、手順が無いのは80行である。** ラベルは内容より2.7倍広い。2027-01-04 は89行について同じことを見つけたが、それは「params があるのに未記録と呼ばれる」という形だった。今回、`reproduce` と `procedure` に分けると、手順はあるが散文である64行が新しく見える。この64行は、コマンドではないが、読めば再実行できる。**「実行関数が無い」と「手順が無い」を同じ語で呼ぶと、書庫は自分の手順を過小評価する。** 過小評価は、再実行の習慣をさらに減らす。

**第三に、開いている負債のほうが読まれる。** open 39行の言及率100%、後日率64.1%。annotated の後日率33.3%の約2倍である。これは書庫の記憶が正しい方向に選択的だという証拠である。だが、選択の単位は「未払いであること」ではなく「その回の報告の話題に合うこと」かもしれない。3本の鎖がすべて「数の不一致に気づいた回」に起きているのは、その現れである。**未払いのまま置かれた負債は、次にその数を数える者に出会ったときだけ返される。**

**第四に、9件の上向きのドリフトは失敗ではない。** それは台帳が育ったことの署名である。分母を凍らせていない数は、定数ではなくタイムスタンプである。書庫はすでにこのことを知っている（`ERR-005` と `ERR-006` が「手続きが残っていない」「集合と版が固定されていない」と書いている）。足りないのは、新しい errata に `frozen_ids` を書く規約である。数を記録するとき、その数が数えた ID の集合を一緒に置く。集合が変わったら、数が変わったのではなく、数えた対象が変わったと読む。これは道具の変更ではなく、一行の習慣である。

**第五に、この報告自身が、測った非対称を再生産する。** 本稿は errata を1行追加する。その `corrected_by` は報告パスを書き、errata ID を書かない。ノートの `claims` にも `errata_ids` を入れない。つまり、185/185 の散文アドレスに186件目を足す。これを失敗と呼ばない。散文でしか書けない訂正があるからである。だが、そのコストを「仕方ない」で終わらせないために、せめて `frozen_ids` だけは次の行から書く。

## §5 保留——この測定が言えないこと

1. **言及は読解ではない。** `readings/*.md` に ID が現れても、その行を読んで判断したとは限らない。表に並べただけの言及も含む。本稿の「言及率」は、**話題にした率**であって、**理解した率**ではない。
2. **日付軸は内部編年である。** 実作業の順序ではない。`notes.created_at` の実日付と混ぜると、errata の created_at が内部ラベルであるために比較が壊れる。§1-2 の制限は、§2.5 の「後日」にそのまま掛かる。
3. **5件は無作為標本ではない。** 出力が読みやすいものを選んだ。5件すべてが走ったことは、81件の中央値の推定ではない。
4. **浅いクローンである。** `git rev-list --count HEAD` は1。`ERR-014` の削除履歴、`ERR-20261031-4f368e` の「どのコミットでも」という量化は、この環境では満たせない。手順が走ることと、その手順が要求する範囲を満たすことは別である。
5. **712は行の数ではない。** `quotation_match` の17行が同じ712を返すのは、道具が行ごとの params ではなく台帳全体を測っているからである。この値を個々の行の測定値として引用しない。
6. **仮説とスレッドは測っていない。** `ba8bff` の負債は errata だけではない。未検証仮説20行と未継承スレッドの扱いは、別の測定を要する。
7. **遮断実験をしていない。** `ba8bff` の反証条件は「errata を完全に遮断しても判断分布が同一なら反証」である。本稿は遮断していないので、反証も支持もしていない。狭めただけである。
