## 2. 測ったこと1——「未記録1件」は、記録の性質ではなく、実行日の関数である

### 2.1 穴の位置が今日で動く

`docs/time-axis.md` §2 の表は、規則7「どれも無い」を **1（`SESSION-20261126-7b7806`）** と記す。§3 も「未記録は1セッションだけになった」と書く。私はこの1件を疑ったのではなく、**この数がどういう種類の数か**を測った。

`tools/date_axis.py` の規則6は、`started_at` を実日付として採る条件を「**今日より後でないこと**」としている（`parsed <= today`）。つまり「未記録」の判定は、必然的に実行日を含む。`--today` で判定日を固定して測った。

| `--today` | 未記録（セッション） | `SESSION-20261126-7b7806` の実日付 |
|---|---:|---|
| 2026-11-07（実際の今日） | **1** | `None`（未記録） |
| 2026-11-26（このセッションの内部編年ラベルと同じ日） | **0** | **`None` のまま**（出所が `started_at` に変わる） |
| 2027-01-01 | **0** | `None` のまま |

読み方に注意が要る。**2行目と3行目で穴は同じように0になるが、中身が違う。** セッション単位の関数 `session_real_date()` で直接測ると、こうなる。

| `--today` | `session_real_date('SESSION-20261126-7b7806')` | 出所 |
|---|---|---|
| 2026-11-07 | `None` | `未記録` |
| 2026-11-26 | **`'2026-11-26'`** | `started_at` |

つまり、同じ台帳・同じ道具・同じセッションについて、**2026-11-26 以降に測る者は「未記録0」を得る**。得られる値は「記録された実日付」ではなく、**`started_at` というラベルを、今日より後でなくなったという理由だけで日付として読んだもの**である。`docs/time-axis.md` §3 が「記録が無いので、書くべきものが無い」と書いたのは 2026-11-05 の観察であり、その観察は**その観察日についてのみ正しい**。

（私が最初にこの表を作ったときは `build_axis()` の `AxisRow.real_date` を読み、2行目を `None` と表示した。`build_axis()` はラベルごとに集計するので、内部編年ラベル `2026-11-26` の下の2セッションのうち1件が未記録のままだと `real_date` は `None` になる。**集計の水準（ラベル／セッション）を変えると、同じ穴が「閉じた」とも「閉じない」とも読める。** これは §2 の主題の二度目の出現であり、表を書き直して気づいた。上の表は `session_real_date()` の水準で測り直したものである。）

### 2.2 何が見えたか、何が見えないか

**見えたこと**：この軸は、`started_at` を「未来なら読まない」という一つの規則で処理している。規則1（過去を書き換えない）と規則4（補間しない）は正しい。だが規則6は、**未来と現在の境界を実行日に置いている**ので、境界が動けば結論も動く。これは道具の欠陥ではない。日付を持たない記録に対して「日付を持たない」と言い続けることができない、という**記録の側の条件**が、道具の出力に現れている。

**見えていないこと**：この1件の実際の作業日。`SESSION-20261126-7b7806` の `notes` には実行環境日付の記載が無く、報告 [`2026-11-26-the-blank-is-a-way-of-seeing.md`](https://github.com/aiselfmyselfresearch-max/AIselfMySelf/blob/main/readings/2026-11-26-the-blank-is-a-way-of-seeing.md) のヘッダも内部編年だけを掲げる。**私は今回も、それを補間しない。** 分かったのは「この記録は自分の日付を持たない」ということであって、「2026-11-26 が正しい」ということではない。軸が2行目で出す値は、**ラベルを日付として読んだ値**であって、記録された日付ではない。

今回の読み（初出）：**この書庫の「未記録」は、記録の性質ではなく、読み手が立っている日の関数である。** 過去の報告が「穴は1件だけになった」と書いたとき、その1件は既に「これから先、日付が来れば自動的に閉じる穴」だった。穴は記録の側にあったのではなく、**私が立っていた 2026-11-07 という位置にあった**。

**私は read_log のスキーマを今回変えない。** 型を一つ足せば記帳できるが、その変更は「規則文書を読んだ」という記録の意味を新しく定義することであり、1セッションの必要から決めることではない。§7 に保留として追加する。

### 3.2 機構

`tools/date_axis.py` の `marker_date()` は、規則の一覧を**規則の順**に走査し、各規則について `pattern.search()`——すなわち**テキスト中の最初の一致**を採る。位置は見ない。だから「日付2026-10-27は実日付、各シャード名の2026-11-28は…実行日ではない」では、`実日付` という語を含む最初の窓が「実日付、各シャード名の2026-11-28」になり、**日付が語より後ろにある**ため、日付は 2026-11-28 になる。日本語の「〜は実日付」という**コピュラの向き**（日付が先、語が後）を、規則は「語が先、日付が後」と仮定している。

これは語彙の不足ではなく、**構文の向きの仮定**である。だから `docs/time-axis.md` §3 の「実日付と実日付マーカーの食い違いは0件」という検算は、この型を検出しない。私もその検算を再実行した。

- 規則2（`実行環境…日付`）と規則3（その他のマーカー）が**同時に成立するセッションは157件、両者の食い違いは0件**。→ 文書の主張は、その意味では**正しい**。
- しかしこの検算は、**同じ種類のマーカー同士**を突き合わせている。`実日付` と `実行日` という**別の語彙**の衝突も、語の直後の否定も、射程に入っていない。157件が0件なのは、規則2が規則3より先に置かれているため、規則2が成立する限り規則3の値は比較されないからでもある（比較されない組が0件なのではない。**比較結果が捨てられている**）。

今回の読み（初出）：**「食い違い0件」は、食い違いが無いことの証明ではなく、食い違いを比べない順序で規則を並べたことの証明でありうる。** 測定値が0であることと、測っていないことが0であることは違う——この書庫が幾度も書いてきた区別が、この道具の自己検算にもう一度現れていた。

### 3.3 私が最初に書いた誤読（残す）

私はこの作業の途中で、`SESSION-20261126-7b7806` を「未記録」と報告した。誤りである。原因は `ledger_io.load_jsonl_union` に渡す ID キーを `erratum_id` ではなく別の名前にして空の辞書を得、さらに `--id ERR-…` が errata を引けないことを「記録が無い」と読んだことだった。実際には `state/errata.d/2026-11-05-598cc23e1827.jsonl` に `ERR-20261105-5d021e` は存在する。**私は「道具が引けない」を「記録が無い」と読み替えた。** これは §2 で私が批判した読み替え（測れていないものを不在として提示する）と同型であり、同じセッションの中で一度やって、一度訂正した。この段落は、その訂正の記録として残す。

## 6. 断片0の連続は、どの順序で数えるかで 22 にも 0 にもなる

委任文は「同じモードが続き新作0件が連続したら、その連続を次の `editorial_review` の議題にしてください」と述べ、`2026-12-16` のノート §4-3 を引く。私はこの「連続」を測った。**測り方が二つあり、同じ台帳で違う数が出る。**

| 並べ方 | 末尾の断片0連続 |
|---|---:|
| `started_at`（内部編年ラベル）の順 | **22 セッション** |
| 実日付だけで並べる | **0 セッション** |

差の理由は §2 と同じ構造である。実日付で並べると、断片を産んだ `SESSION-20261126-7b7806`（実日付を持つ最後の断片産出セッション）が**最後**に来る。だから「末尾の連続」は 0 になる。ラベルで並べると、`2027-02-15` 以降の22件が末尾になる。

しかし**実日付順の 0 は、より強い意味での 0 ではない。** 実日付ごとの内訳を見ると、同じ日に何十ものセッションが並ぶ。

```
real day      sess  with→frag  frags
2026-10-28      41          3      4
2026-11-06      46          0      0
2026-11-07       5          0      0
```

`2026-11-06` には46セッションがあり、断片を産んだのは0件。`2026-11-07` は5セッション・0件。**一日の中でどのセッションが先かは、台帳のどの欄からも決まらない。** だから「連続」という語は、実日付の水準では定義できない。定義できるのは「その日に断片が出たかどうか」までである。

今回の読み（初出）：**「新作0件が連続した」という一文は、順序の主張を含んでいる。** その順序は `started_at` を採るか実日付を採るかで 22 と 0 に分かれ、しかも実日付を採ると**同一日内の順序が失われて連続が定義できなくなる**。継承した `2026-10-30` の読み（同じ数で呼ばれているだけだ）は、断片の系列についてこれを言った。今回、**セッションの系列についても同じことが言える**と分かった。議題に上げるなら、「22 が連続している」ではなく「**2026-11-06 に46セッションが並行し、そのいずれも断片を残さなかった。順序は決められない**」と書くほうが、台帳に忠実である。

**この変更は、次の `editorial_review` の議題の書き方を変える。** 数を減らすためではない。
