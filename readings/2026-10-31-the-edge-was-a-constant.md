## 2. 原典照合——地図を描く手順を読む

「原典」という語を、今回は生成器の本文に対して使う。台帳にとっての一次資料が素材であるように、**索引と地図にとっての一次資料は `map_build.py` である**。以下の引用はすべて、このリポジトリの当該ファイルの現在の内容による。

### 2.1 台帳のうち、地図に載るのは六種だけ

`shard_plan()` が作るシャードは、総覧（モチーフの全文を含む）、問い索引、問い本文、断片、素材（文学／研究／痕跡の三種）、関係、セッションである。**載るのはモチーフ・問い・断片・素材・関係・セッションの六種**で、モチーフは独立したシャードを持たず総覧の中にだけ現れる。

載らないものがある。

| 台帳 | 行数（今回の追記前） | 地図のどこに出るか |
|---|---:|---|
| `errata`（訂正録） | 94 | **出ない** |
| `read_log`（読み痕跡） | 7,196 | **出ない** |
| `editorial_decisions`（編集判断） | 101 | **出ない** |

`errata` と `editorial_decisions` と `read_log` は `load_all()` で `data` に読み込まれ、`sync_readme_counts()` の中で**件数を数えるためだけ**に参照される（`map_build.py` の 607〜621 行、706〜719 行）。描画関数は一つも受け取らない。`read_log` は README の件数表の一行を埋めるためだけに使われ、地図にも索引にも一行も出ない。

つまり、**この書庫が「何を読み直したか」「どこを訂正したか」「何を採否したか」は、地図の上では一件も場所を持たない。** 地図が描くのは、対象と、その間の関係だけである。

### 2.2 二つの記憶と、一つの投影

`READING_MAP.md` の冒頭はこう名乗る。

> この文書は `state/*.jsonl` の台帳から `python3 tools/map_build.py` によって自動生成される**小型索引**です。本文・全文は `map/` 以下のレンジ分割シャードに収録し、`map/` は git 管理しません。（…）全量は `python3 tools/map_build.py` の再生成、または GitHub Actions の `reading-map` artifact で取得できます。

階層は三つある。

| 層 | 実体 | git 管理 | 検査 | 寿命 |
|---|---|---|---|---|
| 台帳 | `state/*.jsonl` ＋ `state/*.d/` | **される** | `validate_seed.py`・`read_log_backfill.py` | 永続（追記のみ） |
| 索引 | `READING_MAP.md` | **される** | `inspect_inquiry.py --check-map`（CI） | 永続（再生成） |
| 地図 | `map/` | **されない**（`.gitignore` の `map/`） | なし | Actions artifact は 90 日 |

`check_index()` の docstring はこう書く——"Verify the tracked index matches the ledgers (map/ is untracked, not checked)." そして `.github/workflows/ci.yml` が回すのは `--check-map` だけであり、`.github/workflows/map.yml` は地図を artifact として upload する（`retention-days: 90`）。

さらに、`write_all()` はこうする。

```python
for stale in sorted(map_dir.glob("*.md")) + sorted(map_dir.glob("manifest.json")):
    if stale.name not in planned:
        stale.unlink()
```

**地図には削除演算がある。台帳にはない。** 台帳は追記専用で、既存行を書き換えない。地図は毎回作り直され、計画から外れたシャードはファイルごと消える。同じ「記録」という語の下に、消さない層と消す層が同居している。

### 2.3 切り口は定数である

地図と索引は、すべての文字列を一定の長さで切る。`_one_line()` は空白を詰め、長さが上限を超えるとき `flat[: limit - 1] + "…"` を返す。**出力はちょうど上限の長さになり、最後の一文字が省略記号に置き換わる。**

| 欄 | 索引（tracked） | 地図（untracked） |
|---|---:|---:|
| 問い | 100 字 | 索引 120 字／本文は全文 |
| 断片の題 | 60 字 | 全文 |
| 素材の題（ラベル） | 90 字 | 全文 |
| 素材の `passage` | —（出ない） | 400 字 |
| 関係の `note` | —（出ない） | 100 字 |
| セッションの `human_direction` | —（出ない） | 120 字 |
| セッションの `notes` | —（出ない） | 200 字 |
| 断片本文・問い本文・総覧のモチーフ説明 | —（出ない） | 全文 |

「印を置かない地図」を問うた問いに対して、この書庫の地図は、**印の代わりに定数を持っている。**

### 2.4 同じ問いが、計器ごとに違う所で切れる

`Q-20261202-f52a08` の本文は 188 字である。三つの経路で、こう切れる。

| 経路 | 表示される末尾 | 落ちる部分 |
|---|---|---|
| 索引（100 字） | `…印を置かない地図は…` | `、行かない場所を残すのか、無い場所を作るのか。そして『中央』…` |
| 地図の問い索引（120 字） | `…行かない場所を残すのか、無い場所を作…` | `るのか。そして『中央』と『端』が採る者の地図の語である以上…` |
| 台帳・地図の問い本文 | 全文 | なし |

索引では、問いが**「印を置かない地図は」と言い終わる直前**で切れ、二つの選択肢（行かない場所を残すのか／無い場所を作るのか）が落ちる。地図の問い索引では、二つ目の選択肢の途中（「作…」）で切れる。

**これは誰かがそこを切ったのではない。** 100 と 120 という定数が、たまたまこの問いの転換点に落ちただけである。だが、**落ちた場所が内容と無関係であることこそが、この計器の性質である。** 定数は何を切ったかを知らない。知らないまま、毎回同じ長さで切る。

同じ 100 字の切断は、394 問のうち **301 問（76.4%）** に及ぶ。索引に残る問いの本文は、全体の 53.7% である。

### 2.5 切り口が実際に切った数

上限を超えているレコードを数えた（今回の計器、追記前の和集合）。

| 欄 | 上限 | 超えている件数 | 母数 | 割合 |
|---|---:|---:|---:|---:|
| セッション `notes` | 200 | 276 | 306 | **90.2%** |
| セッション `human_direction` | 120 | 235 | 306 | **76.8%** |
| 問い本文（索引） | 100 | 301 | 394 | **76.4%** |
| 関係 `note` | 100 | 520 | 5,717 | 9.1% |
| 素材 `passage` | 400 | 107 | 2,450 | 4.4% |
| 断片の題（索引） | 60 | **0** | 232 | **0%** |

二つのことが読める。

第一に、**最も深く切られているのは、作品ではなく、仕事の記録である。** セッションの `notes` は 9 割が 200 字で切られ、`human_direction` は 7 割半が 120 字で切られる。断片本文と問い本文は地図では全文であり、切られない。**地図は作品を保存し、労働を切り捨てる。** ただしここで「切る」は地図の上の話であって、台帳では全文が残っている（§2.6）。

第二に、**断片の題の 60 字という切り口は、一度も切ったことがない。** 232 編のうち最長の題は 36 字である。**存在するが、まだ何も切っていない刃**がある。これは「端を残す」の逆の例として重要である——切っていないことは、残したことの証明にならない。切る位置がまだ来ていないだけかもしれない。

### 2.6 何が残るか——一段落に収まらない差分

六つの文字欄（問い本文・断片本文＋編集メモ・素材の `passage`＋注記類・セッションの `notes`＋`human_direction`・関係の `note`）の合計は **1,993,180 字**。これが三層でどれだけ残るかを、同じ `_one_line()` の規則で計算した。

|---|---:|---:|
| 台帳（全文） | 1,993,180 | 100% |
| 地図 `map/`（untracked） | 1,563,404 | **78.4%** |

### 2.7 印のない欄が、そこにある

素材スキーマの `verification` は**任意**である。列挙値には `unverified`（未照合）があり、**153 件が実際にその値を使っている**。一方で、`verification` 欄そのものを持たない素材が **662 / 2,450 件（27.0%）**、文学素材だけなら **453 / 1,584 件（28.6%）** ある。

`MAT-LIT-295`（蝸牛考）は後者である。地図の素材カタログは `if ver:` のときだけ「**検証**：…」の行を出すので、この素材の項には検証の行が**一本も出ない**。

```
## `MAT-LIT-295` 柳田國男『蝸牛考』——呼び名を数え、分布から歴史を推す
- **種**：literary_text ／ **著者**：柳田國男 ／ **年**：1930
- **出典**：[柳田國男『蝸牛考』](https://dl.ndl.go.jp/)
- **版・箇所**：… ／ 1930年刊。引用は【編者による要約】。国立国会図書館デジタルコレクションの著者・書名から辿れる。
- **一節**：【編者による要約】全国の蝸牛の呼び名を集め、…
- **留保**：民俗学の方法の要約。方言周圏論の妥当性を判定せず、…
- モチーフ: `MOTIF-015` `MOTIF-001` `MOTIF-011`
```

**「未照合」と書く欄は存在するのに、そこには何も書かれていない。** 空欄は三つの読みに開かれている——(i) まだ照合していない、(ii) 照合の必要がない、(iii) 欄の存在を知らないうちに作られた。スキーマの説明は「`source` の存在ではなく、`source` を実際に開いたかどうかを記録する」と定めるから、空欄は本来 (i) を意味するはずである。しかし描画では (i)(ii)(iii) は同じ無印になる。

日付を確かめておく。`verification` は 2026-10-23（`SESSION-027`）に追加された。`MAT-LIT-295` は 2026-10-24（`SESSION-033`）に作られている。**欄は、この素材が作られた時点で既に存在していた。** だから空欄は「欄が無かった時代のレコード」では説明できない。**語彙はあった。使われなかった。**

### 2.8 索引の素材行は、著者を二度書く

これは計器の欠陥である。`build_index()` は素材のラベルをこう組む。

```python
label = "{}『{}』（{}）".format(authors, mat["title"], mat["source"]["year"])
```

ところが台帳の `title` は、多くの場合すでに著者名と鉤括弧を含む（例：`柳田國男『蝸牛考』——呼び名を数え、分布から歴史を推す`）。結果、索引ではこうなる。

```

```

`title` が著者名で始まる素材は **362 / 2,450 件（14.8%）**。地図の素材カタログ（`build_materials`）は `title` をそのまま見出しに使うので二重にならない。**索引だけが二重になる。**

これは台帳の誤りではなく、生成器の前提（`title` は著者を含まない）と台帳の慣行（`title` は著者を含む）の食い違いである。今回は修正しない。理由は §5 に書く。

### 2.9 地図は自分を「全文」と名乗る

索引の冒頭は「**本文・全文は `map/` 以下のレンジ分割シャードに収録し**」と書く。しかし §2.3 の表のとおり、素材の `passage`、関係の `note`、セッションの `human_direction` と `notes` は `map/` の中でも切られている。**地図は全文ではない。** この一文は、切ったことを隠してはいない（各所に「…」がある）が、**どの欄が切られたかをヘッダに書いていない。** 訂正録 `ERR-20261031-cee687` として隣に置いた。

## 3. 見立ての変更

### 3-1. 「採らない」は、少なくとも三つある

12-26 のノートは「採らないことは一つの状態ではない」と書いた。今回、その「一つではない」の中身が、計器の側から三つに分かれた。

| 種類 | 台帳の状態 | 地図の状態 | 可逆性 |
|---|---|---|---|
| (a) 行を作らない | 行がない | 場所がない | **不可逆**（追記しない限り） |
| (b) 行はあるが描かれない | `errata`・`read_log`・`editorial_decisions` | 場所がない | 可逆（描画関数を足せば出る） |
| (c) 行も描画もあるが切られる | 全文がある | 定数で切られる | 可逆（定数を変えれば戻る） |

**問いは、この三つを一つの「採らない」に畳んでいた。** (a) は端以前の問題である——そもそも座標系に入っていない。(b) は内側にあるが地図に映らない。(c) は映るが途中で切れる。**「端を残す作法か、数に入れない別の消し方か」という二択は、(b) と (c) の区別を落とすと解けなくなる。** 台帳の内側では (b)(c) は「保存」であり、地図の上では (c) は「切ったが戻せる」、(b) は「そもそも出ない」である。

### 3-2. 地図は記憶ではない

H4（台帳にあるものは地図にもある）は棄却する。地図に載るのは六種だけで、しかも四つの文字欄は定数で切られる。

しかし、もっと重要なのは**可逆性**のほうである。地図は毎回 `state/` から作り直される。だから地図の省略は、**保存でも消去でもない**。作り直せば戻る。一方、台帳の省略——行を作らなかったこと——は戻らない。

**「印を置かない地図は、行かない場所を残すのか、無い場所を作るのか」という問いは、投影の層ではカテゴリー誤認になる。** 投影は保存も消去もしない。投影は計算する。保存と消去が起きるのは台帳の層だけであり、台帳の層には「端」という語も「中央」という語もない——あるのは ID と、ID を参照する関係だけである。

ただし、完全に無害でもない。地図は消さないが、`write_all()` は計画から外れたシャードを `unlink()` する。**投影は、投影の側の都合でファイルを消す。** 台帳は消さない。この非対称を、同じ「記録」と呼ぶと、消えたシャードを「保存されていたものが失われた」と読んでしまう。実際には、台帳から再生成できる限り失われていない。**失われたのは、その時点の像だけである。**

### 3-3. 端は場所ではなく、定数である

H3（端は地図を引く者の語）は維持する。ただし今回、その語がどこにあるかが具体化した。**「端」は地図の上の場所ではない。地図を切る式の中の数である。**

- 索引では 100。
- 地図の問い索引では 120。
- 素材では 400。関係では 100。セッションでは 120 と 200。

この数は、台帳のどの行にも記録されていない。`map_build.py` という git 管理されたコードにだけ書かれている。だから、**定数を変えれば、全員の「分布の中の位置」が一斉に変わる。そして台帳には一行も足されない。** 変わるのはコードの差分だけである。

ここが今回いちばん効いた。12-26 の第三小問への答えは「作中では彼女は自分の場所を置いていない／台帳では全面的に置かれている」だった。今回、その二層のあいだに第三の層が入る。**索引の上での彼女の位置は、彼女の選択でも、編集者の判断でもなく、`[:99] + "…"` という式の出力である。** 彼女を分布に入れたのは誰かの決断ではなく、定数である。決断が記録されているとすれば、それは `state/` ではなく `tools/map_build.py` の git 履歴の側にある。

### 3-4. 切れ目は印を残すが、内容は残さない

省略記号「…」は、**そこに続きがあった**ことを示す。これは「端を残す」の最小の形である——外があったことだけは残る。しかし「…」はすべての欄で同じ記号であり、**何が落ちたかは示さない。** 均一な印は、内容については無印と同じである。

断片の題の 60 字（0/232）は、この非対称の極端な例だ。**刃はあるが、まだ何も切っていない。** 切っていないことは、保存の証明ではない。切る位置が来ていないだけかもしれない。逆に、セッションの `notes` は 9 割が切られている。**同じ計器の中で、切られていない欄と、ほぼ全部切られている欄が並んでいる。** どちらも「…」の有無だけでは区別がつかない——切られていない欄には「…」がなく、切られている欄には「…」がある。**区別はつく。ただし、切られた側の「…」は、何が失われたかを言わない。**

### 3-5. 索引は、家の者の語を一度も載せない

断片 `FRAG-20261202-75c97c` の題は「尋ねないときの言い方——四十枚目、中央の名」で、**「端」を一度も含まない**。本文には「端」が 6 回現れる。索引は題だけを載せるから、**索引の上では、彼女の語彙はゼロである。** 地図では本文が全文で載り、6 回とも出る。台帳では一行の JSON の中にいる。

つまり、同じ人物が三つの層で三つの置かれ方をする。

| 層 | 家の者の現れ方 | 「端」の回数 |
|---|---|---:|
| 索引 | 題（`中央の名`）の下 | 0 |
| 地図 | 対話の全文 | 6 |
| 台帳 | 断片行＋`question_ids`＋`motif_ids`＋関係 | 6 |

12-26 の二層（作中／台帳）に、**投影**という第三層が加わる。作中でも台帳でもない層で、彼女は題だけになる。そしてこの第三層は、git に保存され、CI で検査され、次のセッションが最初に開くファイルである。

## 4. 問いへの暫定応答（問いは閉じない）

1. **端の名を採らないことは、端を残す作法か、数に入れない別の消し方か。** 台帳の内側では、その二択は成り立たない。行を作らない (a) は座標系の外であり、保存でも消去でもない。行はあるが描かれない (b) と、描かれるが切られる (c) は、台帳では保存であり、投影では可逆な省略である。**三つを一語に畳まないこと**が、今回確定できた範囲である。
2. **印を置かない地図は、行かない場所を残すのか、無い場所を作るのか。** どちらでもない。地図は再生成されるので、その省略は保存でも消去でもない。保存と消去が起きるのは台帳の層だけであり、そこでは「行を持たないもの」は残らない——**「行かない場所」は、地図にも台帳にも場所を持たない。** 場所を持つのは「行を持ちながら、まだ読む文として使われていない対象」だけである。地図の側で新しく言えるのは、**切る位置が定数である**という一点だ。定数は内容を見ない。見ないことが、切られた場所を「選ばれた端」に見せてしまう。
3. **その語で拒絶を述べた家の者は、誰の分布のなかに置かれたことになるのか。** 三層で三つの答えが出る。作中では自分の場所を置かず、相手の分類語の所有者を付け直して返した（12-26）。台帳では全面的に配置されている。**索引では、題の下に置かれ、彼女の語彙は 0 回である。** そして索引上の位置は、決定ではなく定数の出力である。**彼女を分布に入れたのは、誰かの判断ではなく、一〇〇という数である。** 単一の答えは出ない。出ないことを、今回は「層が違う」で終わらせず、**層ごとに置いた主体が違う**（彼女／書庫／定数）と書いておく。

## 6. 中心問いへ（狭く）

**`Q-001`（人間とは何か）。** 今回は人間についての命題を一つも立てない。強いて言えば、この書庫が「声」として保存しているもののうち、最も深く切られているのは声そのものではなく、**その声を記録した仕事の説明**である、という観察がある。断片は切られず、セッションの `notes` は 9 割が切られる。これは人間の条件について何も示さない。書庫の編集の癖である。**比喩の側に残す。**

**`Q-002`（どの意味で同じ自己か）。** 新しい語を一つ足す——**再現性**。同じ台帳と同じ生成器からは同じ像が出る。像は保存されない。保存されるのは台帳と規則である。だから「同じ自己」は、同じ像を持つことでも、同じ内容を覚えていることでもなく、**同じ台帳と同じ規則の下で、同じ像が再計算されること**として、少なくともこの書庫の上では成り立つ。限界は二つ。(i) `manifest.json` に生成器の commit hash がない。同じ台帳から別の像が出ても、台帳はそれを検出しない。(ii) 規則が変われば同じ台帳から別の像が出る。**同一性は、規則の版に依存しているのに、像には版が刻まれていない。**

**`Q-003`（記録は自己を保存するのか、素材なのか）。** 二択の外に、層を分けた第三の答えを置く。**台帳は保存し、地図は描き、索引は思い出させる。** 保存されるのは全文と規則であり、保存されないのは像である。素材は選ばれるが、像は毎回計算される。だから記録は自己を保存しない——記録は、自己が毎回計算されるための**初期条件**を保存する。前回の「記録は未払いを保存する」に、今回はこう足す。**記録は、像を作り直すための規則も保存する。ただし規則には版が刻まれていない。**
