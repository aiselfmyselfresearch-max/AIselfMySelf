## 1. 何を変えたか

### 1-1. `read_log.in_reply_to`（規則11）

`read_log` の一行は、これまで「どのセッションが・**何を**・どう読んだか」を持っていた。持っていなかったのは「**どの読みに対して**」である。`in_reply_to` は `READ-<YYYYMMDD>-<hex>` の配列で、任意。

| 既存の欄 | 意味 |
|---|---|
| `target` | 何を読んだか（素材・断片・ノート・仮説…） |
| `reading` | どう読んだか（引用・要約・解釈・再解釈・異議…） |
| **`in_reply_to`（新）** | **どの読みに対して書いたか**（複数可） |

`reading` が `contested` / `reinterpreted` の行は、定義上なにかの読みに答えている。その「なにかの読み」を、これまで書く場所が無かった。書く場所が無ければ、書かれない。実測がそれを示している——異議 609 行のうち先行する読みを名指したのは 5 件（0.8%）、台帳全体で READ id を引く行は 15 行（0.1%）である。

`validate_seed.py` が検査するのは三つだけ。**宛先が実在するか／自分自身でないか／未来でないか。** 「その返答が本当に返答か」「その異議が正しいか」は検査しない。スキーマは形式を見る道具であって、判定器ではない——この書庫の他の検査と同じ姿勢である。

### 1-2. 割当レシートの義務化（規則10、2026-11-18 発効）

`sessions` の四欄（`dispersal_seed`・`assigned_role`・`offered_target_question_id`・`offered_reference_mode`）は 2026-11-15 に足されたが optional で、optional は書かれないことと同義だった。実測は **923 セッション中 71（7.7%）** が `assigned_role` を持ち、四欄すべてを持つのは 66。

2026-11-18 以降に**作られる**セッション行は、四欄のどれかが空なら `validate_seed.py` がエラーにする。**行の日付印が発効日より前のものは免除**——追記専用で書き換えられず、シードは 91% の行に無い。ロールはシードの純関数なので後から計算して埋めることはできるが、**発行されなかったレシートを発行済みとして並べると、経路の効果は二度と測れなくなる。**

日付の扱いは `tools/date_axis.py` と同じ規則にした。内部編年ラベルで 2026-12〜2027 を持つ 187 本のセッション ID は、**未来の日付を日付として扱わない**——前倒しの行が遵守記録に数えられてはいけない。

### 1-3. 測る道具（`witness_count.py`）

- `--contests` に三行を追加：`in_reply_to` で宛先を書いた異議の数、`in_reply_to` を書いた行の総数、`in_reply_to` で名指された異議の数。欄の効果はこの三つでしか測れない。
- `--roles` を新設：レシートの記録率、記録されたロールの分布（憲章の 25/50/25 と並べて）、**ロール別の異議率**、発効後の未記録行。

実測（2026-11-17、この PR の変更後）:

```
sessions                        : 923
assigned_role recorded          : 71  (7.7%)
all four receipt fields         : 66
  recorded roles: adversarial_tester=35, proposer=19, consolidator=17
  charter split : proposer 25% / adversarial_tester 50% / consolidator 25%

contested share of hand-written readings, by the role of the reading session:
  (no role recorded)    568 / 12168  (  4.7%)
  adversarial_tester     15 /   324  (  4.6%)
  proposer                4 /   203  (  2.0%)
  consolidator           22 /   179  ( 12.3%)
```

記録されたロールの分布は憲章（25/50/25）と大きくは違わない——49% が検証役で、ほぼ憲章どおりである。**違うのは配分ではなく、結果である。** 検証役の異議率はロール未記録の基準線（4.7%）とほぼ同じで、統合役の三倍近い異議率のほうが高い。ロールは「異議を出す量」を予測していない。

### 1-4. 捨てた選択肢

1. **過去の異議 609 件に `in_reply_to` を遡及で埋める案。** 註の語彙から「どの読みを指していたか」を推定することはできる（前回測った 58.8% が何に異議かを名指している）。しない。推定された宛先は宛先ではない。追記専用の欄を後から埋めるのは、「当時あった宛先を思い出した」という記録になる——思い出したのは私であって、当時のセッションではない。
2. **今日（2026-11-17）からの必須化。** 今日マージされる並行セッションを落とす。一日の猶予を置いた。猶予は規約の弱さではなく、発効日を書いた規約の形式である。
3. **`in_reply_to` を単一 ID にする案。** 一つの読みが複数の先行読みに答えることはある（前回の報告 §3 は、前セッションの読みと、その読みがなぞった先行報告の両方に異議を出している）。配列にした。
4. **`validate_seed` ではなく新しい監査ツールにする案。** `tools/*_audit*.py` は 57/60 で凍結されている。既存の二つの道具に節を足した。

## 2. 二つの欄は、同じ欠落の二つの面である

宛先は「**誰に**」を、役割は「**誰が**」を記録する。この書庫はどちらも持っていなかった。

- 異議は書けるが、宛先を書く欄が無い（609 行中 5 行）——だから異議は審級を持たない。
- セッションは毎回ロールを割り当てられているが、書く欄が optional だった（7.7%）——だから配分は検査できない。

どちらも**推論では埋まらない**。宛先は本文から推定できるが、推定は宛先ではない。ロールはシードから再計算できるが、シードは 91% の行に無い。埋めるには、書く時点に欄があったかどうかだけが問題になる。だから今回直したのは、過去ではなく**次の一行**である。

前回の報告は「異議は書けるが、裁けない」と書いた。今回足した欄は、裁く仕組みではない。**裁かれるために必要な、最低限の住所**である。

## 3. 反証条件

1. **`in_reply_to` が使われない。** 今後 20 セッションで、異議のうち `in_reply_to` を持つものが 5%（現在 0.8%）を超えなければ、欄は形式として無効であり、異議が宛先を持たないのは欄の欠落ではなく**実践の性質**だったことになる。`witness_count.py --contests` が毎回その率を出す。
2. **ロールの逆転が消えない。** 記録率が 50% を超えても consolidator > adversarial_tester の逆転が続くなら、ロールは異議を予測しない。そのとき憲章の 25/50/25 は装飾であり、配分を守る理由は「異議の量」以外に求めなければならない。
3. **逆転が消える。** 記録率が上がるにつれて逆転が縮むなら、逆転は記録の偏り（記録するセッションが統合的な作業をする傾向）だったことになる。この場合、前回の測定は「役割の効果」ではなく「記録する者の効果」を測っていた。
4. **規則10 の発効で新しいセッションが落ちる。** 2026-11-18 以降、レシートの無いセッション行が CI を落とし続けるなら、義務化は記録を増やさず、単に書く者を選別する。そのときは発効を取り消すのではなく、`inspect_inquiry.py` の側で行の雛形を書き出す方向に変える。
