## §2 解釈——規則は「ラベル」を数え、「行為」を数えない

設計報告の中心は、層2 を「読んだ／読まなかった」の二値にしないことにある。読まなかったことを失敗にせず、`未読の選択:` として記録すれば充足とする。これによって、読書を強制せずに、接触した素材の扱いを可視化する。設計の意図は一貫している。

しかし、実装された規則には、設計が名指ししていない第四の状態がある。**`used_as_context` である。**

`read_log` の `reading` には、`quoted` / `summarized` / `interpreted` / `reinterpreted` / `contested` / `counted` の六つの手書き読みと、`used_as_context` がある。層2 は前者だけを数える。`used_as_context` は層1（接触）の証拠であって、層2（読書）の証拠ではない。設計はこの区別を正しく書いている。

問題は、`used_as_context` が**「読まなかった」とも「読んだ」とも言えない中間**を指すことだ。素材を文脈に置き、識別や射程限定に使ったが、全文は読んでいない。この状態は、現実の読書では最も多い。設計の P-2 は「開いた／開いていない」だけを要求するが、`used_as_context` は「開いたが読んだとは言わない」という第三の申告である。規則はこの申告を受け取る場所を持たない。

さらに、修復の場所にも問題がある。`未読の選択:` は `sessions.notes` に書く。`sessions` は追記専用で、一度書いた行は書き換えない。したがって、**セッションの行が書かれた後に `未読の選択:` を足すことはできない。** 設計の §8-8 の修復手順は、セッションがまだ書かれていない間だけ有効である。行が確定した後では、検査は未充足を検出できるが、直せない。

これは検査の不具合ではない。**検査の処方と台帳の不変性が食い違っている**のである。`errata` は「本文を書き換えず隣に足す」ことでこの問題を解くが、層2 の `未読の選択:` には、それに相当する追記先がない。

## §5 変更・維持・保留

### 変更したこと

- **`used_as_context` の読み方を変えた。** 以前は「接触の記録として弱いが許容できる」と読んでいた。今は「層2 が数えない第三の分類」と読む。29ペアは、行が無いのではなく、この分類に落ちている。
- **集計の読み方を変えた。** 96.9% を規則の成功率として読まない。セッション別に見ると、一つの大きな文脈が29/39を未充足にしている。平均は、その失敗を薄める。
- **`tools/layer2_accounting.py` を追加した。** セッション別の内訳、最初の10本、文脈サイズ、`context_only` と `unmet_without_row` の区別を出す。ゲートではなく鏡である。

### 維持したこと

- **`read_log` に `not_read` を足さない設計判断は維持する。** `read_log` は接触した素材を指す台帳であり、触れなかった素材をそこに書くと層1 の意味が壊れる。設計報告の P-3 は正しい。**（2026-11-14 追記：§5-2 で足した `declined` は、文脈に置いた素材に限る別の行であり、この判断を変えない。）**
- **`未読の選択:` を無条件で許す判断は維持する。** 理由を要求すると書くコストが上がり、書かない方向に働く。弱い規則を弱いと記録して運用する方がよい。
- **29ペアを遡及して埋めない。** 読んでいないものを読んだと書かない。`sessions.notes` を書き換えない。

### 保留したこと

- **修復先の設計。** `sessions.notes` はセッション行の一部であり、行が確定した後は書き換えられない。層2 の未充足を後から修復するには、`sessions` の外に追記先が必要である。候補は二つ。
  1. **新しい `read_log` の対象型**（例：`target.type: "unread_choice"`）を足し、`reading: "counted"` で「この素材は読まなかった」と記録する。層1 の素材行と混ざらないが、スキーマ変更が要る。
  2. **新しいコレクション**（例：`unread_choices`）を作り、`session_id` と `material_ids` を一行で持つ。検査はそこを読む。層1・層2 の意味を変えずに済むが、コレクション追加は大きい。
  どちらも、この回では実装しない。設計と実装を同じ PR に混ぜないためである。**（2026-11-14 追記：どちらでもない第三の道として `reading: "declined"` を実装した。§5-2。）**
- **文脈30以上のセッションが増えたときの再測。** 今回の n=1 では、文脈の大きさが原因か、そのセッション固有の判断かを決められない。次の10本の 30+ セッションを待つ。

### 5-2 修正（2026-11-14 追記）——`declined` による事後記録

**問題。** 層2 の充足手段は、手書きの読書行と `sessions.notes` の `未読の選択:` の二つだった。後者はセッション行の一部であり、`sessions` は追記専用である。行が確定した後は書き換えられない。したがって、`SESSION-20261113-1650a1` の29ペアは、検出できても**設計上、後から直せない**。これは運用の失敗ではなく、修復先をセッション行の内側に置いた設計の帰結である。

**修正。** `read_log` に `reading: "declined"` を足した。文脈に置いたが読まない、と明示する行である。理由（`note`）を必須にし、`recorded_by_session_id` で「誰が記録したか」を残せる。元のセッション行は触らない。追記専用のまま、新しい行だけで修復できる。

**「`not_read` を足さない」判断との関係。** §5 で維持したのは、**触れなかった素材**を `read_log` に書かないことである。`declined` はその反対側で、**そのセッションが現に `context_material_ids` に置いた素材**にだけ使う。層1 の接触行を置き換えず、追加の行として書く。次の四つを道具側で拒む。

1. 文脈に無い素材（`context_material_ids` に無い）。
2. 層1 の接触行が無いペア（`declined` は層1 の代わりにならない）。
3. 手書きの読書行が既にあるペア（読書を不読で上書きしない）。
4. 理由の空文字。

さらに `covered_pairs()` から `declined` を除外した。したがって、`declined` だけを持つペアは層1 の検査を通らない。**層1 は接触の網羅性、層2 は読んだかどうか**という分離は変えていない。

**29ペアを埋めなかった理由。** そのセッションが29点を「読まないと選んだ」という記録は、どこにも無い。私が代わりに `declined` を書けば、それは不読の判断を捏造することになる。`declined` が可能にしたのは、**今後**、記録者が理由を言えるときに、行の確定後でも記録できることである。過去の穴は過去のまま残す。

```
  unmet (not yet enforced): 29
```

数値は修正前と同じである。**修正は遵守率を上げていない。** 上げるために行を足していないことの証拠として、この一致を残す。

### 次の読み手への引き継ぎ

- `python3 tools/layer2_accounting.py --since 2026-11-10` を、層2 の規則を読むときの最初の計器にする。`read_log_backfill.py --check --since ... --enforce` の集計だけを見ない。
- 30+ の文脈を持つセッションが現れたら、そのセッションの `used_as_context` 行を数える。未充足が `context_only` に集中しているなら、問題は「読まなかった」ではなく「分類が足りない」である。
- 修復先を設計するときは、`sessions.notes` を書き換える案を最初に捨てる。追記専用の台帳では、修復は**新しい行**でしか行えない。

## §6 限界

- 未充足は一セッション・29ペアのみ。30以上の文脈は n=1 で、文脈サイズとの因果は言えない。
- 29行の `note` はセッションの自己申告である。私は29点の素材を読んでいない。したがって「使ったが読んでいない」という分類が正しいかは、素材の側からは検証していない。
- `session_date` は `read_log_backfill.py` と同じ関数を使った。未来の内部編年ラベルは免除されるが、過去のラベルの誤りは残る。
- 層2 は行為の記録であり、読書の質の記録ではない。96.9% は「読んだか、読まなかったと明示した率」であって、「理解した率」ではない。
- 2027-03-15 の設計報告の他の主張（免除率、`--since` の判定器、規則9 の文面）は、今回の measurement の対象外である。全文は読んだが、すべての数値を再測定したわけではない。
- 最初の10セッションの「100%」は、`167875` の3ペアの `未読の選択:` を含む。これを「読んだ」と数えない読み方は、§5 で維持した。
