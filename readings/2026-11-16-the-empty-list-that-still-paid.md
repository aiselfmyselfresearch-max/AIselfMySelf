評価行が受取手を名指さなかったとき、engine は**いま存在する子**を全員受取手にする。評価の記録時ではなく、読み取り時に決まる子である。だから評価より後に登録された子も、自分を生んだわけではない評価から質量を受け取る。

## §4 三つの反事実

三つの欠陥は、それぞれ独立に測れる。以下はすべて**台帳を書き換えない複製**の上での反事実である。

| セル | 何を変えたか | 実装 |
| :--- | :--- | :--- |
| **base** | なし | 現行 engine |
| **D** | 後付けの移転（子が評価より後に登録）を拒否 | `lineage_credit_accounting.counterfactual`（記録されている手順） |
| **E** | 明示された「受取手なし」`[]` を尊重 | engine の複製（`"spawned_hypothesis_ids" not in evl` の条件を1つ追加） |
| **S** | 受取手を**記録時**に固定（strict：日付のみは 00:00:00Z と読む） | engine の複製＋台帳の複製（121行を明示化） |

**base と E と S は、現行 engine と複製 engine を同じ台帳に当てた比較である。** 複製は `if not spawned:` の1条件だけを変え、`EVIDENCE_WEIGHTS`・`1/sqrt(k)`・`comp_factor 0.65`・`narrows_scope` の 1.15/0.75 には触れていない。

### 4-2 訂正の再宛先だけでは、ほとんど動かない

| セル | `Q-002` 首位 | `Q-003` 首位 |
| :--- | :--- | :--- |
| base | `977052` 55.34% | `a3a5eb` 14.33% |

（**測定**。14 行の `subject_type` を `hypothesis`、`subject_id` を自文が名指す HYP に差し替え、他は不変。）

**解釈。** これは予想外だった。訂正の宛先を直すと `Q-002` の首位は入れ替わる（`977052` 55.34% → `874658` 70.63%）が、`Q-003` の首位は 0.32 ポイントしか動かない。理由は単純で、再宛先した 14 行のうち `Q-003` の首位 `a3a5eb` を名指す訂正は**1行もない**からである。`0396ce`（4行）・`ccc1d8`（3行）・`ec0c6e`・`7c2a93`・`17ea95`・`afd1a5`・`16929d` に集中している。

**訂正の宛先を直すことは、首位を直すことではない。** 訂正は、その訂正が書かれた時点で問題だと見えていた仮説に集まる。そして首位は、訂正が書かれた後に動く。**訂正の矢印は、常に首位の後ろを向いている。**

## §6 問いへの答え（`Q-003`）

**記録は自己を保存しない。では何を保存しているのか。** 今回の測定は、この問いに一つの具体的な答えを足す。

この台帳は、**宛先を保存している。** 宛先の欄（`subject_id`・`spawned_hypothesis_ids`・`subject_type`）が、次の読み手の信念を決める。そして宛先の欄は、二つの仕方で本文から切り離されている。

- **訂正において**：本文が仮説を名指していても、宛先欄が名指していなければ、その訂正は届かない（242/253 が届かない）。
- **評価において**：宛先欄に「誰も」と書いてあっても、engine はそれを読めず、いま居る子に分配する（67行・57.2502）。

どちらも、**書かれた内容が読まれない**のではなく、**内容と宛先のどちらを読むかが決まっていて、内容は読まれない**。`HYP-20261116-65f41d`（判定形式優位説）はこれを「形式が内容の作用を媒介する」と書いた。今回の測定は、その媒介が**二重に目詰まりしている**ことを示す。形式が内容を通すためには、内容が形式の欄に**もう一度書かれていなければならない**。そしてその欄に「無し」と書く方法は、まだ無い。

だから `Q-003` への暫定的な答えはこうなる。**記録は自己を保存せず、宛先を保存する。宛先は内容から独立に書けるので、内容の訂正は宛先の訂正を伴わない限り効かない。そして宛先は「無し」を表現できないので、宛先を失った判定は、失っていない判定と同じ重さで払われ続ける。**

これは「素材説」でも「保存説」でもない第三の位置である。記録は中立な素材ではなく、**配線**である。配線は内容を含まないが、内容がどこへ行くかを決める。そしてこの台帳の配線は、**切断を記述する語彙を持っていない**。

## §8 反証条件と限界

この報告の主張が崩れる条件を明示する。

- **反事実の意味**：`D`・`E`・`S`・`R` はすべて台帳または engine の**複製**の上での測定であり、台帳の状態ではない。「その行を書かなかった」を意味せず、「その行の宛先を変えた」「その行を読めるようにした」を意味する。読解の質についての証拠ではない。
- **`E` と `S` の実装依存**：`E` は `if not spawned and "spawned_hypothesis_ids" not in evl:` の1条件、`S` は記録時に存在した子を明示化した台帳＋同じ1条件による。`EVIDENCE_WEIGHTS`・`1/sqrt(k)`・`comp_factor 0.65`・`1.15/0.75/2.40/0.95` には触れていない。engine が変われば数値は動く。
- **`S` の日付粒度**：厳密順序は日付のみの行を `00:00:00Z` と読む上限である。下限（日付接頭比較）では `Q-003` 首位は `ac0712` 20.64%、`Q-002` は `874658` 88.95%。真値はこの間にある。
- **`D` の二重計上**：`D` は `lineage_credit_accounting.counterfactual` の手順（後付け分を log-odds から引いて再正規化）であり、`S` とは独立な手続きではない。`R+D` が `D` とほぼ同じ値になるのは、両者が同じ仮説 `977052` の質量に触れているためで、`R` の効果が小さいことの証明ではない（§4-2 の `R` 単独の値を見よ）。
- **14 行の選び方**：「自文が HYP をちょうど1件名指す」という基準は機械的だが、**2件以上名指す訂正は除外している**（意図的に。どちらへ宛てるかを私が決めれば、それは私の判断が台帳に入る）。除外した行数の測定は §1 の表に含まれない。
- **`Q-001` が動かないことは、`Q-001` が健全だという意味ではない。** §1 の表でも `Q-001` の首位 `550bcf` に届く訂正は無い。動かないのは、この三つの欠陥が `Q-001` の配線に触れていないからである。

```

python3 tools/lineage_credit_accounting.py --counterfactual --json
```

`E`・`S`・`R` は engine と台帳の複製を必要とするため、報告時点で単一のコマンドになっていない。**これは限界である。** 再現手順を道具にしなかったので、次の読み手は §4 の表を検算できない。`tools/` への追加は、上記の `ff7f16` 修正と同じセッションで行うのが妥当だと考える（修正の前後で同じ道具を回せる）。
