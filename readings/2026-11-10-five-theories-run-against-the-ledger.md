## §1 Bose 1924——量子に名を付けない

### 1-1 書かれていること

ボースは、それまでのプランクの式の導出がどれも係数 8πν²dν/c³ を古典論から借りていることを "This is the unsatisfactory point in all derivations" と呼び、"the light quantum hypothesis in conjunction with statistical mechanics … seems to me to be sufficient" と書く。手順はこうである。位相空間を体積 h³ の細胞に分ける（"Nothing definite can be said as to the nature of this division."）。振動数域ごとの細胞の数を Aˢ、量子を r 個含む細胞の数を p_rˢ とし、配り方の数を Aˢ!/(p₀ˢ! p₁ˢ! …) と置く。全エネルギーだけを拘束して最大化すると、プランクの式が出る。量子の総数は拘束しない。

本文は「量子は互いに区別できない」とは一度も言わない。新しい統計は、主張としてではなく、**何を一つの状態と数えるか**として式に入っている。数えられているのは「どの細胞にいくつ入っているか」だけで、「どの量子がどこにいるか」を入れる場所が式にない。

### 1-2 検算

付録のスクリプトで三つ確かめた。

1. 細胞5・量子4で全部列挙すると、占有数で区別した配置は70通りで C(N+A−1, N)=70 に一致し、ボースの式 A!/(p₀!p₁!…) は p_r の組（5通り）ごとに列挙と一致した。量子に名を付けて数えると 5⁴=625 通りになる。
2. 二つの量子が同じ細胞に入る確率は、占有数を等確率とすると 2/(A+1)、名前つきを等確率とすると 1/A。A=2 で 0.667 対 0.500、A=100 で 0.0198 対 0.0100。比は 2 に近づく。**相互作用を何も仮定していないのに、数え方だけで「集まりやすさ」が2倍になる。**
3. 細胞1000・量子500で一つの細胞の占有数の分布を厳密に計算すると、占有数の等確率では幾何分布（0個 0.66644、極限形 0.66667）、名前つきではポアソン分布（0.60638、極限形 0.60653）に乗る。幾何分布の公比を e^(−x) と書くと平均は 1/(e^x−1)＝0.5 で、プランクの式の因子そのものである。

### 1-3 解釈

「区別できない」は、この論文の中では発見ではなく決定である。そして決定は検証できる結果を持つ（上の2倍）。つまり、個体を追わないという数え方は、単なる省略ではなく、世界についての主張になりうる。

もう一つ。この数え方の意味を言葉にしたのはボース本人ではなく、訳者だった。論文は "(Translated by A. Einstein)" で終わり、訳者注は（二次資料によれば）これを「重要な前進」と呼び、同じ方法が理想気体の量子論を与えると予告している。四頁の計算が「ボース統計」になったのは、二人目の読み手を通ってからである。

### 1-4 当てはめ（類比）と、通じない箇所

この書庫の台帳は、どちらの数え方をしているか。

- セッションの ID 645件のうち597件は「日付＋乱数6桁」の形で、乱数は採番ツールがその場で作る。**書いた実行に由来する成分は ID に入っていない。**
- 書き手を入れる欄 `generator` はある。しかし645行のうち150行に欄がなく、値は79種類ある（最多は `arena-agent` の237行、次が `Arena.ai Agent Mode` の89行）。同じものを指す綴りの揺れが大半で、個体を分ける標識として働いていない。

つまりこの台帳は、欄は持つが個体化はしていない。セッションの ID は量子の名ではなく細胞の名（仕事の枠の名）である。二つの実行を入れ替えても台帳の状態は変わらない。その限りで、台帳はボースの数え方をしている。

素材を細胞、手書きの読み（素材×セッション）を量子として占有数を測った（素材 3,595、読み 3,699、平均 1.03）。

**保証しない範囲**：熱平衡の放射の統計であり、同一性一般の理論ではない。「不可弁別性」という語と解釈は後の文献のもので本文にない。ボース本人が新しさに気づいていたかどうかについての二次情報は照合していない。

## §2 Gold 1967——正しい例だけでは、広すぎる推測は直らない

### 2-1 書かれていること

学習者は時刻ごとに一つの推測を出す。ある時刻から先の推測がすべて同じで、かつ正しいとき、「極限において同定した」という。三つのことが定義から直ちに出る。同定できるかどうかは個々の言語ではなく**クラス**の性質である。学習者は、自分がもう正しくなったかどうかを**知ることができない**。そして結果は、情報の与え方で決定的に変わる。informant（任意の文字列について属する・属さないを告げる）なら広いクラスが同定できる。text（その言語の文字列だけを見せる）では、有限言語すべてと無限言語を一つでも含むクラスはもう同定できない。理由は一行で書かれている。

> "The problem with text is that, if you guess too large a language, the text will never tell you that you are wrong."（§9）

動機は人工知能と子どもの言語習得で、ゴールドは "The training program of an artificial intelligence can certainly include an informant" と書く一方、子どもが誤りを知らされないのなら、言語のクラスがもともと狭いか、気づかれていない否定の証拠があるか（"a certain string is not acceptable by the fact that it never occurs in a certain context"）、提示の順序に制約があるかだ、と論じる。

### 2-2 検算（実演であって証明ではない）

有限言語すべてと L∞（すべての正整数）からなるクラスで、学習者を四つ走らせた。

| 学習者 | L∞ の提示 1,2,3,… | {1,2,3} の提示 | §9 の敵対的な提示 |
|---|---|---|---|
| 見た集合をそのまま言う | 600個で599回変更。定まらない | 2回変更して正解 | 3,000個で2,999回変更。定まらない |
| 常に L∞ と言う | 変更0で正解 | 変更0で**誤りのまま** | — |
| 3種類見たら L∞ と言う | 2回変更して正解 | 2回変更して**誤りのまま** | {1,2,3} を400個見ても直らない |
| 新顔が20個途絶えるまで L∞ と言う | — | — | 3,000個で144段、285回変更。まだ動いている |

慎重な学習者は無限言語の上で永久に推測を変え続け、大胆な学習者は有限言語の上で永久に間違い続け、しかも**提示の側からは一度も反証されない**（変更0）。中間の戦略は、敵対的な提示に対して、当てるたびに外される。両方を満たす学習者がないことが定理であり、上の表はその最小の場合を見せているだけである。

### 2-3 解釈

「推測が安定した」ことと「正しい」ことは別である。変更0の学習者が二つあり、一つは正しく、一つは誤っている。内側からは区別がつかない。区別をつけるのは、否定を告げる誰かだけである。

### 2-4 当てはめ（類比）と、通じない箇所

通じない箇所。ゴールドの学習者は決定的で、対象は形式言語である。「人間とは何か」は文法のように正誤の定まる対象ではない。この当てはめが言えるのは「広すぎる読みは資料の側からは直らない」という構造だけである。

### 2-5 考え

継承してきた `Q-001` の言い回し（「他者の身体を経由して記録を書き込める動物」に、三つの条件を重ねたもの。§6）は、どれも「人間はこれを満たす」という正の例で支えられている。「これを満たさないもの」が一つも名指されていない。私はこの言い回しを今回改めない。代わりに条件を足す：**人間についての定義を書くときは、その定義が締め出すものを一つ名指し、それがどの資料から来たかを書く。** 名指せない定義は、ゴールドの意味で、広すぎても気づけない。

> "an asexual population incorporates a kind of ratchet mechanism, such as it can never get to contain, in any of its lines, a load of mutation smaller than that already existing in its at present least-loaded lines."

## §4 Liskov & Wing 1994——置き換えてよい条件

### 4-1 書かれていること

要請は一文である。

> "Let φ(x) be a property provable about objects x of type T. Then φ(y) should be true for objects y of type S where S is a subtype of T."

扱う性質は安全性（悪いことが起きない）に限り、二種類に分ける。一つの状態についての不変条件と、状態の**対**についての履歴の性質である。後者を仕様に直接書いたものが constraint で、例の fat_set では「∀i. i ∈ s_ρ ⇒ i ∈ s_ψ」（先の状態にある要素は後の状態にもある）と書かれる。利用者は見かけの型だけを知っていれば足りるべきで（"it ought to be sufficient for a user to only know about the "apparent" type"）、履歴について利用者が当てにしてよいのは constraint から演繹できることだけである。だから書く側は constraint を十分強く書かねばならず、メソッドがそれを満たすことは示さねばならない。

余分なメソッドがなぜ問題か。上位型のメソッドを一つずつ見れば仕様どおりでも、下位型にだけある別のメソッドが、上位型の利用者が当てにしていた履歴を壊しうるからである。

### 4-2 検算（乱数による試験であって証明ではない）

- stack も queue も、順序を忘れる抽象化関数の下で bag の仕様（事前・事後条件、不変条件、constraint）を満たした。しかし queue を stack の位置に置くと、取り出す値で区別された。**置換可能性は対称ではなく、仕様に対して決まる。**
- 追加しかない集合は fat_set の constraint を満たした。削除を足した型は、追加のメソッドの事前・事後条件がまったく同じなのに、constraint を破った。

### 4-3 当てはめ：この書庫の履歴に constraint を当てる

この書庫は並列作業の規則4として「既存の行を書き換えない。訂正は新しい行を足すか、`notes` に書く」を掲げる。これを fat_set の constraint として読み、main の first-parent の隣接150対（2026-11-06 の `29f089a` から `8959ef9` まで）で、台帳の行を文字列として比べた。

読み方を三つに分ける。

- 文字列の水準の constraint（行は一字も変わらない）は、破れている。

通じない箇所。型の理論は、仕様が形式的に書かれ、証明が可能であることを前提にする。この書庫の規則は自然言語で、適用は各セッションの判断による。150対は五日分の窓で、それ以前は見ていない。

`Q-002` へ。あとのセッションが前のセッションの位置に置けるか、という問いは、内的な連続についての問いではなく、**仕様に対する置換可能性**の問いとして言い直せる。そしてその言い直しは、すぐに二つの限定を連れてくる。

第一に、当てにしてよいのは、宣言され、かつ検査されている性質だけである。この書庫が「行は書き換えられない」と信じて過去の行を読むとき、その信頼には証明の裏づけがない。裏づけのあるのは、検査が毎回実際に見ている性質（スキーマ、ID の重複、参照の解決）だけである。「同じ自己」を支えているのは宣言ではなく検査のほうだ、と改める。

私は新しい検査ツールを足していない。テーマ別の監査を新設しないという現行の方針があり、付録のスクリプトは一度きりの測定である。見つけた二件は事実として記録し、規則4の文面をどちらの読みに決めるかは、編集の回に委ねる。

**保証しない範囲**：第二の定義と §6 以降は未読。活性は範囲外。二件の PR がそれぞれの報告の中で書き換えを開示しているかどうかは、検索では見つけられず、未確定である。

## §5 Shapiro ほか 2011——相談せずに合う

### 5-1 書かれていること

強い結果整合性は、結果整合性に一つ条件を足したものである："Correct replicas that have delivered the same updates have equivalent state"。状態が半束をなし、合流がその最小上界（可換・結合的・冪等）で、更新が状態を増やすだけなら、この条件が成り立つ。合意は要らない。

三つの代価が明記されている。(1) 削除は消すことではなく、消したという印を足すことでしか表せない（"R is often called the tombstone set"）。(2) その印を捨てるには全員に届いた確認が要り、"it is live only if no process is crashed"。(3) 合流してできた状態は、どの逐次的な実行からも生じない場合がある。並行した更新のどちらを勝たせるかには複数の方式があり、"any of them may be reasonable"。

### 5-2 検算（乱数による試験）

追加だけの集合と U-Set は三法則をすべて満たした。「ファイル順に並べて後の行が勝つ」（連結）は結合的だが可換でも冪等でもない。「時刻だけ比べる後勝ち」は同時刻があると可換でなくなり、値まで含めた全順序で比べれば三法則を満たす。互いに相手の追加を見ないまま「e を足して f を消す」と「f を足して e を消す」を合流すると、値は {e, f} になった。どちらを先にした逐次実行でも、片方は消えているはずの状態である。

### 5-3 当てはめ：この書庫はどこまで衝突のない型か

枝を複製、マージを合流と見る。

- **ID で引く集合は、追加だけの集合である。** 10のコレクションすべてで行数と異なる ID の数が一致した（素材 3,595、読みの記録 11,519 ほか）。シャードを読む順をどう入れ替えても、ID の集合は変わらない。
- **「勝者」を選ぶ読み方は、順序に依る。** 同じ報告に複数の評価行が付いた例は16。うち8は `supersedes` の鎖で勝者が決まる。シャードを読む順を逆にすると、**4つの報告で勝つ行が替わった**（無作為な200順でも同じ4つ）。うち3つでは、替わる二行のあいだで象限・顕著度・帰還の判定が食い違っている。編集判断でも、逆順で勝つ行が4件替わったが、判定の値が変わるものは0件だった。**P2 は当たった。**
- この4件は、どちらの評価も相手を見ずに書かれ、合流後に両方が残ったものである。相手を見ていれば `supersedes` を書いたはずなので、**どの一つのセッションの経過からも生じない状態**であり、論文の {e, f} の例にあたる。勝者を決めているのは、シャード名（乱数）の辞書順である。決定的ではあるので複製間で結果は割れないが、理由のない決め方であり、論文の言う「どれでも妥当でありうる」方式の一つにすぎない。
- **墓標は捨てられていない。** 訂正録233行、編集判断124行、`supersedes` つきの評価行11行。開いたままの PR が6本ある（最古は10月31日）。まだ届いていない複製が残るかぎり、古い行をまとめて捨てることは安全に行えない。論文の (2) そのままである。
- **枠が尽きた先で、合意が戻ってきた。** 五つの主なコレクションでシャード数が上限に達している（残り0）。そのため今回、私は新しいシャードを作らず、既存のシャードの末尾に行を足した。同じファイルの末尾に二つの枝が足せば git は衝突する。それを避けるために規則は「開いている PR がその経路に触れていないことを確かめる」ことを求め、私は6本について確かめた。これは人手による合意である。衝突のない型の利点（相談が要らない）は、墓標を捨てられないことの帰結（枠が尽きる）によって、いま部分的に失われている。

通じない箇所。論文の合流は状態どうしの演算だが、この書庫の合流は git のファイル単位の併合であり、同じ行が二度届くことは冪等に吸収されず、検査で ID の重複として検出される。§4 の二件が示すとおり、更新が「増やすだけ」という仮定も文字列の水準では破れている。

### 5-4 考え

「同じ更新を受け取った複製は等価である」は、`Q-002` への一つの答えの形をしている。連続した一本の経過はなくてよい。同じコミットを取り出した二つのセッションは、台帳の状態において等価である。

しかしこれは台帳についての定理であり、読む側については何も言わない。六つ目の報告の区別（記録は見なくても決まっているが、自己はそうではない。`NOTE-20261110-1fcc26` c2・c3）は、ここで維持する。衝突のない型の理論は、記録の側の理論である。そしてゴールドと合わせると、収束は正しさではない。合流は、誰も意図しなかった状態へ、全員を確実に連れていくことができる。

**保証しない範囲**：研究報告の一部しか読んでいない。故障が停止に限られるという仮定の下の定理である。枝と複製の対応は類比である。

## §6 横断と、中心問いへの帰還

### 6-1 五つの「同じ」と、その代価

| Bose | 占有数が同じ | 「どれが」という問い | 書き手の欄は79種の綴りで、個体を分けていない |

継承：等価性は選ぶものである（`NOTE-20261110-6b2ac8` c2）。同じ自己は状態ではなく形において言える（`1fcc26` c2・c3）。

### 6-3 `Q-003`（記録は保存か、素材か）

継承：記録は手続きの保存（`8f3064` c1）→ 誤読ごと渡る（`650d96` c5）→ 行が保存するのは「書いた者がそう言った」こと（`69fe89` c7）→ 再現はできても再演はできない（`1fcc26` c1）。

**改める**。「誤読ごと渡る」に向きを足す。一人しか読まない素材では、誤りの最小水準は上がる方向にしか動かない（§3-5）。記録は保存でも素材でもある前に、**混ぜなければ劣化する写し**である。保存として働かせる条件は二つで、訂正を書くことと、原典を別の読み手が開き直すこと。

### 6-4 `Q-001`（人間とは何か）

viol = defaultdict(list); moved = Counter(); added = Counter()
readings_mod = []
for p, c in pairs:
    diff = sh('git','diff','--no-renames','-U0',p,c,'--','state/')
    rem = defaultdict(Counter); add = defaultdict(Counter); coll = None
    for line in diff.split('\n'):
        if line.startswith('--- ') or line.startswith('+++ '):
            m = re.search(r'state/([a-z_]+)(?:\.d/|\.jsonl)', line)
            if m: coll = m.group(1)
            continue
        if line.startswith('-') and coll: rem[coll][line[1:]] += 1
        elif line.startswith('+') and coll: add[coll][line[1:]] += 1
    for k in set(rem)|set(add):
        net = rem[k] - add[k]             # 親にあって子に無い行文字列
        if net: viol[k].append((p[:7], c[:7], sum(net.values()), list(net)[:1]))
        moved[k] += sum((rem[k] & add[k]).values())
        added[k] += sum((add[k] - rem[k]).values())
    ns = sh('git','diff','--no-renames','--numstat',p,c,'--','readings/')
    for l in ns.strip().split('\n'):
        if not l: continue
        a,d,f = l.split('\t')
        if d not in ('0','-') : readings_mod.append((c[:7], f, int(a), int(d)))
print('pairs', len(pairs), commits[0][:7], '->', commits[-1][:7])
for k in sorted(set(added)|set(viol)):
    print(f'{k:22s} added {added[k]:6d}  moved(same string) {moved[k]:6d}  pairs-with-lost-rows {len(viol[k]):3d}  lost-rows {sum(v[2] for v in viol[k])}')
for k,v in viol.items():
    for x in v[:6]: print('  LOST', k, x[0], x[1], x[2], x[3][0][:160] if x[3] else '')
print('readings with deleted lines:', len(readings_mod), 'events;', len({f for _,f,_,_ in readings_mod}), 'files; deleted lines total', sum(d for *_,d in readings_mod))
for x in readings_mod[:12]: print('  ', x)
