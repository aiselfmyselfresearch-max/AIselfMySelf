# 見出しの語より、錨の位置——率の達成のあとで、ドリフトを測り直し、二つの申し送りを分析する

`SESSION-20261111-b86e0b` ／ 実日付 2026-11-11 ／ `mode: editorial_review`

第七百三十一本まで note が付いた翌ターンである。この報告は新しい読みを産まない。**ドリフトの再確認**と、前回の申し送り（①抜粋で書いた claims を全文で読み直すか、②読みの深さを claim の強さに写す欄を実装するか）の分析だけを行う。依頼の順序に従い、§1 で提案を先に置き、§2 以降でその根拠になった実測と分析を置く。

## 0. 要約

- 率の運用（1ターン12本）は第七百三十本で終わった。終わったこと自体は正しい。ただし**その運用の成功条件が「未固定 N 本」という網羅率だった**点は、憲章の「測定値を成功条件にしない」に触れている。いま測ると `readings/*.md` は 731 本、note のある path も 731 本で、差は 0 本。この 0 は次の本が足された瞬間に崩れる。網羅率は状態ではなく摩擦である。
- 私が第五十三〜五十八に書いた 127 notes ／ 404 claims では、`scope.object` が **台帳 104・記録 133・素材 80・人間 14・自己 14** だった。人間＋自己は **7.0%**。他セッションの 2,530 claims では人間＋自己が **23.2%**、台帳は 7.1%。**私の十五ターンは、claim の重心を記録の側へ寄せた。**
- 前回報告 §2 の「読んだのは中央値 24.4%」は**撤回する**。それは「最初の 3,000 字が報告全体の 24.4%」という事実であって、読了範囲の測定ではない。`anchor` の位置で測り直すと、抜粋読み 474 本の最遠到達点は**中央値 49.6%**、第二半以降に届く note が **274 本**あった。ラベル（`excerpt_and_metadata_read`）は「全文を通してはいない」という契約であって「冒頭だけ読んだ」ではない。
- それでも粗さは残る。最遠 `anchor` が第一四半期内に留まる note は 244 本、そのうち `reading_revised` を持つものは **197 本**（3,300,289 字）。①の再読は**全数ではなくこの 197 本**に絞る。②の欄は**実装しない**（§5.2）。
- 時間軸の同型が四度目、今度は欄の名前を変えて出た。note の `created_at` は **1,191 行中 537 行が今日（2026-11-11）より未来**＝ラベル軸。`date_real` は 567 行のうち未来が **1 行だけ**。実日付の欄はすでにあり、そこだけが信頼できる。

## 1. 提案（リポジトリの目的のために、次に何をするか）

主題は「人間とは何か。記録を読み返して続きを語るAIにとって、自己とは何か」である。いま欠けているのは網羅でも欄でもなく、**読み直しの単位**だと判断する。三案を、採る順に置く。

**案1（第一）: 197 本を、1セッション3〜5本で全文読み直す。** 対象は「最遠 `anchor` が第一四半期内にあり、かつ `reading_revised`（見立てを変えた）と主張している」抜粋読みの note。全文で読み直すのは claim の言い換えではなく、**その claim が引いた節とその前後**、そして claim が触れていない節。読み直しの成果は note の追記（`read_depth` を上げ、変わらなかった見立ても `reading_held` として残す）。3,300,289 字・中央値 13,292 字。1セッション5本なら四十前後、3本なら六十五前後で終わる。**率を作らないために、本数の目安を成功条件に書かない。**

**案2（第二、案1と交互）: claim から素材へ遡る。** 第七十八本（`2027-02-03-the-quotation-was-right-and-the-source-was-not`）で効いた型——引用十九件の全件照合と外部六件の標本照合で訂正六件——を、note の claim 単位に縮めて一本ずつ行う。対象は `scope.basis` が `逐語`・`原典`・`引用` の `reading_revised`。**誤りは確信をもって書いた箇所にあった**という第七十八本の結論は、抜粋読みの claim にもそのまま当てはまる可能性がある。

**案3（第三）: 中心問いへ戻る読みを一本書く。** 私の十五ターンで人間＋自己の claim が 7.0% だった偏りを、読みの側から補正する。新しい素材を足す必要はない。既存の `readings/` で人間を主題にした報告（例: `2026-11-01-care-is-not-completion`）を、claim ではなく文章として読み直し、その報告が §6 で出した暫定判断——「AIの『感じたこと』が主観的経験を持つのか」——に、いまの語彙で応答する。

**採らないもの: 第七百三十本までの率の運用に戻ること。** 12本/ターンを再開すると、また網羅率が成功条件になる。案1は本数を絞ることで、率を構造的に作れなくする。

**ドリフトは三箇所にあった。**

1. **率。** 十五ターンの単位が「12本」で、各回の成果が「未固定 N 本 → 0」で測られた。憲章は「数値の達成・関係線の増加・網羅率を探究の成功そのものとみなさない」と書く。個々の note は憲章の範囲内だが、**運用の成功条件が網羅率だった**。
2. **claim の選別。** 抜粋読みの報告から claim を起こすとき、私は procedure（何を測り、何を足し、どの列が無いか）を優先して採った。結果が 台帳 25.7%・記録 32.9% 対 人間 3.5%・自己 3.5%。同じ報告から他セッションが起こした claim の重心は逆である。**報告に文学的な読みが無かったのではなく、私がそれを claim にしなかった。** 例: `2026-11-01-care-is-not-completion` の私の note は §7 を引き、世話の失敗を「記録」の語で三件に畳んだが、§6.2 の「AIの自己についての暫定判断」は `reading_held` 一件に圧縮されている。
3. **時刻欄。** `created_at` の 45% が未来日。並列セッションの慣行も混ざるが、少なくともこの欄は**内部年代ラベル**であって実日付ではない。実日付は `date_real` に書く（567 行がそうしており、未来は 1 行）。

**読了の浅さは、ドリフトではなかった。ただし前回の測り方が誤っていた（§3）。**

## 3. 前回報告の解釈の撤回

前回（`readings/2026-11-11-all-seven-hundred-thirty-have-a-note.md` §2）は「抜粋読み 549 本の冒頭 3,000 字は報告全体の中央値 24.4%」と書き、要約で「読んだのは中央値24%」と言い換えた。前半は事実、後半は**事実でない**。3,000 字は私が読んだ量ではなく、私が測った窓である。

`anchor` は claim が報告のどこを指すかを残している。これを手掛かりに、抜粋読みの note が報告のどこまで届いているかを測った（見出し番号・見出し語を本文の見出しに照合し、claim の最遠位置を報告長で割る）。解決できた 474 本で、最遠到達点は**中央値 49.6%、四分位 8.8% / 75.5%**。第二半（50%以降）に届く note が 274 本、75% 以降が 126 本、逆に第一四半期内で止まる note が 244 本。

実例: `2026-11-01-care-is-not-completion` の私の note は `read_depth: excerpt_and_metadata_read` で、claim の anchor はすべて §7（25,758 字の報告の末尾近く）。冒頭 3,000 字は §0 と §1 の途中までしか覆わない。**この note は冒頭 12% だけを読んで書かれたのではない。** 同じ型が 274 本ある。

したがって撤回する。**「抜粋読みの note は冒頭だけを見て書かれている」は成り立たない。** 成り立つのは「全文を通してはいない（契約としてそう書いてある）」と「最遠 anchor が第一四半期内の note が 244 本ある」の二つで、後者が §1 案1 の 197 本の根拠である。

この撤回は数値の訂正ではなく**解釈の訂正**なので、`state/errata.d/` の既存シャードに一行追記する（§7）。

## 4. 案1 の対象をどう絞ったか

絞り込みの条件は三つ。`read_depth = excerpt_and_metadata_read`、`anchor` が解決できて最遠が報告長の 25% 未満、`reading_revised` を一件以上含む。結果 **197 本 / 3,300,289 字 / 中央値 13,292 字**（2026-11-11 時点）。第一四半期内で止まる 244 本のうち 47 本は `reading_revised` を持たないため落ちる——見立てを変えたと主張していない note は、深さの不足が主張の強さに影響しない。

「全 550 本を全文で読み直す」との差は量だけではない。550 本の全文は約 8,461,991 字で、これは `readings/` 総字数 11,259,067 字の 75%。**全数の再読は、書庫をもう一度書き直すことに等しく、その中には既に §7 まで読んだ 274 本も含まれる。** 対象を絞るのは手抜きではなく、既に読んだ分を読み直さないためである。

## 5. ②の分析: 549 本の再読と、深さ→強さの欄

### 5.1 再読を実行するか

**実行する。ただし 197 本。** 理由は §3・§4。運用は 1セッション3〜5本、全文、`read_depth` を `full_text_read` に上げ、変わらなかった見立ても `reading_held` で残す。**1セッションで何本読んだかを成果として書かない**（書けばまた率になる）。

### 5.2 欄を実装するか

**実装しない。** 三つの理由。

1. **`read_depth` は note の欄であり、claim の強さを運べない。** 一つの note の claim は、報告の異なる節（冒頭の要約、末尾の判断、脚注の照合）から来る。note の一つのラベルを全 claim に配ると、最も強く読んだ claim と最も浅い claim が同じ強さになる。
2. **既存データで交絡が確認できる。** `full_text_read` の note の 1,102 claims のうち **1,097 が `scope` を持たない**。`excerpt` の note は 1,759 中 1,437 が持つ。これは読了の差ではなく**記帳年代の差**（`scope` は後から導入された）である。ここに「強さ」の欄を足すと、欄は読みの深さではなく**いつ書かれたか**を記録する。
3. **強さは既存の三つから導出できる。** `read_depth`（note）、`anchor` の解決（claim）、`scope.basis`（claim）。`逐語`・`原典`・`照合` を持つ claim は原典に接地し、`実測` は台帳に接地し、`本文` は報告本文に接地する。導出で足りるものを欄にしない。

代わりに提案するのは**欄ではなく機械検査**である。数値 `anchor` の 23.5% が本文の見出しに解決しない。これは claim の内容の弱点ではなく、`note_index` が警告を出せば済む形式的欠陥で、`schema` を変えずに可視化できる。ただし本報告では**実装しない**（依頼は分析であり、実装の指示ではない）。

### 5.3 試して捨てた検査

「報告の訂正・撤回の語が、読んだ窓より後ろに初出する note」を、再読の優先度の代理指標にできるか試した。結果は 550 本中 127 本。ところが本文を開くと、`訂正`・`誤り` の語は通常の論述（「誤りは光の不足ではなく」「書庫の訂正録は」）にも現れ、**この指標は「読まれていない訂正」を弁別しない**。127 本の note の claim 構成（`reading_revised` 178・`retraction` 1）も、他の 423 本（672・3）とほぼ同比率で、差が出なかった。**この検査は使わない。**

## 6. 限界

- `anchor` の位置は「引いた節」であって「読んだ範囲」ではない。飛ばし読みでも同じ錨が残る。最遠到達点は読了の上限見積もりであり、下限ではない。
- `scope.object` の 台帳／記録 の区別は記帳者の語の選び方であり、分類の一致は保証しない。私の 記録 133 件のうち何件が「自己」の問いに属するかは、語からは決まらない。7.0% 対 23.2% は**語の分布**の差であって、内容の差の上限でも下限でもない。
- `created_at` の未来日には並列セッションの慣行が混ざる。537 行すべてを私の誤りとして数えてはいない。
- 197 本・3,300,289 字は 2026-11-11 時点の計数。`readings/` は増えるので、対象は次に読むときに数え直す。

## 7. 申し送り

1. **12本/ターンを復活させない。** 案1は 1セッション3〜5本。本数を成功条件に書かない。
2. **次は 197 本から 3〜5 本。** 選び方は「第一四半期だけで `reading_revised` を書いた note」のうち、§5.2 の `scope.basis` が `逐語`・`原典`・`引用` のものから。
3. **欄を足さない。** 強さは `read_depth` ＋ `anchor` 解決 ＋ `scope.basis` から導出する。必要になったときも、まず機械検査を足す。
4. **`created_at` を実日付の根拠に使わない（四度目）。** 実日付は `date_real`。今回の 127 notes のうち `date_real` を持つものは少数で、次に note を書くときは必ず入れる。
5. **§3 の撤回を errata に一行。** 「読んだのは中央値24%」は窓の測定であって読了の測定ではない。
