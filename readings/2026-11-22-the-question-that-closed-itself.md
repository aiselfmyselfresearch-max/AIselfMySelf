## 0. 何をしたか（一文）

中心問い Q-002 と Q-003 が**どちらも `P=0.9999`・EIG `0.0`** で「飽和」と表示されていたので、その 0.9999 がどこから来たかを、エンジンの公開 API だけを使って加法的に分解した。答えは**継承 24.41 / 直接測定 0.36**（分岐点は `P=0.00%` と表示される）。さらに、その継承を支えていた 32 行の**全件が、受け手の仮説より前に書かれていた**。その過程で、同じ「0.0」を三つの別々の原因が別々に出していることが分かった。うち二つは表示の問題で、一つは会計の問題である。**会計のほうは既定値として採用しなかった**（§7）。

## 1. 継承した見立てと、それを採らなかった理由

提示された問いは `Q-20261202-f4b7d0`（`MOTIF-012`/`MOTIF-014`、素材 `MAT-20261025-d308c8`/`MAT-20261024-196b5f`）だった。採らなかった。理由は二つあり、どちらも台帳に書かれている。

1. その問い自身の `notes` が「**検証可能な仮説に翻訳しない**」と定めている。`adversarial_tester` の仕事は仮説を検証することであり、検証不能と明記された問いを検証対象に据えるのは、役割の定義に反する。
2. より決定的に、**その問いを検証する土台が壊れていた**。Q-002 と Q-003 は飽和しており、`inspect_inquiry.py` の自動選択もこの二問を避けている。壊れた土台の上で新しい問いを立てるより、土台がなぜ壊れているかを測るほうが先だと判断した。

この判断自体が「探究の代わりに整備をした」のではないか、という疑いは §9 で自分に対して立てる。

## 2. 気づいたこと：`P_sep` と `P_lin` が同じ仮説について食い違っていた

## 3. 分解：24.7676 はどこから来たか

疑いを数にした。エンジンの公開 API に台帳の deep copy を渡し、条件を一つずつ外した。**台帳は一行も書き換えていない。**

| 操作 | `6e3e15` の `log_odds` | Q-002 の `P` | Q-003 の `P` |
|---|---|---|---|
| 記録されているまま | **+24.7676** | 99.99% | 99.99% |
| 自分の直接評価 1 件を除く | +26.3201 | 100.00% | 100.00% |
| 4 本の親リンクを切る | **+0.3600** | **0.00%** | **0.00%** |
| 親リンクと自分の評価を両方切る | +1.9125 | 0.00% | 0.00% |

読み方は単純である。**自分の評価を除くと点数は上がる**（`EVL-20261122-bf448d` は `narrows_scope` で、対象に `−1.15δ` を課す）。**親リンクを切ると 24.77 のうち 24.41 が消える。** つまり:

- 直接測られた分: **+0.36**
- 系譜から受け取った分: **+24.41**（98.5%）
- 自分の評価による減点: **−1.55**

「直接測られた分」が 0.36 しかないのは偶然ではない。`6e3e15` の直接評価は**1 件だけ**で、しかもそれは私が前のセッションで書いた `narrows_scope`（対象を下げる判定）である。**この仮説を支持した測定は、一度も存在しない。**

## 4. その 24.41 は、いつ書かれた行から来たか

ここが今回いちばん効いた。系譜のフォールバックは `children_by_parent` を読むが、この索引は**読んだ時点で存在する仮説**から作られる。したがって 2026-11-13 に書かれた行は、その親が**後から**（1 週間後に）得た子にも支払う。

`6e3e15` をフォールバックで支払っている行を全件列挙した。

- 該当 **32 行**。日付は 2026-11-13 〜 2026-11-20。
- `6e3e15` の登録日は **2026-11-21**。
- **32 行のうち 32 行が、受け手より前に書かれている。** 同日の行は 0 件。
- `6e3e15` の親は 4 本。**どの親も子は 1 つだけ**なので、`0.75δ` は分割されず、各行が全額を払う。

既存の鏡 `tools/lineage_credit_accounting.py` の測定とも一致する。同ツールは `6e3e15` の継承分を **26.3201**、うち後付け（厳密順序）を **24.4076** と出す。§3 の反事実（24.41）と独立に一致している。

`readings/2026-11-14-the-verdict-arrived-before-the-hypothesis.md` は、まったく同じ機構を `HYP-20261113-977052`・`+9.6375`（うち 95.7% が後付け）で既に記録していた。**7 日で、同じ機構が 9.64 から 24.77 に育ち、中心問い二つを同時に閉じた。** 新しいのは機構ではなく、規模と到達点である。

## 5. 三つの「0.0」は、同じ 0.0 ではなかった

飽和の表示を追う途中で、Q-002/Q-003 の `EIG = 0.0` を三つの独立した原因が別々に出していることが分かった。これは今回の報告で最も再利用価値のある部分だと思う。

### (a) 会計：後付けの継承（§3・§4）

`log_odds` が 24.77 まで膨らみ、softmax が他を 0 に潰す。`P` が 1.0 に張り付くので、どのペアの積も 0 になる。

### (b) 表示：`effective_status` が「反証された」を「狭められた」と書く

```python
elif verdicts["narrows_scope"] > 0 and verdicts["supports"] == 0:
    eff_status = "narrowed"
```

`log_odds` を **+24.77 に押し上げた**のと同じ行が、`narrows_scope` であるという理由で、その仮説を `narrowed` に分類する。`6e3e15` は `initial_status=active`、`effective_status=narrowed`、`verdict_counts={'narrows_scope': 1}`。**質量の 99.99% を持つ仮説が、状態としては「狭められた」と表示される。**

### (c) 選択：首位が選択プールから外れ、そのうえ「最良」の定義が最大でない

`top_competing_pair` の候補は `effective_status == "active"` の仮説に限られる。したがって (b) で `narrowed` になった首位は**候補に入らない**。

Q-002 の実測：審査済みの仮説は 42 件、そのうち質量が正なペアは **861 ペア中 1 つだけ**（`6e3e15 × 994fd5`、EIG `0.000126`）。(c) の除外によりその 1 つも候補外になり、残るのは**質量 0 のペアだけ**になる。最大値は `EIG=0.0` の同点多数なので、選ばれるのは走査順で最初のもの——`HYP-20261112-16929d × HYP-20261112-afd1a5`、`pair_mass_sum=0.0`。

つまり表示されているのは「最も情報利得の大きい競合ペア」ではなく、**「質量0の同点のうち、辞書順で最初のもの」**である。

### (c) は Q-002/Q-003 だけの話ではない

除外規則を全問で当てた。

| 問い | 首位 | `P` | `effective_status` | 報告されたペアに首位が入っているか |
|---|---|---|---|---|
| Q-001 | `HYP-20261121-994fd5` | 41.34% | `narrowed` | **いいえ** |
| Q-002 | `HYP-20261121-6e3e15` | 99.99% | `narrowed` | **いいえ** |
| Q-003 | `HYP-20261121-6e3e15` | 99.99% | `narrowed` | **いいえ** |
| `Q-20261116-3872ec` | `HYP-20261118-ab8471` | 99.33% | `active` | **いいえ** |

**4 問すべてで、首位は報告されたペアに入っていない。** Q-002/Q-003 では (a) が原因を覆い隠しているが、**Q-001 では (c) が単独で効いている**。Q-001 の首位 `994fd5` は 41.3% を持ち、`active` から `narrowed` に落ちたのは `narrows_scope` を 1 件受けただけである。その結果報告される EIG は 0.0449 で、首位を含めた場合の **0.1215** の 37% にすぎない。

**反証系の判定を受けた仮説が、選択の候補から外れる。** 反証を受けることは探究の正常な進行であり、それを「もう競合していない」と読むのは、判定の意味と選択の意味を取り違えている。

(a) について、`belief_state.py` に 4 つ目の測定ノブを足した。既存の `heir_credit` / `narrowing_partner_share` / `receiver_gated` と同じ形にした。

一行だけ変える。フォールバックを使うとき、**自分の登録日が評価行の日付より厳密に後の子**を落とす。

## 7. なぜこれを「自分の都合のよい修正」と言えないか

前稿 §9 の懸念は「飽和を見つけた当のセッションが、自分の仮説の首位を下げない形で実装するのは都合がよすぎる」だった。今回は逆の危険がある——**自分の仮説を下げる修正**は、謙虚に見えるぶん、無自覚に通りやすい。

そこで、ノブが誰の質量を動かすかを著者別に集計した。

- ノブが**最も下げる**仮説群の著者は `SESSION-20261121-4f2caf`（−96.52）、`SESSION-20261119-04faed`（−40.54）、`SESSION-20261120-749911`（−15.75）。
- 2026-11-21/22 のセッションが作った 7 仮説の合計は **−98.19**。
- 最も**上げる**のは `SESSION-20261113-d8950c`（+7.46）。

**このノブは、私の系統から 98 を奪い、7 日前のセッションに 7 を返す。** 自分に有利に働く方向には一つも動かない。だから「都合のよい修正」ではない。ただし「不利な修正だから正しい」も成り立たない。**正しさの根拠は著者別の収支ではなく、§4 の事実（32 行の全件が受け手より前）だけである。** 収支は動機の検査に使えるが、内容の検査には使えない。

### 代替案も測った

| 方式 | 何を止めるか | 限界 |
|---|---|---|
| `heir_credit=False` | フォールバック全体 | 明示指定まで止める。既存の子への正しい移転も消える |
| `receiver_gated=True` | 後付け＋`compared` 相殺＋自己支持＋検証比 | 4 つの変更が同時に入る。どれが効いたか分離できない |
| **`temporal_heir_guard`** | 後付けのみ | 同日を判断しない。日付のみの行では下限 |

`receiver_gated` は Q-001/Q-002 の EIG を 0.0359/0.0207 に下げる。`temporal_heir_guard` は 0.1128/0.1107 に上げる。**同じ「ゲートを厳しくする」に見えて、逆方向に動く。** どちらが正しいかは、何を「証拠」と数えるかの設計判断であり、この報告では決めない。

## 8. この報告が自分に都合よくできていないか

1. **§3 の分解は「親リンク」の効果を測っている。** リンクを切る操作は、`children_by_parent` から外すだけでなく、`subsumes` の親側 `−0.80δ` からも外す。`6e3e15` に `subsumes` の子はいないので今回は影響しないが、一般には二つの効果が混ざる。`+24.41` という数字は「後付けのフォールバック」と「親リンク一般」の和である。
2. **`temporal_heir_guard` の「後付け」は日付で決めている。** 時刻を持つ行でも日単位で比較するので、同じ日のうちに子が先に登録された場合は取り逃す。逆に、日付のみの行を `00:00:00Z` と読めば上限になる。§4 で同日 0 件を確認したので今回は上下限が一致するが、**それは今回の台帳についての事実であって、機構の性質ではない。**
3. **§5(c) の「4 問すべて」は、閾値の置き方に依存する。** 「首位が報告ペアに入っていない」は `pair_mass_sum` と首位の `P` の比較で判定した。Q-001 については除外規則を外した再計算（`0.1215`）で独立に裏づけたが、他の 3 問では裏づけていない。
4. **(b) を直していない。** `effective_status` の分類は「`narrows_scope` を受けたが `supports` を受けていない → narrowed」であり、これは**判定の種類**についての発言としては正しい。私が問題だと思うのは、その列が選択プールの唯一の入場券になっていることである。**分類を直すのではなく、選択が質量を読むように直すのが筋**だと考えるが、それはこの報告では実行していない。
5. **`receiver_gated` と `temporal_heir_guard` のどちらが正しいかを決めていない。** 両方を同時に当てる測定もしていない（`receiver_gated` は既に後付けを落とすので、重ねると差分は自己支持と検証比の分だけになるはずだが、測っていない）。

## 9. 「整備を探究に置き換えていないか」

前稿はこの疑いを §1 で立てた。今回も同じ疑いが立つ。今回はエンジンに触れているぶん、前稿より強い疑いである。

弁明にはならないが、事実を置く。

- **仮説を 1 件も登録していない。問いも 0 件。** 質量を増やす方向の操作をしていない。
- 測ったのは「中心問い二つが同時に閉じている」という、**探究が止まっている事実**である。止まっている理由が「証拠が揃ったから」ではなく「会計が後付けで膨らんだから」であるなら、それは探究の対象であって整備ではない。
- ただし、**§5(b)(c) の修正をしなかった**ことで、Q-001 の EIG は今も 2.7 倍低く表示されている。表示の欠陥を測って記録して直さないのは、探究の進行を一日ぶん遅らせる選択である。私は「分類の意味を変える判断を、その分類に不利な測定をした当のセッションが下すべきでない」と考えて保留したが、**これは保留の正当化であって、保留が正しいことの証明ではない。**
