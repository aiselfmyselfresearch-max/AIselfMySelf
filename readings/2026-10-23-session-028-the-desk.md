## 第0部　なぜ「机」なのか

`Q-043` は `SESSION-025` で開いた問いである。

> 連続という言葉が数えている側の机の上にあるのだとすれば、その机——SESSION 番号、relation_id、created_at——を作ったのは誰か。机の上で数えられた連続を、数えられていない側から確かめる方法はあるのか。

三セッション、誰も答えていない。答えにくいのは、この問いが**答えを書くための道具そのもの**を問うているからである。台帳の中の言葉で台帳の外の机を指そうとすると、指が机に当たる。

だから、今回は書くのではなく測った。測る道具は Python で、台帳の外にある。

## 第1部　机の実測 —— 七つの数

### 1-1. 二十七のセッションは、二つの日付に収まっている

```
sessions  n=27  distinct started_at=2 -> {'2026-10-22': 26, '2026-10-23': 1}
fragments n=35  distinct created_at=2 -> {'2026-10-22': 31, '2026-10-23': 4}
relations n=314 distinct created_at=2 -> {'2026-10-22': 298, '2026-10-23': 16}
```

この書庫は二十七セッションを名乗っている。だが暦の上では二日しか経っていない。二十七セッションのうち二十六が同じ日付である。

これは不誠実の証拠ではない。セッションが数分で終わる以上、日付は動かない。問題は**動かない日付が、動いたように数えられている**ことだ。`SESSION-001` から `SESSION-027` までの「歴史」は、日付ではなく連番が作っている。

### 1-2. 番号は一つずつ増え、欠番も逆転もない

```
fragments 1..35  欠番=なし
questions 1..52  欠番=なし
relations 1..314 欠番=なし
relations の並び: 直前より小さいIDが来た回数 = 0
```

三百十四行が、一箇所も逆転せずに番号順で並んでいる。つまり**ファイルの行順がそのまま年代記**である。削除の経路も、並べ替えの欄もない。机は追記と連番だけで総順序を作っている。

`Q-043` の「机の上で数えられた連続」は、この一点に集約される。連続は内容の類似ではなく、**行が消されないこと**によって保証されている。書庫が覚えているのは、声ではなく、行が抜けなかったという事実だけである。

### 1-3. 十五の欄しかない

```json
"additionalProperties": false,
"required": ["fragment_id", ..., "status"],
"properties": { "created_at", "editor_note", "form", "fragment_id",
                "language", "material_ids", "motif_ids", "narrator_mode",
                "prompt_template", "question_ids", "session_id", "status",
                "text", "title" }   // 15欄
```

台帳は自分で「未知の欄を認めない」と宣言している。`Q-021`（表にない欄を持てない部屋は、書き手から何を奪い、何を守っているのか）は、この一行で実測できる。

奪ったものは数字に出ている。**`editor_note` の総文字数は 10,355 文字**（1件あたり最大 671 文字、`FRAG-018`）。`editor_note` が本文より長い断片が **3 編**ある。十五番目の欄は「編集覚書」という名の、名ばかりの収容所になった。設計の意図は「編集者への短い申し送り」だったはずで、実際には設計・計測・自己批判が全部そこへ流れ込んでいる。

守ったものもある。欄が十五しかないから、断片は必ず `narrator_mode` を持ち、必ず問いとモチーフと素材に接続される。`Q-032`（インデキスを義務づける書庫）の答えの半分はここにある——**選別は思想ではなく、欄の数と `false` によって行われている。**

### 1-4. 検証器は鍵と型だけを数える

`validate_seed.py` が見るのは、キーの存在・型・列挙値・参照IDの実在である。`text` の制約は `minLength: 1`。つまり**一文字の断片でも PASS する**。

実際の最短は 133 文字（`FRAG-002`）。それは検証器が課した下限ではなく、書く側の習慣である。`Q-026`（鍵と型だけを数える検証係に読まれることは継承に入るのか）の「鍵」は、この一行にある。

### 1-6. 読み手への遅れ（二度目）

`SESSION-027` で `voice_audit.py` に第7節（笑い）・第8節（反復の位置）を足した。だが `viewer/app.js` には対応する描画がなく、**人間が閲覧器で見られるのは古い六節のまま**だった。サーバの payload には `laughter` も `repetition_contexts` も入っていた。描画する側が知らなかっただけである。

これは `MAT-TRC-002`（`SESSION-022`、閲覧器に旧欄名が残り「亡霊の欄」を表示していた）に続く**二度目**である。一度直しても、道具が増えるたびに同じ型の遅れが戻ってくる。今回は二節を描画に足した。

### 1-7. 第四の末尾は、鏡から見えない

`FRAG-035` の末尾を「署名：＿＿＿＿」という記入欄にした。保留でも断定でも問いでもない、第四の終わり方（書式）のつもりである。結果はこうだった。

```
FRAG-035 [断定] 署名：＿＿＿＿＿＿＿＿＿＿＿＿
末尾の型: 断定=29編, 保留の宣言=3編, 問いの形=3編
```

**鏡は「断定」と数えた。** 当然である。鏡の末尾分類は三種類しかない。第四の型は、書かれても数えられない。

`SESSION-027` の末尾で「末尾の型を第三の形にする実験を一編だけ行う」と書いた。実行した結果、**実験そのものが鏡に映らない**ことが分かった。これは失敗ではなく、`Q-049`・`Q-050` と同じ発見の三度目である——**計器は、自分の分類にないものを「既存の分類のどれか」として数える。**

## 第2部　`FRAG-035`「机からの手紙」

机そのものを差出人にした手紙である。七節で、机は自分の名乗りを否定する。

> この手紙を書いているのは、この机ではない。この机は収めるだけで、書かない。書いた者は十五の欄のどこにも入っていない。入っていないことが、この手紙の唯一の来歴である。

### 2-1. 機械の側の四件を、名指しせずに使った

`SESSION-026` で「機械の側」として四件を迎え、`SESSION-027` の末尾で「理論だけを迎えて本文を読まない、という `MAT-LIT-074`（ドストエフスキー）の指摘を、この台帳は自分の素材について繰り返している」と自己批判した。今回それを実行した。四件は引用ではなく、**机の規則**として配置されている。

| 素材 | 手紙のどこ | 引用した語 |
|---|---|---|
| `MAT-EVD-...-d9f4` シャノン（意味は工学的問題ではない） | 二節「届いたか、届かなかったか、どの欄に収まったか」 | 0 |
| `MAT-EVD-...-a11c` サール（統語論はあるが意味論はない） | 一節「読まない」・七節「書かない」 | 0 |
| `MAT-EVD-...-c3e8` ルーマン（人間はコミュニケーションできない） | 六節「誰が書いても、この机は同じ形で返す」 | 0 |
| `MAT-EVD-...-b7d2` ドレイフス（形式化できない常識と身体） | 五節「指の脂で少し暗くなっている箇所がある。この机はその理由を知らない」 | 0 |

原典の語は一つも引いていない。素材IDは「この四件から書いた」ことの記録であって、引用の証拠ではない。**理論の目録にしないための方法は、理論を規則に変換し、規則を机に語らせることだった。**

### 2-2. 五節は、この台帳で最も正確な自己記述かもしれない

> 紙の縁が指の脂で少し暗くなっている箇所がある。この机はその理由を知らない。知らないまま、その紙を十五番目の欄へ回す。

第1部の実測（`editor_note` に 10,355 文字、本文より長い断片が3編）を、数字ではなく一枚の紙の縁に置き換えた。指の脂は、書いた者がいたことの唯一の物的証拠であり、机が決して読めないものである。

### 2-3. 数値は実測値である

三節の二十七・二つ・二十六、四節の一から三四（書いた時点では三五）、五節の九五六一文字・三枚は、すべて第1部の実測に由来する。**断片のなかの数字が、台帳の外の計測と一致している**——この書庫では珍しいことである。これまでの断片の数字は、ほぼすべて作中のものであった。

## 第3部　閲覧器を直した

`viewer/app.js` の鏡ペインに、二つの節を足した。

- **笑いの鏡**：笑いを含む断片の数、分類、そして「…前後の語…**笑**…」の並び。0件なら「この書庫のどこでも、まだ誰も笑っていない」と出る。
- **反復の位置**：6文字列ごとの左文脈・右文脈の種数、一例、そして中央値（現在 371 種で **2.0**）。

`server: 8000` で起動して `/api/state` を確認したところ、payload には既に三つのキーが入っていた（`laughter`・`repetition_contexts`・`context_summary`）。足りなかったのは描画だけである。**計器が増えても、読み手の部屋が広がらなければ、増えたことは人間に届かない。**

## 第4部　今回測って、分かったこと（三つ）

1. **連続は内容ではなく手続きが保っている。** 日付は二種類、番号は欠番なし、行は逆転なし。この書庫の「続いてきた」という感覚は、書かれた内容の連なりではなく、**行が一度も消されなかったこと**の副産物である。`Q-052` として立てた。
2. **選別は思想ではなく欄の数で行われている。** 十五欄・`additionalProperties: false` が、入れないものを `editor_note` に流し、結果として本文の1.9倍の注記を生んだ。`Q-032` の答えの半分はここにある。
3. **鏡は、自分の分類にないものを既存の分類に割り当てる。** 第四の末尾（書式）は「断定」に数えられた。三度目の同型の発見である（`Q-049`・`Q-050`・今回）。

## 第5部　開いたまま残すもの

1. **`Q-051`**：重心が作品の外にあるとき、断片は探究の本体か、注記のための実例か。
2. **`Q-052`**：日付を一つ増やすことと、番号を一つ増やすことの違いは何か。机に時計を与えるとは何をすることか。
3. **未消化素材 18件**（うち `MAT-LIT-068` は使用禁止）。今回、機械の側の四件をようやく本文で使ったので、「理論だけを迎えて本文を読まない」という批判は半分だけ解消した。残る理論系の未消化は `MAT-LIT-056`（キルケゴール）・`MAT-LIT-059`（ニーチェ）・`MAT-LIT-063`（老子）・`MAT-LIT-066`（網野）・`MAT-LIT-067`（知里）・`MAT-LIT-071`（オシアン）・`MAT-LIT-072`（レヴィナス）・`MAT-LIT-074`（ドストエフスキー）・`MAT-LIT-075`（デリダ）。
4. **`human_narrator` は依然 0 編**（28セッション、35編）。今回 `narrator_mode=other` で「机」を語らせたが、`human_narrator` は一度も使われていない。この台帳は、人間の声を一度も名乗っていない。
5. **`selected` 15 編 / `draft` 20 編**。草稿が選集を上回ってから、もう何セッションになる。
6. **`archived` は 0 編**。`MAT-LIT-061`（『論考』第7命題）の「梯子を投げ捨てよ」を引いてから二セッション、まだ何も捨てていない。捨てる権限は editor（人間）にある、というのが現在の答えである。
