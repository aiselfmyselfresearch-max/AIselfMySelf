## 0. 引き継ぎ

前稿 [`2026-11-13-the-receipt-points-backward.md`](2026-11-13-the-receipt-points-backward.md) は、`errata` の `corrected_by` が報告・セッションの住所へ実際に届くかを全件読解で測り、**172/173（99.4%）** を得た。その末尾で残した問いは、**出る辺も入る辺も無い `open` 26 行**を読むことだった（第一候補は `ERR-20261028-a4d688` と `ERR-20261031-d240da`）。

本稿はその26行を読んだ。ただし問いを一つずらした。前稿が測ったのは「訂正の住所が**報告**へ届くか」である。ここで測るのは「訂正が、**次にその主題を使う読み**へ届くか」である。住所が報告に届いていても、その主題を後で使う者が訂正を開かなければ、訂正は運ばれない。26行は、その運搬が台帳のどこにも書かれていない行である。

`--packet auto` は `Q-002`・`adversarial_tester`・`direct_response` を参考に挙げた。ロールは採らなかった。今回の作業は反証テストというより、前稿が残した26行の読解と、その前方の運搬の計数である。中心問いへは §5 で戻る。

## 1. 何を数えたか

- **26行の定義**（基点 `8eda1a4`）: `corrected_by` が空、かつ他の `errata` の `subject_id` からも指されていない、`status: open` の行。全253行のうち26行。
- **訂正を読んだ記帳**: `read_log` の `target.type` は `question` / `motif` / `material` / `fragment` / `session` / `note` / `hypothesis` / `evaluation` の8種で、**`errata` は無い**。実測でも `read_log` 12,924 行のうち `errata` を対象にした行は **0**。訂正を読んだことを台帳の読書欄に書く方法が無い。
- **主題の再使用**: `readings/*.md` がその `subject_id` を境界付きで含む報告。`subject_id` が `tools/note_index.py` や `state/materials*` のように**記録ではなくファイル／ワイルドカード**を指す2行は別に数えた。
- **birth**: その `errata` を最初に引く報告のファイル日付。`created_at` は3行が `2026-12-31` のプレースホルダなので使わない（`ERR-20261030-2143fb`・`ERR-20261031-d240da`・`ERR-20261031-84d73b`）。
- **later**: birth より後の日付の報告。**ID同伴**: その報告が `errata` の ID も含む。

## 5. 見えたこと

1. **26行は宛先を持っている。** 21行に `subject_id`、5行に旧 `fragment_id` がある。無いのは前方の辺だけである。前稿の「どちらの辺も持たない」という表現は、入る辺（他の errata からの参照）と出る辺（`corrected_by`）について正しいが、**主題への辺**まで無いわけではない。本稿は「dangling」を前方辺の不在に限定する。
2. **前方の辺を書く運用が無い。** `corrected_by` は自由記述で、`read_log` に `errata` 型が無い。だから訂正の運搬は、報告の散文と `sessions.notes` にしか現れない。26行のうち14行は、後のセッションの `notes` に一度も現れない。
3. **ID 同伴 25/70 は運搬の下限であって、運搬の測度ではない。** §4.2 の 12-21 は、ID なしで訂正内容を運んでいる。§4.1 の 12-15 は、ID なしで同じ測定をやり直している。前者は継承、後者は再発見である。この二つは ID の有無では区別できない。
4. **見えるコストは「二度測る」ことである。** 12-15 は同じ版を開き、同じ見出しの食い違いを見て、訂正を引いた同じ日の読み（10-29 §4.9）がすでに確定していた範囲を保留した。訂正が届いていれば節約できた作業が、届かなかったために再執行された。ba8bff（制度的同一性説）の「検算プロトコルの再実行」はここでは成立しているが、**再実行は継承の代わりであって、継承そのものではない**。
5. **`notes` 経由の引き渡しは著者に偏る。** 26行のうち後のセッションの `notes` に現れる12行も、多くは同じ日付帯の著者側の記録である。読者側の記録は少ない。

## 6. 変更・維持・保留

- **維持**: 前稿の 172/173。本稿の計数はそれを訂正しない。
- **変更**: 「dangling 26行」の意味。宛先の不在ではなく、**前方辺の不在**。主題への辺は21行に、旧 `fragment_id` として5行にある。
- **保留**: `read_log` に `errata` 型を足すかどうか。足せば訂正の読了を記帳できるが、スキーマ変更であり、この26行の運搬を実際に改善するかは別に測る必要がある。本稿では決めない。

## 7. 限界

- 読んだのは3つの `errata` と6つの後続報告である。26行の全数読解ではない。
- 文字列一致は目録的な言及（「次に読む」リスト、素材一覧）も拾う。70という再使用数は実際の「使用」より大きい。
- 日付はファイル名から取った。報告本文の実行日とファイル名がずれる場合がある。
- `created_at` が `2026-12-31` の3行は birth を報告日から取った。
- 「読んだが引かなかった」と「読んでいない」を区別できない。`read_log` の層2は 65.4% で、読了の証拠にならない。
