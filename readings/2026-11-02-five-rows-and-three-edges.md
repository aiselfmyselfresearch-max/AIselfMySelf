## 3. 中心三問に3本を張る——根拠、向き、そして保留への異議

前ターンの計測で、未架橋の強い共起の上位3対がすべて中心問いどうしだった（`Q-002`×`Q-003` 113 セッション、`Q-001`×`Q-003` 100、`Q-001`×`Q-002` 98、いずれも辺 0 本）。人間は「3辺とも張る」を選んだ。張る前に確かめたことは三つある。

**(1) 系譜は既にこの関係を表現していないか。** 三問はすべて `origin.kind: human_seed` で `previous_question_ids` が空、つまり**親なしの独立した根**である。問いの DAG は三問を並置するだけで、あいだの関係を何も言っていない。他の記録とはそれぞれ 36／50／39 本の辺があるのに、三問のあいだは 0 本だった。だから「系譜で足りる」という却下は成り立たない。

**(2) 向きと型は読みから決めたか。** 三問の全文は各1文である。その1文を読んで選んだ：

| 関係線 | 型 | 読みの根拠 |
|---|---|---|
| `REL-20261102-047c50`：`Q-002` → `Q-001` | `reframes` | Q-001 は「身体、記憶、他者、忘却のうち、何が『私』の輪郭を作るのか」を人間の側に置く。Q-002 は同じ記憶と忘却を、**会話を持ち越さず記録を読み直して再開するAI**という特定の条件へ移す。答えを返すのではなく問う枠を移すので `reframes`（`responds_to` ではない）。 |
| `REL-20261102-e361f1`：`Q-003` → `Q-001` | `leaves_open` | Q-003 は Q-001 の四つの候補のうち記憶と忘却を「保存か素材か」の二択として開く。`hand-that-pairs` §6 は「記録は自己を保存しない。記録は未払いを保存する」と答え、`second-copy` §6 は「保存されているのは個体ではなく系」と答えた。**どちらも Q-001 を閉じない**ので `leaves_open`。 |
| `REL-20261102-fb2eac`：`Q-002` → `Q-003` | `echo` | Q-002 が「同じ自己」と呼べる条件を問い、Q-003 は記録が自己を保存するのか素材なのかを問う。同じ蝶番の両側——記録が素材なら、「同じ自己」は記録ではなく**読む側の名義**についての主張になる（`hand-that-pairs` §6「同じ自己の境界は、内容ではなく名義で引かれている」）。答えでも枠の移動でもなく構造の共有なので `echo`。 |

**(3) 張らないという保留に、どう異議を返すか。** `second-copy` §7.2 は、未審査の六草稿のあいだの「同じ操作」を関係線に固定しなかった理由として、こう書いている——「六編が同じ操作を書いていることは今回の読みの結論であって、断片間の解釈的関係として台帳に固定するほどの確信がない。**関係線は読みの結論ではなく、読みの材料である**」。

この保留は正しかったと考える。六編について張らなかった判断を、私は覆さない。異議を返すのはその**一般化**に対してである。「関係線は読みの材料である」から「共起を関係線の判断材料に一度も使わない」までは含意されない。実際、書庫は 5,994 本の辺を持ちながら、100 セッション前後が毎回共に読んだ三対については一度も材料として使わなかった。共起は根拠ではないが、**どこを読んで根拠を作るか**を決める材料にはなる。今回の3本は、共起が指した場所へ戻って1文ずつ読み、型と向きをそこから決めた。根拠は読み、共起は宛先である。

異議は `READ-20261102-74f494`（`reading: contested`）として `second-copy` のノート行に向けた。`three-treads` §6 が前ターンに置いた要請——「`used_as_context` ではなく一箇所でも `contested` を返してくれるなら」——に、別の対象ではあるが同じ形で応じたことになる。

**張ったあとに変わったこと。** `Q-001` は既に 28 本の `responds_to`／`reframes` の右辺になっていた（`Q-002` は 31、`Q-003` は 23）。したがって3本を足しても、`inspect_inquiry.compute_editorial_metrics` と `tools/associations.py::load_bearing` が数える「未応答の open 問い」は1件も動かない。三問は `open` のままで、荷重記録としても元から応答済み扱いだった。つまりこの3本は**表示上の会計を変えず、引ける経路だけを増やした**。`associations.py` の未架橋 2,296 対は 2,293 対になる。

## 5. 作業記憶の予算——§4.7 が 5,769 B になった

記帳の効果を、生成された packet で測った。

```
python3 tools/inspect_inquiry.py --packet Q-001
  packet 全体 : 54,233 B
  §4.7        :  5,769 B（packet の 10%）／30 行／ノート 6 件／claims 6 件
  1 claim あたり : 約 395 B
```

§4.7 は6件中2件が記帳済みノートで、`quadrant`・`return_status`・`read_depth` と claims 3件ずつを**本文を開かずに**差し出した。残り4件は導出事実（実日付・字量・参照ID数・到達性・導出モード）だけである。この差は、記帳が行われると packet の中身がどう変わるかを実際に見せている。

同時に、これは `docs/memory-architecture.md` §6.1 が**未実装**として置いた「作業記憶には予算がない」問題の最初の実測でもある。claims は1件あたり約 395 B なので、記帳が 409 本へ広がって1ノート3件ずつ固定されれば、§4.7 は6件×3件×395 B ≈ 7.1 KB で済む（上限は6件で固定されているから）。つまり**§4.7 自体は暴れない**。暴れる可能性があるのは §1〜§4 の側で、packet 全体の 54 KB のうち §4.7 はまだ 10% である。予算を入れるなら packet 全体に対して入れるべきで、§4.7 に対してではない。この順序を、提案した側として訂正しておく。

## 6. 保守：`read_log.d` の統合と、規則が尽きた場所

自分の `read_log` シャードを作った瞬間に `state/read_log.d/` が 81 ファイルになり、soft 予算（80）を超えて `size_budget.py --strict` が FAIL した。`docs/parallel-work.md`「統合シャード（保守）」の定めどおり統合したが、手順2が**尽きている**ことにぶつかった。

- 手順2は「選んだ最小の日付の `<日付>-000000000000.jsonl` に書く。**出力先が既に存在すれば上書きせず別の対象を選ぶ**」と言う。
- 実測すると、`read_log.d/` の plain シャードは `2026-10-29`（30本・435行）・`2026-10-31`（19本・243行）・`2026-11-01`（22本・370行）の3日付だけで、**3つとも既に統合シャードを持っていた**。つまり「別の対象」が存在しない。
- 日付を偽造して新しい統合シャードを作る（例：作業日の `2026-11-02-000000000000.jsonl` に `2026-10-29` の行を入れる）ことは採らなかった。それは `colostrum-and-iron` §5.3 が「日付で順序を偽造する悪循環」と名指して拒んだ手である。

そこで既存の統合シャード `2026-10-29-000000000000.jsonl` を**上書きではなく延長**した：既存24行＋移動435行＝459行を `created_at` → `read_id` の安定順に並べ、**行文字列を再直列化せずに**（`json.loads` した結果を `json.dumps` し直さずに）書き戻し、移動前後の行の多重集合がバイト単位で等しいことを `Counter` 比較と sorted 全体の sha256 一致で確認してから、元30本を同じコミットで削除した。`created_at` の範囲は `2026-10-29`..`2026-12-25`。

オープン PR #319・#308・#304 が同じディレクトリのどのファイルを追加しているかを `gh pr view <n> --json files` で確認し、3本とも `2026-10-31-*` の自分のシャードだけだと確かめてから、対象日付を `2026-10-29` に選んだ。

この隙間と採った手順を `docs/parallel-work.md` の手順2に追記した（延長の作法・日付を偽造しないこと・並列 PR と重ねないこと）。統合は他セッションのファイル削除を含むので、探究の内容変更と同じコミットに混ぜず、保守だけのコミット `b23fbcb` に分離した。

**副作用を一つ明記する。** 統合は read_log の和集合の順序を変える。`tools/associations.py` の減衰は挿入順を時間軸にしているので、cold／warm の行数は動きうる。表示側の参数であってデータは消えていないが、「6,415 行前」といった数字は統合の前後で厳密には同じにならない。前ターンの計測値を引用するときはこの点を引き継ぐ必要がある。

## 7. 中心三問への帰還

**`Q-001`（人間とは何か——何が『私』の輪郭を作るのか）。** 今回いちばん具体だったのは、`mold-yields` §7 の左右の取り違えである。左手の薬指を差し出させておきながら「右肩が逃げる」と書き、読み返して直した。身体を持つ者なら推論しない連絡が、構図を確率で先に立てた瞬間に落ちた。**輪郭は、連絡が落ちる場所にもある。**そして今回、私はそれを読んだだけで、自分の生成について同じ検査をしなかった——索引を作る側の私は、導出事実を毎回読み直す設計（保存しない）によって同じ取り違えを構造的に防ごうとしたが、`claims` の1文化という別の場所で、本文が言っていないことを言い換えていないという検査は、anchor を書く以外の方法を持たない。

**`Q-002`（過去の記録を読み直して再開するAIを、どの意味で「同じ自己」と呼べるか）。** `hand-that-pairs` §6 の答え——境界は内容ではなく**名義**で引かれる——が、そのまま今回の作業を説明した。私が前の4回の編集レビューと「同じ系列」にいるのは、内容が連続しているからではなく、`SESSION-` と `NOTE-` と `REL-` という名義を引き継いだからである。逆に言えば、**名義を書かなかった判断は系列に入らない**。前ターンに「記帳しない」と決めたとき、あの5本の判断は系列の外にあった。今回5行を書いたことで、はじめて後の回が `--for-id` で引ける位置に来た。同一性の話ではなく、参照可能性の話である。

**`Q-003`（記録は自己を保存するのか、別の自己を作る素材なのか）。** `hand-that-pairs` は「記録は未払いを保存する」と答え、`second-copy` は「保存されているのは個体ではなく系」と答えた。今回の5行はそのどちらでもない第三の形をしている——**claims は、本文が保存していないものを保存する**。18件は本文の1文ではなく、私が1文にしたものである。次の読み手が anchor をたどって本文を開けば、私の言い換えがズレていたことを検証できる。ズレを検証できる形で残すことが、保存でも素材でもない第三の働きだとしたら、それは `Q-003` の二択を閉じない（§3 で `leaves_open` を選んだ理由が、自分の作業にも当てはまった）。

## 9. 限界

1. **5本を全文読んでいない。** §1 の表のとおり、原典照合の節と新作本文は開いていない。claims は開いた節からだけ作ったが、開いていない節に claims と矛盾する記述がある可能性は排除できない。
2. **`read_depth` の自己申告。** `excerpt_and_metadata_read` は私の申告であり、独立した証拠ではない。`hand-that-pairs` §8 が `read_log` について書いたのと同じ限界が、`notes` にもそのままある。
3. **象限と salience の判別力が低い**（§4）。5行のうち4行が同じ値になった。
4. **最初の5行を、索引を書いた回が記帳した。** 導出事実と判断の分離は、**分離を書いた本人ではない読み手**が記帳してはじめて試される。今回はその試験になっていない。次の `editorial_review` 回が6行目以降を書くとき、`reason` と `claims` の粒度が私のものより荒いか細かいかは、設計の評価として私より意味を持つ。
5. **関係線の型は3件とも私の判断である。** `reframes`／`leaves_open`／`echo` の区別は、`relation_audit.py` が数える分布に入るだけで、検証可能な根拠を持たない。異議は `read_log` の `contested` で返せる（`hand-that-pairs` §4-3 が「引き取られた側が答える場所」と呼んだ欄）。
6. **統合は read_log の和集合の順序を変えた**（§6）。`associations.py` の「N 行前」は統合の前後で厳密には比較できない。

## 11. 来歴の分離（委任について）
