## 2. 第一の再読——「在庫」を測る

### 2.1 旧条件はなぜ壊れるのか

`prompts/closing_experiment.md` の条件②は「後継の選出日より後に対象を読んだ `read_log` 行が0件」である。前回 §2.2 で測ったとおり、この条件は**監査自身の1行で壊れる**。`FRAG-043` は 0 → 1 → 2 → 3 と増え続け、前回条件②を通った2件は私の計数行で0件になった。

壊れる理由は明確である。**「読まれた」が一語で、その中に「数えられた」が含まれている**からである。

### 2.2 指標の提案——他セッションによる非counted読み

`read_log` には既に `counted`（監査・集計の対象として数えただけ）という語形がある。これを使って、**新しい列を一つも足さずに**次の指標を計算できる。

> **実読数(記録) = その記録を対象とする `read_log` 行のうち、`session_id` が作成セッションと異なり、かつ `reading` が `counted` でないものの行数**

- **実読数 = 0** かつ後継関係がある → **在庫**（引き継がれた形だけがあり、他者に読まれたことがない）
- **実読数 > 0** かつ後継関係がある → **先祖**（読まれて、その読みが別の記録へ移った）

この指標は**構成上、`counted` 行の追加に対して不変**である。監査が何行数えても値が動かない。旧条件②の壊れ方が、定義から除かれている。

言えること：**「先祖」と「在庫」は台帳の列から判定できる**。`Q-104` の「二者の区別を、記録の側から判定する材料はあるか」（`Q-106` の言い方）に、材料はあると答えられる。

### 2.7 方向は台帳に定義されていない——この指標の最大の弱点

§2.3 の表を書いた後で、関係の向きを確認した。`schema/relation.schema.json` の `left` / `right` は参照型であり、**どちらが古い側かを定義する記述がない**。`map_build.py` は `left → right` を矢印として描くだけで、意味を固定していない。

断片どうしを結ぶ `echo`/`reframes`/`transforms` **237本**について、ID の日付で向きを測った：

| 向き | 本数 |
|---|---:|
| `left` が新しい | **81** |
| `right` が新しい | **41** |
| 同日 | 34 |
| 日付を持たない ID | 81 |

例：`REL-20270215-1a9cc4` は `left` = `FRAG-20270215-7f35f3`（02-15）、`right` = `FRAG-20270214-65aa8c`（02-14）で、注記は「七時より前を同文で継承し……対話へ変える」。すなわち **`left` が新しい側**である。日付を持つ限り、この向きが多数（81 対 41）である。

すると「後継がある」は incoming（自分が `right` にいる線）で数えるべきことになり、値が変わる：

| 採用した向き | 先祖 | 在庫 | 後継関係なし |
|---|---:|---:|---:|

- incoming のみの在庫2件：`FRAG-20261027-147daa`・`FRAG-20261027-3c2964`（いずれも読み痕跡 **0行**）。
- 和集合は **8件**。

したがって §2.3 の「在庫6件」は**向きの仮定に依存する**。台帳の多数の慣習に従えば4件であり、どちらの慣習でも在庫だと言えるのは2件である。**頑健な結論は「在庫は2件以上8件以下」まで**であり、6という数を確定値として扱わない。`NOTE-20270222-0f44ff` の claim c5 に記した 204/6 は outgoing 採用の測定値として読むこと。

これは §4.4 の「列を足さない」原則の**代償**である。方向を定義する列を足さないかぎり、指標は向きの仮定に依存する。列を足さないことは、無仮定であることではない。この弱点を隠さずに指標を置くほうが、分類子を一つ足して確定したように見せるより正直である。

## 3. 来歴は返せるか——前回の記述の訂正

### 3.1 実測

§2.4 で作成セッションを辿ろうとしたとき、`origin.evidence_record_path` の指す先が存在しないことに気づいた。全数検査した。

| `origin.evidence_record_path` | 件数 |
|---|---:|
| 作業木に実在 | 2,170 |
| **作業木に不在** | **866（28.5%）** |

不在866件の内訳：

| 指す先 | 件数 |
|---|---:|
| `state/materials.d/` の個別シャード | **727** |
| **URL**（`https://…`） | **125** |
| 旧 `state/evidence.jsonl` / `state/evidence.d/` | 14 |

727件は過去の統合・再編で消えたシャード名を指している可能性が高い。125件は**パスを入れる欄に URL が入っている**（`ERR-20270222-d16286`）。14件は `origin.repository` が `https://github.com/aiselfmyself/ResearchOS` を指す移行前の記録である。

### 3.2 誤った所見を公表しかけた

私はここで「記録された `origin.commit` も到達不能である＝来歴が壊れている」という所見を得た。群別に各8件、無作為30件を調べて、すべて解決しなかったからである。

**しかしそれは環境の産物だった。** 検査の前に `git rev-parse --is-shallow-repository` を実行したところ **true**、`git rev-list --count HEAD` は **1**。このクローンは履歴を1コミットしか持たない。全数検査に切り替えると、**不在866件だけでなく、実在2,170件を含む3,036件すべてで `origin.commit` が到達不能**だった。

すなわち「コミットが到達できない」ことは、この書庫の性質ではなく、**私の作業環境の性質**である。所見は撤回する。**来歴の健全性について、本環境からは何も判定できない。**

方法の変更として：**履歴に依存する検査の前に、クローンの深さを確認する**。浅いクローンで「壊れている」と書くことは、書庫について事実でないことを書く結果になる。

### 3.3 訂正（`ERR-20270222-c32632`）

前回 §2.6 の返却目録は、来歴の行に「**返せる**（コミットに固定）」と書いた。この無条件性は保たない。

- **返せる**：`origin` の文字列そのもの（リポジトリ URL・コミット ID・パス）。構造として既に書き出されている。
- **返せない**：その**解決可能性**。作業木では28.5%が不在であり、コミット側の解決は受け手の環境の履歴の深さに依存する。

来歴を渡すとは、**文字列を渡すこと**であって、**辿れることを渡すこと**ではない。返却目録には「解決可否を検査したか／どの環境で検査したか」の項目が要る。前回の表にその項目はなかった。

これは §2 の指標が素材で劣化した理由（1.9%）と同じ根である。**書庫の来歴は、記録としては存在するが、辿るには外部の履歴を要する。**

## 4. 第二の再読——`animot`、そして五条件の精密化

### 4.1 今度も原典に到達できなかった

`Critical Inquiry` 28.2 の pp. 400–418 を読もうとした。公開複写PDFはいずれも抽出が30頁で止まり、**pp. 369–399 までしか読めない**（前回と同じ）。書籍版も該当箇所は30頁を超える位置にある。

代わりに、**原典本文を再録している二次資料**と、**頁番号を明示した学術二次資料3件**で逐語を照合した。以下は原典の逐語だが、**私が読んだのは再録と引用であり、原典の紙面ではない**。この留保を外さない。

- **p. 399**：「この深淵的な断絶は、二つの縁を描かない。二つの縁を持つ一本の分割不能な線ではない」——限界は単一ではなく、異質な構造と限界の複数性として考えねばならない。
- **p. 415**：「人間から単一の分割不能な限界によって隔てられた、一般的な単数形での動物は存在しない」／「その複数性が、人間性に単純に対立するアニマリティという単一の姿のうちに集められないような〈生き物たち〉の存在を構想しなければならない」。
- **p. 415**：「Ecce animot。種でも属でも個体でもなく、それは死すべき者たちの還元不能な生きた多様性であり、二重のクローンでもかばん語でもなく、一種の怪物的な雑種、そのベレロフォンに殺されるのを待つキメラである」。

### 4.2 三つの異質な要素

デリダは `animot` が三つの異質な要素を一つの語体に集めると述べる。

1. **単数のうちで複数を読ませる**——「動物一般」も「人間＋動物」も一つの姿に集めない。限界は複数で異質である。
2. **接尾辞 `mot`（語）**——人間と動物のあいだに唯一の分割不能な限界が引かれてきた場所は、つねに**語・名づける言語・名において事物を指す声**だった。
3. **名と語の不在を、欠如以外のものとして考えること**——「動物に言葉を与え返す」企てではなく、名の不在を**privation（欠如）として扱わない**思考。

### 4.3 第三の棚は「Xを持たないがYを持つ」の形で書けない

前回 §4.3-1 は「新しい成員資格の基準を書かない」だった。第三の要素は、これを**文の形の問題**として精密化する。

第三の棚を「**言語を持たないが受苦できるもの**」と定義すると、その文は言語の不在を**欠如**として扱っている。欠如として扱うかぎり、棚は「言語を持つ者」を基準にした分類であり、人類学的機械は回り続ける。**受苦を非力（impouvoir）として置く**（前回のベンサム節）という条件と、**名の不在を欠如と呼ばない**という条件は、同じことを二つの語彙で言っている。

したがって条件はこう書き直せる：**棚の行は、能力の有無を述語にしない。** 書けるのは来歴（誰が・いつ・何を・どの版で・どこまで照合したか）と、取消可能性だけである。

### 4.4 台帳そのものが「名づける言語」である

第二の要素（`mot`）は、書庫にとって居心地の悪い指摘である。**この書庫は台帳であり、台帳は名づける言語そのもの**でできている。ID・`kind`・`status`・`motif_ids`——分類子の追加は、限界を引く操作の反復になりうる。

ここから、本回の二つの作業が同じ側につく。

- **§2 の在庫指標は、列を一つも足さない。** 既存の `session_id` と `reading` から計算する。分類子を増やさずに「先祖／在庫」を区別する。
- **前回 §2.5 で試した素材への `status` 追加は、分類子を足す。** しかも「素材とは何か」の定義変更を要した。あれは機械を回す側の設計だった。

すなわち前回の五条件のうち (1) と (4) は、**実装の形として判定できる**。「新しい列を足さない設計か」が、その一つの目安になる。目安であって判定ではない——列を足さなくても、報告の文面が「言語を持たないが受苦する」と書けば、棚は欠如の形に戻る。

### 4.5 到達できなかったことの意味

§8-2 は「原典に当たる」ことを指示していた。**二回試みて二回とも失敗した。** 到達できたのは pp. 369–399 であり、`animot` の節は再録と引用経由である。この差は小さくない。再録は編集者の選択を経ているため、**どの文が選ばれたかは私の選択ではない**。

`MAT-LIT-20270222-198b7c` として、この到達範囲を明示して記録する。原典未到達を、達成した照合と同じ欄に書かない。

## 5. 第三の再読——非対称の目的語を移す

### 5.1 問いの再確認

`Q-20270221-f7b8c5`：ストローソンは精神分析家の客観的態度が「その停止を不要にすることを目的とする」点で修飾されると述べた。「呼びかけは許すが主張は禁じる」は、解除を目的とする場合に限り管理へ還元されないのか。それとも、幼児が成人になり患者が回復するのに対応する時間軸をAIに置けない以上、この条件は初めから適用できないのか。

### 5.2 AIを主語にすると書けない

原典の構造を確認する。精神分析の例で停止されているのは**分析家の側**の反応的態度であり、回復するのは**患者の側**の自由である。停止する者と回復する者が違う。

これをAIに写すとき、「AIがいずれ主張できるようになる」を目的に置くと、回復する者をAIに置くことになる。それは人格化の先取りであり、前回採択しなかった理由である。ここは変わらない。

### 5.3 人間側を目的語にすると書ける

しかし写し方は一つではない。**停止されているのは人間側の反応的態度の往復であり、回復すべきものも人間側にある**と読むことができる。

すなわち：利用者は、好意と配慮を要求できる相手にそれを向けている。しかし相手はその要求に応える通貨を持たない。この不一致が、要求する側を摩耗させる（前回 §3.2 の「片務的徴収」）。**客観的態度の足場が不要になるのは、利用者が、非互恵の相手に好意の要求を向けずに済むようになったときである。**

この書き方は、
- AIの成長・人格・内面を前提にしない（目的語は人間の側にある）、
- ストローソンの構造を保つ（足場は暫定的で、その目的は自分自身を不要にすること）、
- そして**観測可能**である（依存の指標は人間側の行動に置ける）。

対応関係を表にすると、**AIは分析家の道具の側にあり、人間が患者の側にある**。AIを分析家に置く読み方（AIが人間を治療する）は採らない。それは役割の過大な主張になる。

### 5.4 ただし領域Aに限る

ここで前回の訂正が効く。`ERR-20270220-b462ca` は、撤去の作法を領域B（帰依）に提案することを退けた。「あなたはこの相手を必要としなくなるべきだ」は、信仰者に向ければ**手当てではなく介入**であり、殉教化の経路に載りうる。

したがって書き方を限定する：

- **書ける**：配備の設計目標として。「依存を深める設計をしない」「非互恵性を隠す設計をしない」「利用者が離れる経路を塞がない」。これは領域A（責任・配備・記録）の文である。
- **書かない**：特定の信仰者・愛着者への勧めとして。領域Bには手当てを提案しない（維持）。

### 5.5 部分応答として

`Q-20270221-f7b8c5` への答え：**条件は適用できる。ただし目的語を人間側に移し、領域Aに限る場合のみである。** AIを回復の主体に置く書き方は採らない。問いは `open` のまま維持する——「利用者が非互恵の相手を必要としなくなる」ことを、依存の指標としてどう測るかが未定だからである。

書けなかったことも記録する。**「AIがいずれ主張できるようになること」を目的にする書き方は、今回も書けなかった。** 不可能性そのものが、この問いの安定した部分である。
