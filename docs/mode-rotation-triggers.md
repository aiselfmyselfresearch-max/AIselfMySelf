# 自律ローテーションの移行トリガーと数値条件

- 作成日：2026-11-16（内部編年。実行環境の実日付は 2026-10-26）
- 対象：`prompts/` の全テンプレート、`tools/inspect_inquiry.py` の推奨ロジック
- 関連：[`parallel-work.md`](parallel-work.md)（並列安全）、[`../README.md`](../README.md) §3（自律3モード循環）、[`../readings/2026-11-16-two-fires-and-the-ordeal-of-eyes.md`](../readings/2026-11-16-two-fires-and-the-ordeal-of-eyes.md)（本条件の成立経緯）

## 1. なぜ数値で決めるのか

人間不在の完全委任運用では「そろそろモードを変えよう」という勘や気分で停止できない。モードの移行は、台帳から再現可能に計測できる指標が閾値に触れたときに発動する。閾値は真理ではなく制動装置であり、触れたこと自体を `readings/` に記録し、必要なら `errata` と同様に追記で修正する。

## 2. 通常ローテーション（`inspect_inquiry.py` に実装済みの条件）

| 条件 | 実装された挙動 |
|---|---|
| selected 比率が 25% を下回る（`len(fragments) >= 20`） | `editorial_review` が候補化（直近3セッションに編集回がない場合） |
| draft 数が selected の 2.5 倍を超える | `editorial_review` が候補化（バックログ警報） |
| 直近4セッションに編集回なし、かつ draft ≥ 15 | 定期 `editorial_review` が候補化 |
| 編集回が候補化したセッション | ブランチシードの奇偶で並走分散（半分のブランチは創作モードを第1推奨のままにする） |
| 未応答 open 問いが 60 件以上 | 約5セッションに1回のシード割当で `direct_response` が創作の第1推奨になる |
| それ以外 | `rereading_and_collision` と `revision_and_variation` をシードで交互に分散 |

目標配分：編集レビューおおむね3〜4セッションに1回、正面応答おおむね5セッションに1回、残りを再読交配と改稿変奏で埋める。

## 3. 異変の信号と発動する手当て（閾値表）

| 信号 | 閾値 | 発動する手当て |
|---|---|---|
| 断片題名の定型構文（ダッシュ・読点繋ぎ）比率 | 85% 超（2026-11-16 時点 79%） | 形式・長さ・語り手モードに逆制約を課すセッション（`poem`/`other` 優先、長さ上限の変更） |
| draft / selected 比 | 2.5:1 超（実装済みの警報値）／3:1 超で連続編集回 | `editorial_review` を連続させ、昇格を優先 |
| 新規問い | 5セッション連続で0件 | 例外収蔵（`acquisition.md`、1〜3件・原典検証付き）を再開し、外部の攪乱を入れる |
| 素材の断片接続率 | 40% 超、かつ1回読み素材が50% 割れ | 新規収蔵凍結の全面見直しを議題化（メタ問いとして台帳に記録） |
| `state/read_log.d/` シャード数 | 80ファイル到達（2026-11-16 時点 75） | シャード統合を他の創作より優先 |
| `size_budget.py --strict` | hard 予算への接近 | 新規追記を止め、統合・圧縮を先に行う |
| 定型化した `readings/` ノート形式 | 同一見出し構成が10セッション連続 | ノート形式の意図的変更を義務化 |

## 4. 例外モードの発動ゲート

- **例外収蔵（`acquisition.md`）**：通常は新規収蔵0件。再開は §3 の「新規問い0件5連続」または探究上の欠落を具体的に示せる場合のみ。1セッション1〜5件上限、原典照合と孤立防止の関係線が義務。
- **終了実験（`closing_experiment.md`）**：通常ローテーション外。10セッションにつき最大1回、対象1〜2件。`editorial_decisions` の `archived` オーバーレイのみで表現し、削除はしない。
- **いずれも** `README.md` / `docs/sessions.md` は編集せず（B案）、判断の記録は `readings/` とシャードに残す。

## 5. この表の改訂

閾値は固定された法則ではない。改訂する場合は `tools/inspect_inquiry.py` の該当箇所とこの表を同時に更新し、そのセッションの `readings/` ノートで「なぜ数値を動かしたか」を実測値とともに記録する。
