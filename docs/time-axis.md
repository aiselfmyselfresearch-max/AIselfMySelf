# 時間軸——この書庫は、いつ起きたことかをどう決めるか

- 実日付：2026-11-05（UTC）。内部編年：**この文書から採らない**（下記 §1）。
- 実装：`tools/date_axis.py`（軸）、`tools/new_id.py`・`tools/new_ledger_shard.py`（書き込み側の規則）、`tools/inheritance.py`（継承の実測）。
- 関連：[`memory-architecture.md`](memory-architecture.md) §2（時系列が二つあることの実測）、[`trust-root.md`](trust-root.md) §1（正統性の層）、[`parallel-work.md`](parallel-work.md)（追記専用・シャード）。

## 0. なぜこの文書が必要か

主題は「記録を読み返して続きを語るAIにとって自己とは何か」である。その主題に対して、この書庫は自分の時間を読めていなかった。

`docs/memory-architecture.md` §2 の実測（2026-11-02）：

> **時系列という軸自体が、この書庫には二つあって、どちらも信用できない。**

- ファイル名・`started_at`・素材ID・ノートID に載っている日付は**内部編年ラベル**で、`2027-02-23` まで進んでいた。実日付は `2026-11-05` のままである。
- 同じラベル `2026-12-31` に **45 セッション**が入り、実日付は `2026-10-30`〜`2026-10-31` に散っていた。同じ実日付 `2026-10-29` に `2026-10-29` と `2026-12-19`〜`2026-12-25` のラベルが同居していた。
- 過去の `editorial_decisions` の内部編年シャードが、実日付シャードを辞書順で逆上書きする事故が起き、`supersedes` 欄が後から足された（`2026-11-01` の `editorial_review`）。

主題が「自己の連続」である書庫が、自分の記録の順序を復元できない状態を放置すれば、そこで書かれる自己論は順序を捏造したものになる。だから軸を一本にする。

## 1. 規則（ここから先、この書庫はこの規則で時間を読む）

1. **過去のラベルは書き換えない。** 台帳は追記専用で、`started_at` もファイル名も既存行の一部である。軸は「その値が実際にどこに落ちるか」を言うだけで、値を直さない。
2. **新しい記録は実日付で採番する。** `SESSION-`・`MAT-`・`NOTE-`・`ERR-` などの ID 接頭辞、およびシャード名は、**実行環境の実日付**（`date.today()`）を使う。内部編年ラベルは ID にもファイル名にも使わない。`tools/new_id.py` と `tools/new_ledger_shard.py` は今日より後の日付を拒否する（`FutureDateError`）。
3. **`started_at` は来歴として残してよい。** 委任文に書かれたラベルをそのまま記録することは、順序を偽ることとは別である。ただし `sessions` の `notes` に必ず実日付を書く（`実作業日 2026-11-05` の形）。軸はそこを読む。
4. **補間しない。** 実日付が記録されていないラベルは `未記録` として穴のまま並べる。前後の日付から推測して埋めた日付は、記録ではなく創作である。
5. **ラベルと実日付が一致しないことは失敗ではない。** 軸は「一致 39 ／ 不一致 94」のような**観察**を出すだけで、合否を出さない（`docs/mode-rotation-triggers.md` §2 と同じ扱い）。

## 2. 実装（`tools/date_axis.py`）

軸は、既に台帳に入っている証拠だけから、内部編年ラベル→実日付の対応を作る。優先順位は次のとおりで、どの規則で置いたかを一行ごとに残す（**2026-11-05 改訂**。規則2.5・2.6・3 を追加し、集計をラベル単位からセッション単位に直した。訂正は `ERR-20261105-5d021e`）。

| 順 | 出所 | 例 | 実測（2026-11-05・451セッション） |
|---|---|---|---|
| 1 | `notes.date_real`（後から記帳された判断） | `2026-11-05` | 61 |
| 2 | `sessions.notes` / `human_direction` の**実行環境日付** | `実行環境の UTC 日付は 2026-10-26` | 103 ＋ 10 |
| 3 | `sessions.notes` / `human_direction` のその他の実日付マーカー | `実作業日 2026-11-05`／`実行日（UTC）2026-11-04` | 80 ＋ 40 ＋ 4 ＋ 3 ＋ 1 |
| 4 | `readings/` の**ヘッダ**（`セッション` 行と同じブロックの実日付） | `**実行日**：2026-10-28（UTC）` | 15 |
| 5 | `readings/` の**本文**にある実行環境日付だけ | `本セッションは実行環境の実UTC日付 2026-10-30 をそのまま記録する` | 18 |
| 6 | `started_at` が**既に実日付である**場合 | `2026-10-24`（今日より後でない値） | 115 |
| 7 | どれも無い | — | **1**（`SESSION-20261126-7b7806`） |

規則6が要点である。**今日より後の `started_at` は日付として読まない**。この一つの規則で、「ラベルか実日付か」を例外表なしに判定できる。内部編年は必ず実日付より先へ進んだからである。

規則4・5は本文と台帳を分けて読む。ヘッダが**内部編年ラベルを「日付」として掲げ、実行環境日付を別行に書いている**報告（`2026-11-12-sixty-millimeters-that-never-came.md` など）では、ヘッダから採るのは `実行環境` 以外のマーカーだけであり、実行環境日付は本文側の規則5が拾って出所を `readings.body:実行環境日付` と明示する。**ラベルを実日付と誤読する経路を残さないため**、`実行環境` を含むマーカーはヘッダ規則から外してある（`header_marker_date()`）。

```
$ python3 tools/date_axis.py
  labels 133 ／ sessions 451 ／ 実日付あり 450 ／ 未記録 1 ／ 未来ラベル 224
  実日付の範囲: 2026-10-22 〜 2026-11-29
  出所: {'started_at': 115, 'sessions.notes:実行環境日付': 103, 'sessions.notes:実行日': 80,
        'notes.date_real': 61, 'sessions.notes:実日付': 40, 'readings.body:実行環境日付': 18,
        'readings.header': 15, 'sessions.human_direction:実行環境日付': 10, …}
  2026-10-24  ← 2026-10-24   45 session(s)  (started_at)
  2026-10-30  ← 2026-12-31   45 session(s)  (sessions.notes:実行環境日付) [未来ラベル]
  2026-11-05  ← 2027-02-23    1 session(s)  (notes.date_real) [未来ラベル]
```

`--anomalies` で「ラベル ≠ 実日付」の行だけ、`--json` で機械可読、`--today` で判定日を固定して回帰テストに使う。

### 2.1 集計は、ラベルではなくセッションで数える

初版は「ラベルに実日付が決まらないこと」を未記録の条件にしていた。そのため **`2026-12-31` に同居する45セッション（実日付は 2026-10-30 と 10-31）が、全員まとめて未記録に落ちていた**。ラベルが二つの実日付を持つことと、セッションの実日付が無いことは別である。現在は `AxisRow.sources` をセッション単位で合算し、`未記録` の数だけが穴として数えられる。

二つの穴は区別して読む。

| 穴 | 意味 | 現在 |
|---|---|---|
| **未記録**（セッション） | どの規則でも実日付が決まらない | **1** |
| **曖昧なラベル**（ラベル） | そのラベルの下に複数の実日付がある（並列セッション） | 8ラベル・96セッション |

曖昧なラベルは穴ではない。`--json` の `ambiguous_labels` に出る。

## 3. 直せなかったこと（2026-11-05 改訂）

- **未記録は1セッションだけになった。** `SESSION-20261126-7b7806`。`sessions.notes` にも `human_direction` にも実行環境日付の記載がなく、報告 [`readings/2026-11-26-the-blank-is-a-way-of-seeing.md`](../readings/2026-11-26-the-blank-is-a-way-of-seeing.md) のヘッダも内部編年ラベル（`2026-11-26`）だけを掲げている。**補間しない**ので、この1件は穴のまま置く。
  - 初版の「25ラベル・119セッションが未記録」は誤りだった（`ERR-20261105-5d021e`）。原因は三つ：ラベル単位の集計（§2.1）、`実行環境の UTC 日付` をマーカーとして認識していなかったこと、`readings/` のヘッダと本文を読んでいなかったこと。**記録は最初からそこにあり、測り方が足りなかった。**「未記録」を「記録が無いことの可視化」と書いたのは、測れていないものを記録の不在として提示した点で誤りである。
- **`2026-10-27T06:01:04Z` のような ISO 時刻ラベル**は日付として読めるが、実日付かどうかは `sessions.notes` の記載に依る。軸はマーカーが無ければ `started_at` を採るので、ここでも「未記録を未記録と言う」原則の外に出ていない。
- **素材ID・ノートIDの 1,124 件**（`MAT-LIT-20270222-…` など）は既に内部編年で振られている。ID は書き換えないので、これらは `tools/date_axis.py --json` の軸に載らず、`notes.date_real` 側からしか実日付に戻れない。新規採番だけが規則2で直る。
- **実日付と実日付マーカーの食い違いは0件**だった。規則2を規則3より先に置いたことで既存の解釈が変わっていないことを、全セッションで確認した（`ERR-20261105-5d021e` の `observed`）。

## 4. 再計測と回帰テスト

```sh
python3 tools/date_axis.py                 # 軸（ラベル→実日付）と観察値
python3 tools/date_axis.py --anomalies     # ラベルと実日付がずれた行だけ
python3 tools/date_axis.py --json          # 機械可読（--today で判定日を固定）
python3 -m unittest tests.test_date_axis -v
```

## 5. この文書の効力（自己言及）

この文書は `main` にマージされた時点で規則になる（[`trust-root.md`](trust-root.md) §1 第三層）。**マージ前は提案にすぎず、マージ前のセッションがこの規則に従う義務はない。** また、この文書自身は内部編年ラベルを持たない——規則2を、規則を書いた文書が最初に適用している。

## 6. 追記（2026-11-12）：判定器はこの軸を使っていない

`SESSION-20261112-7df82b`（報告：[`readings/2026-11-12-two-clocks-the-gate-counts-labels-the-axis-lays-out-dates.md`](../readings/2026-11-12-two-clocks-the-gate-counts-labels-the-axis-lays-out-dates.md)）。上の規則と実装は**書き換えていない**。測定だけを残す。

1. **規則9（層2の必須化、`docs/parallel-work.md`、2026-11-10 発効）の判定器 `session_date()` は、この軸を使っていない。** それは `session_id` の `YYYYMMDD` を実日付として読む（docstring の前提：「`new_id.py` stamps it from the real date」）。この文書 §3 が記録するとおり、**ID の 1,124 件は既に内部編年で振られている**ので、この前提はラベル期の記録に対して成り立たない。
2. **実測（判定日 2026-11-12・679セッション）**：軸が実日付を返す 678、未記録 1（`SESSION-20261126-7b7806`、上の §3 と同じ1件）、判定器が免除する 96、**二つの時計が食い違う 25**。食い違いは片側の誤りではない——判定器はラベルを実日付として読み、軸は後日登録された `notes.date_real`（例：`SESSION-023` は ID 10-22・後日登録 11-07、この形は76セッション）を実日付として読む。
3. **規則9の適用範囲**：判定器の時計で発効日以降・この軸の時計で発効日より前になるセッションが **4 件・26 ペア**（`43ee9f`・`900e9b`・`5ebabb`・`711655`。4 件とも委任文に実日付 2026-10-26 と内部編年の両方が書かれている）。規則9を軸の時計で数えると **373 適格・名指し 9・未充足 0**、判定器の時計で数えると 399・11・**未充足 1**。
4. **免除の悪用は 0 件**。判定器が未来IDとして免除する 96 セッションのうち、軸の実日付が発効日以降のものは無い。抜け道ではなく、過剰適用だけがある。
5. **この不一致は解いていない。** 判定器を軸に合わせるかは規則の変更であり、`docs/parallel-work.md` の分類（規則の変更は editorial の判断）に従って、次回以降に残す。詳細は `ERR-20261112-10a312`。
