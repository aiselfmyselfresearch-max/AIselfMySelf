## 処置と限界

- **命名と予算。** `*_audit*.py` の本数はテーマ別監査の増殖を抑えるための近似であり、意味を判別する検査ではない。書庫全体の本文存在ゲートを、仮に `readings_integrity_audit.py` と呼んでも本数予算に入れないよう、厳密なファイル名の例外を明示した。既存の `readings_integrity_check.py` は名称も既存の参照先も変更しない。例外にはレビューが必要で、名前に audit を含まないテーマ別スクリプトを検出できない。辞書駆動への移行という方針は維持し、名称だけで遵守を証明したとは言わない。
- **13件の訂正録。** `errata_audit.py --schema` が基準時に返す13行それぞれに、新しい訂正録を追記した。各記録に対象ID、元のシャード、実際のエラー文字列、再測定コマンドと基準コミットを残す。存在しない「この行は自身が有効だと主張する」という主張は帰属させず、不一致があるという観測を記録した。行とスキーマのどちらを変更すべきかは裁定しない。元行とスキーマは変更していないため、形式上の不一致は13行のまま。訂正録の追加とスキーマ適合は別のことである。
- **比較回数。** 旧実装は `compared_touch_count` を算式で使っていなかったが、比較相手に `cmp:種類:出所` を独立出所として加える別経路があり、不確実性には既に影響していた。これを取り除き、`u = clamp((1 + 直接の独立出所数 + 0.5 * log2(1 + 比較回数))^(-1/2) * 反証系補正, 0.05, 1)` とした。0.5 と対数は、単なる名指しを直接検証より弱く、反復の増分を減らすための**暫定的な設計判断**であり、経験的校正ではない。重複行を含め比較回数は増えるため、同一出所の反復にも影響が残る。旧方式は出所単位で重複を畳んでいたので、回数によっては旧方式より不確実性が低くなる場合もある。将来は出所の独立性と重みの感度を検証すべきである。事後確率の計算経路は変えていない。
- **未評価の対。** 従来どおり active が2件以上なら active を、そうでなければ全仮説を候補にする。その候補から、両側に直接評価がある対だけを順位付けする。該当しなければ推薦を返さず、表示・割当理由で説明する。候補なしを EIG=0 の飽和と誤認しない。これは未評価仮説を評価することを禁止するものではなく、対の自動推薦を保留する規則である。直接評価は質の保証でも対立の証明でもない。EIG 同着の反復順問題は今回の依頼では分析のみとし、変更しない。
- **横断的な比較。** 問いを跨ぐ `compared_against_hypothesis_ids` の拒否は追加していない。合成テストで、別の問いに属する仮説への比較回数が届くことを確認する。

同じ基準データで旧版と新版を比較すると、問いごとの仮説の表示事後確率の絶対差総和は **0.0000**、不確実性が変わった問い・仮説の組は **36**。Q-002 の首位は `977052 / 065706` から `977052 / 8f6552` に変わった。Q-001 と Q-003 の首位は不変。これは基準スナップショットの比較で、将来も不変という保証ではない。
