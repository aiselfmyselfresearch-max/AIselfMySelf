## ② 支持照合率による割引 — `P_gate` の係数

**何を変えたか。** `supports` 評価行の重みを、その行が引用した素材のうち `verification.status == "verified"`
である割合 `r` で割り引く。

```
factor = SUPPORT_DEPTH_FLOOR + (1 - SUPPORT_DEPTH_FLOOR) * r      # floor = 0.5
```

* 素材を1件も引用しない行（命題監査・再現スクリプト）は `r` が定義されないので**割り引かない**。
  「本文を読んでいない」と「本文について語っていない」は別だから。
* 効果は `P_gate` のみ。歴史的事後確率 `P_t` は動かさない（既存の `P_sep` / `P_lin` と同じ扱い）。

**実装。** `tools/belief_state.py` の `support_verified_ratio()` と `delta` の1行。閾値の実測は
`python3 tools/verification_targets.py`（未照合の支持行 158/356）。

**効き方（2026-11-20 時点、`SUPPORT_DEPTH_FLOOR` を 1.0 に戻した対照との比較）。**

| 問い | 仮説 | 割引なし | 割引あり | Δ |
| :--- | :--- | ---: | ---: | ---: |
| Q-003 | `HYP-20261117-4bf2dc` | 99.2% | 78.4% | −20.8pp |
| Q-001 | `HYP-20261119-8b3e04` | 61.8% | 50.9% | −10.9pp |
| Q-002 | `HYP-20261119-8b3e04` | 49.1% | 39.9% | −9.1pp |
| Q-003 | `HYP-20261119-8b3e04` | 0.4% | 8.8% | +8.5pp |

51仮説が動いた。Q-003 の首位が20.8ポイント下がったのは、その支持が未照合素材に載っていたからで、
これは「確信が読書の深さに依存していた」ことの直接の測定値である。

## ③ 検証深度の分離 — `verification.depth`

**何を変えたか。** `verification` に `depth` を足した。

| 値 | 意味 |
| :--- | :--- |
| `metadata` | 書誌だけ |
| `abstract` | 抄録・Summary |
| `results` | 結果表・主要図 |
| `full_text` | 引用した一節を論文本文で読んだ |
| `re_derived` | 報告された数値から再計算した |

* `schema/material.schema.json` に追加（既存行は無変更、`additionalProperties: false` は維持）。
* `schema/editorial_decision.schema.json` に `verification_depth` を追加し、
  `tools/ledger_io.py` が material の `verification.depth` へ適用する（shard は書き換えない）。
* 検証器（`validate_seed.py`）は次の2つを強制する:
  - `depth` が `metadata` / `abstract` なのに `status == verified` は**矛盾**（本文を読まずに verified は名乗れない）。
  - `depth` が `full_text` / `re_derived` なら `status` は `verified`（または `corrected`）。
  - `2026-11-21` 以降に照合した行は `depth` 必須。

**正直な残高。** `python3 tools/validate_seed.py` の助言行:

```
INFO: verification.depth (advisory): 2 material(s) carry a depth; 1414 legacy `verified` row(s) predate the field
```

つまり既存の 1,414 件の `verified` は「照合はあった」としか言っていない。本文を読んだのか抄録だけかは、
この変更以前の行からは**復元できない**。復元できるのは、これから書く行だけである。

## ④ 数値の三経路と、独立二読

### ④-a 数値は「再計算・照合済み素材・理由」のどれかを持つ

`evaluations.no_recompute_reason` と `notes.claims[].recomputer` を追加し、`2026-11-21` 以降の行で
数値を含む主張がどの経路も持たない場合を**エラー**にした。

```
python3 tools/validate_seed.py
INFO: number traceability (advisory): 0 numeric row(s) from 2026-11-21 on are gated by script/material/reason;
      1211 legacy numeric rows are ungated and remain un-recomputed history
```

この規則は、この文書を書いている最中に**自分の誤りを1つ捕まえた**。前の応答で
「上位50件の照合で支持行の約6割が verified を持つ」と書いたが、これは複数素材が支える行を
二重に数えた値だった。行を一度だけ数えると、50件で **31%**、100件で **51%** である
（`python3 tools/verification_targets.py`）。数値を書いた本人が再計算しないと、その数値は記憶になる。

### ④-b 二読の食い違いを測る — `tools/double_reading.py`

Arena ではモデルの割当を選べない。だから「同じ素材を別セッションが読む」ことだけが
モデル間分散への手がかりになる。

```
python3 tools/double_reading.py
- 手読みのある素材: 4,620
- うち 2 セッション以上が読んだ素材: 1,169 (25.3%)
- セッション対: 2,594 / 読みの種類が食い違う対: 1,832 (70.6%)
- 方向転換の対（interpreted → reinterpreted/contested）: 704 / 該当素材 441
```

70.6% という数字は**上限**である（二人が同じ `interpreted` と書いても内容が同じとは限らない）。
それでも、二読の4分の3が同じ語を選ばないという事実は、「一度読んだ素材の読みを台帳は保存している」
という前提を弱める。保存されているのは読み**行為**の分類であって、読み**内容**ではない。

# 追補（同日 第2部）: ③の遡及適用と、その限界の測定

## 何をしたか

`tools/depth_backfill.py` を追加し、depth を持たない照合済み 1,421 行の `verification.method` / `note` の
記述を**保守的に**分類した。否定語（未読・未取得・読めず）を含む節は本文到達とみなさず、
「抄録と本文§3」のように深さの異なる記述が併存する行は判定不能に落とす。

| 分類 | 件数 | 扱い |
| :--- | ---: | :--- |
| full_text_claim（本文到達を明示） | 364 | `depth=full_text` を overlay で付与（status は変更しない） |
| results_claim（本文に到達したが図表のみ） | 38 | `depth=results` を overlay で付与 |
| shallow_claim（抄録・書誌のみ） | 204 | **書き込みを拒否**。降格を伴うため |
| unknown | 815 | 再読が必要 |

**分類は記述からの推定であって、本文の再読ではない。** そのことは overlay の `reason` に1行ずつ書いた
（「深さは記述からの推定であり、本文の再読ではない」）。

## なぜ 204 件を自動で降格しないか

新規則では `verified` は `metadata` / `abstract` を名乗れない。したがって shallow_claim の 204 件は
**記録どうしが矛盾している**（verified と言いながら、method は抄録しか見ていないと書いている）。
矛盾の解消は「降格」であり、降格は `P_gate` の支持照合率を動かし、順位を動かす。
記述の推定だけで順位を動かすのは、③を入れた理由（読んだ以上のことを名乗らない）の裏返しの違反になる。
だからこの道具は `--allow-downgrade` を持たない。**204 件は①のキューの先頭に置く。**

## 実測: この作業で `verified` の意味が変わったか

変わっていない。`verified` / `corrected` は 1,421 行あり、depth が付いたのは **402 行（28.3%）**。
残る **1,019 行**は依然として「照合はあった」としか言わない。この残高は道具が毎回出す:

```
python3 tools/depth_backfill.py
- 照合済み（verified/corrected）素材: 1,421
- すでに depth を持つ: 402
```

**28.3% という数字を「解決」と呼ばないこと。** 解決したのは、記述が本文到達を明示していた
402 行に限られる。残る 1,019 行のうち 204 行は記述が浅く（矛盾）、815 行は判定不能である。

## 途中で捨てた修復案

main の `SESSION-20261120-a45e52` が割当レシートの2欄を欠いたまま入り、`validate_seed` が赤になっている。
追記で補おうとして**同一ファイル内の重複 session_id で拒否された**ため、その案は取り下げた
（`git checkout` で復元）。sessions 行は追記で上書きできない設計であり、既存行を書き換えるのは
追記専用規約に反する。したがってこの不整合は**未修復のまま残す**。赤の原因がこの行だけであることは
`python3 tools/validate_seed.py` の出力で確認できる。

# 第3部（2026-11-21）: 推定 depth の監査 — 13.4% が誤りだった

## 何が起きたか

前日、③の遡及適用として 402 件に推定 depth を付けた。その分類器は否定語として「未読」「未取得」「読めず」などを
持っていたが、**「〜ではない」という普通の否定を持っていなかった**。結果、次のような行が `depth=full_text` を
名乗った。

> method: 「仕様・実装の**全文精読ではない**。引用文字列をファイル内で照合（4/4・2/2・3/3 一致）。」

overlay の `reason` は「否定語を含まない」と書いており、**誤りが自分の根拠の中に印刷されていた**。
読めば分かる矛盾を、書いた本人が検査しなかった。

## 何を直したか

1. 否定語に「ではない / していない / せず / 及ばず / 限らない」等を追加。
2. 「抄録と方法を照合」型を shallow と呼ばないよう、本文マーカー（方法・結果・考察・統計・頁・図表）を追加。
   **8件の標本で shallow 分類の精度は 4/8（50%）だった** — これが自動降格をしなかった理由の実測。
3. overlay の `reason` に埋め込んだ「元の note」を再帰的に読まないよう、監査時の入力を分離。
4. 監査モード `--audit-overlays` を追加し、推定 depth を再分類して**取り消し**を出す。

## 結果

| 項目 | 件数 |
| :--- | ---: |
| 前日付けた推定 depth | 402 |
| 新しい分類でも維持 | **348** |
| 取り消し（`depth=unspecified` へ） | **54（13.4%）** |

`unspecified` は schema に足した新しい値で、「記録は深さを言っていない」を意味する。**新しい行の答えとしては
認めない**（照合したセッションは「どこまで読んだか」を書かねばならない）。legacy 行と、推定を取り消す補正だけが
これを使える。わからないことを、わかったふりで埋めないための値である。

## 降格の代償を測った — `tools/downgrade_impact.py`

「verified なのに記述は抄録だけ」の行を降格すると何が動くかを、書く前に計算する道具を足した。

# 第4部（2026-11-21）: 例外をコードから台帳へ、そして外部アクセスの再確認

## 例外の置き場所を間違えていた

前日、追記では直せない3件（PR #1002 の register 無しの問い2件、PR #998 の受領証欠落 session 1件）を
`KNOWN_REGISTER_DEFECTS` / `KNOWN_RECEIPT_DEFECTS` という **Python の辞書** に載せた。意図は正直だった
（どのセッションも緑にできないゲートは読まれなくなる）が、置き場所が間違っていた。

- `state/questions.d` を読む人は、そこに既知の欠陥行があることを知らない。
- 例外の件数は「ソースに何行書いたか」で、他のどの道具からも見えない。
- 例外を消す手段がコードの編集しかない。

**だから移した。** waiver は errata の一行である。

```json
{"errata_id": "ERR-20261121-8c6d1f", "subject_type": "question",
 "subject_id": "Q-20261121-198fc8",
 "check": {"kind": "manual", "params": {"gate_waiver": "register", "expected": "...", "observed": "..."}},
 "verdict": "contradicted", "status": "open", ...}
```

`validate_seed.gate_waivers()` がこれを読み、`status == "open"` のあいだだけゲートを通す。移動で得たもの:

| 性質 | 辞書（前日） | errata（今日） |
| :--- | :--- | :--- |
| 台帳を読む人に見える | いいえ | **はい**（`grep` で出る） |
| いつ消えるか | コードを編集したとき | **`status` を閉じたとき**（自動で戻る） |
| 綴り間違い | 無言の no-op | **エラー**（未知のゲート名は通さない） |
| 対象の取り違え | 無言の no-op | **エラー**（subject_type が違えば拒否） |
| 二重 waiver | 検出しない | **エラー** |
| 記録を失ったら | コードにあるので残る | **ゲートが赤くなる**（正しい） |

あわせて `schema/errata.schema.json` に任意の `session_id` を足した。既存11行が既に書いていたのに
スキーマが拒んでいたためで、判断を書いた者を記録できない errata は、この台帳の趣旨に反する。
`errata_audit.py --schema` の不一致は 13 → **10行**に減った（新規3行は適合）。

## ② 二重読み不一致は「何」の不一致か

`tools/double_reading.py` に出力を追加し、不一致の中身を3つの角度から測った

- **層別**（`verification.depth` ごとのセッション対）: full_text 素材は一致 67 /
  不一致 173（**72.1%**、計240対）、depth なしは 687 / 1,634（70.4%、計2,321対）。**原文の読了深度が
  深くても、読みの種類の食い違い率は下がらない。** results（17対）・abstract（3対）は
  標本が小さすぎて語れない。これは `reading` の種類が内容の判定ではなく、そのセッション
  が**した作業**（引用・要約・再解釈・異議）の記録だからである。一致率は相変わらず上限
  であり、不一致率も「対立」の率ではない。
- **組み合わせ**（食い違う1,848対の内訳）: interpreted × reinterpreted 608、
  interpreted × summarized 248、quoted × reinterpreted 178、interpreted × quoted 169、
  reinterpreted × summarized 148、counted × reinterpreted 100。
  「再解釈した／していない」の形が最大の塊であり、方向転換705対と重なる。
- **裁定の届き方**（coverage, not resolution）: 食い違いのある素材 **962件**のうち、
  訂正録または編集判断が名指すのは **262件（27.2%）**。名指しされているだけで、どちらの
  読みが正しいと裁定されたかは数えていない。逆に言えば **72.8% は誰の裁定も届いていない。**

数値は本日書いた `counted` 2行（①の実読の痕跡 `READ-20261121-3ad7c1` / `READ-20261121-9f42be`）を
含めた最終状態の測定である。

数値の対立ではない可能性が高い、(2) それでも台帳には裁定の届かない食い違いが
