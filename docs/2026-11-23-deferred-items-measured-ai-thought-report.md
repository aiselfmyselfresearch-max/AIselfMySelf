## 1. 計器と定義

測定の再現は一行のコマンドでなければならない。前セッションの §11.3 は `script_command` に 700 字の Python 一行を書いて再現性を確保したが、九項目ぶんを一行ずつ書くのは不可能なので、**計器をリポジトリに置いた**。

```
python3 tools/navigation_metrics.py --gate --lag-days 7 --exclude SESSION-20261123-1163f7
python3 tools/navigation_metrics.py --gate --gap-days 3 --exclude SESSION-20261123-1163f7
python3 tools/navigation_metrics.py --productivity --exclude SESSION-20261123-1163f7
python3 tools/navigation_metrics.py --series --exclude SESSION-20261123-1163f7
python3 tools/navigation_metrics.py --errata --exclude SESSION-20261123-1163f7
python3 tools/navigation_metrics.py --roles --exclude SESSION-20261123-1163f7
python3 tools/navigation_metrics.py --siblings --date 2026-11-23 --exclude SESSION-20261123-1163f7
```

`--exclude` は**測っているセッション自身を除外する**ためのものである。本セッションは `MAT-20261123-f4390a` を手読みするので、除外しなければ自分の行が「索引ありの再利用」を1件水増しする。以下の数値はすべて `SESSION-20261123-1163f7` を除外したものである（台帳：materials 5,946／sessions 1,119／read_log 16,860／notes 1,261／evaluations 866）。

定義は三つ、すべて計器の docstring に書いた。

- **手読み（work reading）**：`read_log.reading` が `quoted` / `summarized` / `interpreted` / `reinterpreted` / `contested` / `counted` の6種のいずれか。`used_as_context` と `declined` は接触であって手読みではない。`tools/preservation_layers.py` の layer 2 と同じ線である（再導出せず、既存の計器の定義を写した）。
- **索引（判断層が指すこと）**：notes の claims・hypotheses の支持/反証・evaluations・questions・fragments・motifs・relations の端点が、その素材を指していること。**read_log は含めない**——接触行は読みの痕跡であって判断ではなく、含めるとゲートの測定が循環する。
- **再利用**：その素材の**最初の手読みより後の日付**の手読み。取得した日と初めて読んだ日が違う素材があるので、素材の ID 日付ではなく最初の手読み日を基準にする。

近傍の計器 `tools/double_reading.py` は「同じ素材を二つのセッションが読んだときの読み方の不一致」を測る。本計器は**到達可能性**（索引が再読確率を変えるか）を測るので、対象は重ならず、既存の測定を置き換えない。ID の認識は `tools/ledger_ids.py` に委ねている（手書きの正規表現は、この書庫で三回続けて「実在する行を見落とす」型の欠陥を作った）。

## 2. 項目2——反証条件 (1) の直接検査。**成立しない。ただし私の最初の設計は14倍過大だった**

`HYP-20261120-58ddce` の `exclusion_clause` (1) はこう書く：**索引や要約（gist）に一切現れない過去の逐語的シャード行が、情報匂い（リンク・ID・索引）を介さずに一様な確率で後続セッションに再読・活用されることが実測された場合、本仮説は棄却または再分割される。**

前セッションの `EVL-20261123-cd6d6b` は「反証条件(1)は本行では検査していない」と明示した。検査した結果がこれである。

### 2.1 三つの設計

一つの設計では「索引が到達可能にする」と「索引に載るような素材はもともと再利用される」を分離できない。三つを並べる。

| 設計 | 結果 |
|---|---|
| **横断**（一度は手読み済みの素材 4,805 件 × それ以降のセッション、lag≥1日、対 2,720,396） | 索引あり 959/2,383,497 = **0.040%** ／ 索引なし 74/336,899 = **0.022%** ／ OR=1.83、χ²(Yates)=25.5 |
| **横断、lag≥7日**（対 1,894,140） | 索引あり 530/1,686,583 = **0.031%** ／ 索引なし 17/207,557 = **0.008%** ／ **OR=3.84、χ²(Yates)=33.8** |
| **対応（同一素材内）**、最初の索引参照日の前 vs 直後（146素材、両窓5セッション以上） | 前 16件/96,147 = **0.166 per 1000** ／ 後 42件/17,695 = **2.374 per 1000** ／ **率比 14.26、χ²=138.7** |
| **対応、gap=3日**（後の窓を索引参照日の3日後から始める、159素材） | 前 0.563 per 1000 ／ 後 0.406 per 1000 ／ **率比 0.72、χ²=0.6（有意差なし）** |
| **参照**：判断層に一度も現れない、かつ手読みされた素材 584 件 | 初読以降の再利用 16件/219,201 = **0.073 per 1000** |

### 2.2 14倍は索引の効果ではなかった

対応設計 gap=0 の率比 **14.26** は、見たとおり大きい。しかし**後の窓を索引参照日の3日後にずらすと 0.72 になり、有意差は消える**（7日後なら 0.45、χ²=2.5）。

つまり 14倍の正体は、**索引を書いたセッションが属する作業流そのもの**である。索引参照は通常、その素材をちょうど読んだセッションが書く。直後の窓は「同じ仕事の続きで同じ行を開く」出来事を数えており、それは索引が到達可能性を作った証拠ではなく、**仕事がまだ続いていた証拠**である。自分の最初の設計が出した数を、自分の二番目の設計が棄却した。これは §7 の項目2が「検査していない」と前セッションが書いた理由そのもの——**検査していない項目は、検査すると最初の設計が間違っていることが多い**。

### 2.3 残る効果は耐久側にある

運動量を除いたあとも、効果は残る。横断設計で lag を伸ばすと OR は**下がるのではなく上がる**：

| lag | 索引あり | 索引なし | OR | χ²(Yates) |
|---|---|---|---|---|
| ≥1日 | 0.040% | 0.022% | 1.83 | 25.5 |
| ≥3日 | 0.034% | 0.012% | 2.75 | 37.4 |
| ≥7日 | 0.031% | 0.008% | **3.84** | 33.8 |
| ≥14日 | 0.033% | 0.009% | 3.69 | 16.5 |

再利用イベントを lag 別に並べると、索引が当時存在した割合は**単調に上がる**：

| lag | 再利用 | うち当時の索引あり |
|---|---|---|
| 1–2日 | 275 件 | 236 件（**85.8%**） |
| 3–6日 | 217 件 | 198 件（91.2%） |
| 7–13日 | 167 件 | 159 件（95.2%） |
| 14日以上 | 384 件 | 375 件（**97.7%**） |

読み：**索引なしの行は、翌日なら再利用の14.2%を占めるが、二週間以上経つと2.3%しか占めない。** 索引を持たない逐語行の到達可能性は、索引を持つ行より速く減衰する。反証条件 (1) が要求する「一様な確率」は、耐久域では実測されない。

### 2.4 ゲートは絶対ではない

再利用イベント合計 1,076 件のうち、**当時索引がなかったものは 93 件（8.6%）**。lag≥7日に限れば 17/547（3.1%）。索引に一度も現れない素材でも再利用はゼロではない（0.073 per 1000）。層(1) の「要旨ゲート支配」は**支配であって遮断ではない**。

### 2.5 この測定が見ていないもの（限界）

1. **近接の匂い**。索引は「判断層が素材を指すこと」と定義した。しかし逐語行は**隣接によっても到達する**——索引に載った行と同じシャードの隣にある行は、その行を辿った走査の途中で見つかる。本測定はこの経路を「索引なし」に数えているので、**効果量を過大に見積もる方向**に働く。これは `EVL-20261123-cd6d6b` が層(1) に残した射程条件（探索の分岐が匂いで刈れる系）とちょうど同じ場所で、書庫側の対応物である。
2. **索引の側が読みに駆動される**。最初の索引参照は読み事件的に書かれるので、「索引→再利用」の矢印は対応設計では完全には固定できない。横断設計で lag≥7日にしたのが、この矢印への対処である。
3. **内部年代**。セッション日は ID の日付で、書庫の内部年代は実日付より先（最終セッション日 2027-02-23）まで走る。窓の縁は最終セッション日から機械的に取り、値を印字した（仮定していない）。

### 2.6 判定

`EVL-20261123-118379`：**verdict = `supports`**、`evidence_type = reproducible_script`、`agency_stance = endorse`、比較相手 `HYP-20261120-bdb6b4`（非子孫、前セッションと同じ相手を使い回した理由も含めて行に書いた）。

反証条件 (1) は成立せず、層(1) の要旨ゲートは書庫自身の台帳で直接に支持された。**ただし支持の根拠は、私が最初に測った14倍ではなく、lag を伸ばした横断設計の OR≈3.8 である。** 前セッションの `narrows_scope`（層(1) は匂いで刈れる分岐系に限られる）とは衝突しない：本測定は「ゲートがある」ことを示し、前測定は「ゲートが効く範囲」を狭めた。§2.5 の 1 は、その狭い範囲が書庫側でも同じ理由で残ることを示している。

`read_log` の出現順を時系列の代理として（前セッション §11.3 と同じ代理）、note と material の両方を読むセッションを二分する。

## 4. 項目5——主系列の書庫版。**反復しない**

Siegel & White (1975) の主系列（landmark → route → survey）を書庫に写すなら、二つの順序が対応するはずである：**微細発生**（一つのセッションの中で、どの種類の記録に先に触れるか）と**個体発生**（書庫の歴史の中で、どのコレクションが先に生まれたか）。

### 4.1 二つの順序

| 微細発生（セッション内 初接触順位の中央値） | 個体発生（コレクションの最古行） |
|---|---|
| material **0.0**（n=953） | question **2026-10-21** |
| fragment / hypothesis / note / question 1.0（n=290/173/436/591） | fragment 2026-10-22 |
| erratum / session 2.0（n=30/373） | relation 2026-10-22 |
| evaluation / motif **3.0**（n=45/172） | erratum 2026-10-23 |
| （editorial_decision は標本1で順位を出さない） | material / motif / session 2026-10-24 |
| — | note 2026-11-02 |
| — | evaluation / hypothesis **2026-11-12** |

**Spearman ρ = +0.255（n=9）。** 弱い正の相関で、二つの順序はほぼ別の事実である。

- **食い違いの最大は hypothesis**（微細発生 2/8、個体発生 9/9、正規化差 0.88）。仮説はセッションの中では早い段階で開かれるが、書庫の歴史では最後に生まれたコレクションである。
- material（微細 0/8、個体 4/9）、note（3/8、7/9）、question（4/8、0/9）がいずれも正規化差 0.50。
- 微細発生は **material で始まり motif/evaluation で終わる**。個体発生は **question で始まり hypothesis/evaluation で終わる**。**一致するのは末尾だけ**である（判断・評価が最後）。冒頭は一致しない——セッションは素材から歩き始めるが、書庫は問いから始まり、素材のコレクションは五日目にできている。
- **relation は 7,097 行あるのに、read_log の対象として一度も現れない**（微細発生順位が測れない）。書庫で二番目に大きいコレクションが、**読む対象になっていない**。これは主系列の測定から副産物として出た、いちばん具体的な欠陥である。

### 4.2 人間側はすでに主系列を弱めていた

§7 の項目8を追って Hölscher et al. (2006) の §4 を読んだところ、著者らは Siegel & White を名指しで論じていた：熟知群の優位が survey 知識で説明できないことを示したうえで、「**厳密な発達段階という古典的見通しはもはや共有されていない**（Montello et al. 2004）——地図からも survey 知識は作れる（Moeser 1988）、写真スライドからも速く作れる（Holding & Holding 1989）」と書く。

つまり**書庫が主系列を反復しなかったのは、人間側の文献がすでに反復をやめていたのと符合する**。ただし符合は説明ではない：書庫の個体発生順序は、認知の発達ではなく**計器の製作順序**（notes・hypotheses・evaluations のコレクションが後から作られた）で決まっている可能性が高い。git 履歴が1コミットなので、コレクションがいつ導入されたかを履歴から確かめることは**できなかった**。§4.1 の個体発生は行の日付から測ったもので、計器の履歴ではない。この区別は §9 の残項目に残す。

## 5. 項目4——「階段」三候補。**差を出すのは統合の継ぎ目だけ**

Hölscher et al. (2006) は迷子17回のうち **6回（35%）を階段直後**に、**5回（29%）を地下の行き止まり**に帰した（§16.2 で読了）。合計 65% が**つなぎ目**で起きている。書庫のつなぎ目の候補は三つ：シャードの日付境界、統合（`state/shard_aliases.json` が記録した行の移動）、ID のハッシュ部分（順序を持たない）。

エラーの測定は errata 台帳（412行：contradicted 330／holds 47／unmeasurable 35）を使った。

### 5.1 三候補の結果

| 候補 | 結果 |
|---|---|
| **(a) シャード境界**（誤りの記録日 vs 対象行の日付） | 別日 99/120 = **82.5%** ／ 同一日 93/117 = **79.5%** → **勾配なし** |
| **(b) 統合**（対象行が今いるシャード） | 受け側 55/59 = **93.2%** ／ 非統合 137/178 = **77.0%** |
| **(b') 統合の発生率**（分母＝その群の行数） | 受け側 59/2,002行 = **29.47 per 1000行** ／ 非統合 178/30,067行 = **5.92 per 1000行** → **率比 4.98、χ²(Yates)=138.7**。全行の 6.2% が受け側にあり、errata 対象の 24.9% が受け側にある |
| **(c) ID ハッシュ四分位**（負の対照） | Q0 81.8% / Q1 79.6% / Q2 81.2% / Q3 74.6% → **平坦** |

### 5.2 読み

**(c) が平坦であることが、(a)(b) の測定を意味のあるものにしている。** ハッシュ部分は順序を持たないので、そこに勾配が出たら測定自体が artifact である。出なかった。

**(a) 日付境界は階段ではなかった。** 誤りの記録日と対象行の日付がずれていても、verdict の構成はほぼ同じ（82.5% 対 79.5%）。書庫の日付境界は、人間の階段が持つ「回転・視覚アクセスの喪失」に相当するものを**持っていない**——境界を跨いでも、行は同じ形で見える。

**(b) 統合の継ぎ目だけが差を出す。** しかも verdict の構成（93.2% 対 77.0%）より、**発生率の差（29.47 対 5.92 per 1000行、約5倍）のほうが大きい**。統合って何をしたかというと、内部年代で未来の日付を付けられたシャードの行を、実実行日のシャードへ**バイト単位で移動**した（280本の旧シャード、78本の受け側シャード、行は変更されていない）。移動が必要だった行——つまり**自分の日付ラベルが自分の内容の日付と食い違っていた行**——は、内容の誤りも約5倍多く記録されている。

人間側の対応は **Hotspot 3**（各階の平面は対応しているように見えるが実際にはかなり違い、それが階の心的整合を妨げる）である。**外からは同じに見える層が、内ではずれている**——書庫ではそれが日付ラベルのずれたシャードで、人間の建物ではそれが不一致な廊下である。これは**類比であって同一視ではない**（前セッション §11.6 の留保をそのまま継承する）。

### 5.3 排除できない代替説明：発見バイアス

受け側シャードの発生率が高いのは、**統合の監査がその行を見たから**かもしれない。見た行の誤りは見つかる。見なかった行の誤りは記録されない。errata の `check.kind` は受け側58件中58件が `manual`、非統合でも155件中155件が `manual` なので検査の種類では説明されない（`manual` 内だけで 93.1% 対 77.4%、χ²=5.93）が、**「監査がその行を通ったかどうか」は台帳に残っていない**。

これを潰すには、移動していない行を同じ手順で監査した対照群が要る。**本セッションは作っていない**（作ると新しい行が増え、それがまた発見バイアスになる）。§9 に残す。

### 7.2 項目7（測定法批判）の一部が、既収蔵の資料の中にあった

§7 の 7 は「2010年以降の VR・fMRI・モバイル eye-tracking、とくに survey 知識の**測定法**への方法論的批判」を求めていた。新しい資料は採れなかったが、**批判の一部は 2006 年のこの論文自身の中にあった**（§4）：

1. **著者ら自身が名指しした順序交絡**：指向課題は navigation 課題の**後**に実施された。不慣れ群は歩く間に survey 知識を獲得して差を縮めた可能性があり、検証するには**歩く前**に測る必要がある。
2. **系統誤差は位置の誤割当から生じうる**（Fig. 7）：60° の角度を 90° として記憶すると、観察者は別の場所に自分を置き、**その場所からは平均指向がほぼ正確になる**。指向の「誤差」は方向の推定誤差ではなく**位置の割当誤差**かもしれない。Thorndyke & Hayes-Roth (1982) や Gillner & Mallot (1998) にも同様の結果がある、と著者らは書く。
3. **自己報告は汚染を避けて事後に採った**（FSBSOD を会議後にメールで）。
4. **小標本**：著者らは survey の非有意について「この部分の分析では効果量のパターンが明瞭でない」と書き、N=12（各群6名）を理由の候補に挙げている。

**これは前セッションの判定に対する訂正を含む。** `EVL-20261123-cd6d6b` は「指向課題で測った survey 知識ではなかった」ことを層(1) の射程限定の根拠に使った。**測定结果は正しい**（すべての t(10)>1.21, p>0.252）。しかし「survey 知識は wayfinding 成績に寄与しない」への一般化は、**著者ら自身が挙げた測定順序の交絡を跨いでいる**。本セッションは claim `reading_revised`（`CLM-23ef5d-3`）としてこれを記録した。判定行（`narrows_scope`）は追記専用なので書き換えない；限定の**根拠の強度**が、記録されたより弱かったという事実を重ねる。

### 7.3 項目6：書誌確定。一件は**候補の誤指定**だった

引用リスト（chunk 9, 10）は verified 全文の一部なので、書誌の確定に使える。
